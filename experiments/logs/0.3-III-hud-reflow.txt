0.3 Phase III — the perf strip's reserved size, measured before and after
=========================================================================

The owner's complaint (archive/0.3-3-log,task.txt): "this info has variable size
that cause GUI elements move. need reserve size to avoid flicker and reflow."

Method: experiments/hud-reflow.js serves two trees of this repo over 127.0.0.1 -
HEAD as "old" (git archive) and the working tree as "new" - opens index.html on the
CPU engine in headless Chromium (the @sparticuz rig; layout needs no adapter), and
samples, in one evaluate per sample: the strip's box, the rows box, the number of
rows shown and with text, and the top of every element below the strip, while the
strip's content varies the way it really does: playing (the kernel table filling in
and changing length), an injected event round-trip window appearing and closing
again, an injected checkpoint line, and one update with all fourteen kernels over
Perf.MIN_KERNEL_MS (the widest the kernel row ever gets, 160 chars). Waits are
synchronised to the strip's own 2 Hz render, so a sample always catches the state
the injection asked for.

rig: @sparticuz/chromium 126 headless, LD_LIBRARY_PATH=/tmp/al2023/lib:/tmp,
     CPU engine (no WebGPU adapter in this sandbox; layout does not need one)
date: 2026-09-13
