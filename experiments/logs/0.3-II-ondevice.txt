Myr/s roughly doubled at both levels and p95/max fell 2-4x. The 5-step hitch
*counts* went up (0 -> 68 at L5) only because the median fell 6x, which lowers
the 2x-median threshold; the bench now prints hitches/frames so the fraction is
what gets compared. The 20-step rows are still missing.

webgpu-smoke.html: two FAILs, both now diagnosed.

	[FAIL] meanSpeed drift > 20%
	[FAIL] uncaught: OperationError: getMappedRange failed
	       at pull (sim-gpu.js:712) <- roundTrip:789 <- step:811 <- play:826
	       <- webgpu-smoke.html:162

The second is the "GPU play stops until play is pressed again" bug, and it is
fixed: `pull` unpacked the whole mirror by testing the *staging cache*, which
keeps buffers from an earlier, wider download. A light event round trip therefore
called getMappedRange on a cached cellF that this transfer never mapped, and the
device raised OperationError. In the smoke the trigger is the full download at
line 113; in the app it is any full sync - a probe click, Save, the deposit
extract, or the 20 Myr checkpoint - followed by the next event cycle, which is
why a run died at a fixed point in time and then survived a while after a
restart. `tests/gpu-stub.js` now enforces the map state, so `tests/gpu-play.js`
reproduces the identical stack headless and the regression cannot come back.

The first is defect D1, now measured:

	[parity] frame 5 · owner mismatch 0/10242 · |dz| max 139.0 m
	[parity] meanSpeed cpu=4.022 gpu=4.947 · maxSpeed cpu=11.449 gpu=13.026
	[parity] omega: worst |dR*w| plate 14 = 2.053 cm/yr
	         cpu from relaxed omega 4.022/11.449
	         cpu from target omega  5.040/13.052
	         gpu                    4.947/13.026

The device's plate speeds land on the *unrelaxed* least-squares fit (1.9% mean,
0.2% max) rather than on the relaxed omega the CPU carries. Reading the code
does not explain it: the relaxation is identical in js/plates.js and
wgsl-plates.js reduceB (omega + (fit - omega) * min(1, dt/tau_omega)), tau_omega
is 0.5 in both (params.js -> wgsl-common.js P_TAUOMEGA), dt is 0.1 in both
(uploadFrame -> fDT), both boot with dt = tau_omega so both start at the fit, and
the accessors are consistent (plateOmega = PLATEF[p*8+1], plateOmegaTarget =
[p*8+2], written by setPlateOmega, read by velocities, contact and diag). The
smoke now prints the decisive ratio - each engine's own mean |omega|/|omegaTarget|
plus the first four plates - which separates "the device never relaxes" from
"omega is fine and the aggregate differs".

Kernel table note: per-kernel ms roughly tripled against 0.3-2.txt (winners
0.56 -> 1.89, diagC 0.41 -> 1.69). The frames are no longer separated by a
114 ms stall, so the queue is saturated and the kernels contend. Two
consequences for the plan: loserRank is ~16% of the top-10 kernel time (not 4%),
and diagA + diagC = 2.67 ms of the 6.74 ms top-10 total is diagnostics that
nothing on the device reads.
