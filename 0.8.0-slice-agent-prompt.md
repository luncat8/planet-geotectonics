# 0.8.0 — Standing handoff prompt for the `planet-tectonics-2d-slice` agent

Paste this document as the working brief for an agent in `luncat8/planet-tectonics-2d-slice`.
It is written so that agent can start immediately, without waiting for the globe repository to
implement its 0.8 code. Everything it says about the globe was verified against globe revision
`85f4a59e39eaa1bf1dd7f98c1c4e8837052d2de1` (the commit that landed the 0.8 plans as documents;
the v2 codec, cutter and bake CLI are **not written yet**).

Authority for the exchange design is the globe's `0.8.0-plan-slice-exchange-foundation.md`
(§6 is the slice-side work list), with `0.8.1` (cutter), `0.8.2` (Earth bakes) and `0.8.3`
(return observations and live-bridge gates) behind it. This prompt restates what the slice agent
needs from those documents; the plans remain the normative text.

## 1. Your position in the exchange

| concept | owner |
| --- | --- |
| globe geometry, cut path in world coordinates, cell walk, plate motion, crust aggregates, sea level, ore potentials | globe |
| pack schema, validation, quantisation, identities | shared byte-identical `port/` file |
| vertical beds, section renderer, section-local thermal model, section-local deposits | you (the slice) |
| a returned core log | you produce it; the globe only displays it as `observed (section)` |

A pack is a snapshot, not an authority handoff. The first product is one-way: the globe
Copy/Saves a `pgt-slice-pack` **v2** file; you load and reconstruct it. Clipboard text and a
downloaded `.json` file are the contract transports; `postMessage`/`localStorage` are later
conveniences. There is no live link and you must not start one — the globe's 0.8.3 gates are
explicit and item 4 there (your section's automatic plate-topology rebuild after incoming
crossings) is still open on your side. Your R4 mechanics are closed (0.1.8 absorbed-shortening
brake, 0.1.9 re-measurement) — that gate is recorded as satisfied.

## 4. Phase A — start now (no v2 dependency)

1. Run your `experiments/port-check.js`; record green before anything else.
2. Write the staleness table of §3 into your own docs (roadmap and/or the assumption ledger):
   every globe-derived artifact, its source pin, its stale reason. Mark the bundles
   stale-by-data, not corrupt — they still decode under v1.
3. Collapse your read paths to one decode entry: `SectionPack.load`, the bundled
   `SECTION_PACKS`, the raw strip and the section seeder should all call one function today.
   This is an internal refactor with no format change; it makes the v2 swap a one-function
   change later. Your arc-length box filter, raw/reconstructed overlay, assumption ledger and
   clock-off window rule stay exactly as they are (globe 0.8.0 §6.3 endorses them).
4. Write the retirement note for `bake_section.py` (superseded by the globe CLI), so nobody
   invests in extending a mirror of globe internals.
5. Define your return package for the fixture round trip (globe 0.8.0 §6): decoder result,
   reconstructed section state hash, and a list of schema ambiguities you hit.
6. Only if you need fresher section data before v2 exists: re-bake is possible against
   `earth-1deg.js`, but you must first verify your frozen mirror field-by-field against the
   current globe loader (the pack schema moved with 0.4.8). Prefer waiting for the v2 writer;
   a v1 re-bake you throw away at the cutover is waste, and a silently drifted one is worse.

## 5. Phase B — the coordinated v2 cutover (waits for one file drop)

The globe will hand you `port/slice-format.js` (v2), `port/fixtures/slice-pack-v2.json` and
`port/PORT.json`, byte-identical, with its source revision and checksums. Then:

1. Replace the v1 codec and manifest entry with the byte-identical v2 files; your local hash
   check must go green without network access.
2. Regenerate `SECTION_PACKS` and all v1 fixtures through the v2 writer (the globe's CLI or the
   handoff command lines it records); delete the v1 reader path — readers reject v1 with a
   clear version error, no legacy branch.
3. Route everything through the single v2 decode path from Phase A step 3.
4. Replace your private coupling path hash with `SlicePack.pathChecksum` when coupling is
   planned (not before; nothing here starts coupling).
5. Leave the deposit ports alone (§3).
6. Do the manual fixture round trip and return the §4.5 package. Neither side begins a live
   channel before both sides agree on it.

A port bump is one reviewable change: shared files, regenerated fixtures, both manifests, both
local checks. No unrelated change edits a shared file.

## 6. Standing boundaries

- No v2 schema decision is made locally on your side; a proposal goes back through the globe's
  0.8.0 §5 procedure as a coordinated port bump.
- No deposit catalogue backport in either direction; no section-engine vendoring into the
  globe; no second globe implementation in your repository.
- No live coupling, no `pgt-core-log` import into the globe, no claim of two-way validation
  until the globe's 0.8.3 gates close.
- Your standing repo rules apply throughout: `file://` friendly, classic scripts, guarded
  `module.exports`, tab indentation, no hot-loop allocations, measured plans.

## 7. Report format (end of Phase A, and again after Phase B)

- both revision pins (yours and the globe's) and the SHA-256 of every file under `port/`;
- port-check result; the staleness table location; the single decode path entry point name;
- after Phase B: decode results for the globe's fixture and bundles, reconstructed state hash,
  ambiguities, and any schema proposal.
