# 0.8.2 — Deterministic Earth-start section bakes

Once the interactive cutter has produced and exchanged verified v2 packs, add a reproducible
headless route for selected Earth and paleo start states. The output is the same portable
`pgt-slice-pack` v2 JSON as the map exporter; it is not a second section format and not a
pre-rendered replacement for the globe.

This plan follows `0.8.0-plan-slice-exchange-foundation.md` and
`0.8.1-plan-slice-cutter.md`. It should not begin until their v2 fixture and real interactive
round trip are accepted by the slice repository.

## 1. Why bake after the interactive cutter

Earth packs already ship as compact global raster inputs, but they are not cross-sections and
do not carry every live-state field. A dedicated section bake is useful for reproducible examples,
regression fixtures and `file://` demos, provided it runs the same globe initialization and the
same `Slice.pack` writer as a browser capture.

It is specifically not an excuse to reimplement Earth raster decoding, K9 inversion, ownership,
boundary classification, section geometry or the shared checksum in Python. The current Earth
loader already owns those details; the new tool composes it.

## 2. Command-line product

Add a Node tool:

```text
tools/earth/bake_section.js
```

Its initial stable interface is:

```text
node tools/earth/bake_section.js \
	--start earth|pangaea|gondwana|jurassic|cretaceous|kpg|eocene|miocene \
	--level 5|6|7 --seed <uint32> --preset game|realistic \
	--circle <lat0-deg> <lon0-deg> <azimuth-deg> \
	--out <file.json> [--built <ISO-8601>] [--report <file.json>]
```

The start value is resolved through `Earth.pick(level, start)`, not a hand-maintained filename
switch. The tool rejects missing packs, invalid levels/seeds, invalid/collapsed circles,
unwritable output paths and a nonempty output path unless `--force` is explicit. It never writes
inside `js/data/` by default. Use an explicit ignored `out/` or caller-selected directory for
large generated files; do not commit a batch of derived sections merely because it was used for
measurement.

The command prints a concise line suitable for a release record:

```text
pgt-slice-pack v2 <start> L<level> seed <seed> t 0 Myr <runs> runs <bytes> B
path <pathChecksum> pack <checksum>
```

The optional report is separate from the portable payload and records input args, source Earth
pack name/epoch/source attribution, output bytes, runtime, run count, identities and validation
measurements.

## 3. One authoritative generation path

The implementation bootstraps real CommonJS globe modules in this order:

1. load the existing data-pack scripts so they register `global.EarthPacks`;
2. load `Grid`, `State`, `Earth`, the simulation dependencies and the shared v2 `SlicePack`;
3. build `new Grid(level, seed).build()` and `new State(grid, seed)`;
4. call `Earth.apply(state, Earth.pick(level, start), { realistic: preset === 'realistic' })`;
5. construct the canonical circle through the same `Slice.circle...` helper used by the UI;
6. pass the resulting state, effective water settings and explicit provenance to the same
   `Slice.pack` writer used by the UI; validate and encode through `SlicePack`;
7. write only after the full validation succeeds.

Do not use a test helper as production infrastructure, and do not copy the source of
`Earth.decode`, `Earth.invert`, `Earth.sample`, `Resolution.nearestCell`, the walker or the
codec into the CLI. If loading the browser data scripts needs a small data-pack registry helper,
extract a pure helper from the existing loader and make both paths use it.

This sequence creates a freshly initialized `tMyr = 0` world. It is deterministic for a given
argument tuple, source revision and Earth data file. It is not a way to recreate an arbitrary
interactive world at a later simulation time; use the interactive export or a verified checkpoint
for that.

## 4. Honest field semantics for Earth starts

The same v2 field contract applies, with no made-up geology:

| field class | Earth-start source |
| --- | --- |
| crust thickness, age, fertility, plate assignment, surface elevation and water | `Earth.apply` followed by its real raster/elevation pass |
| current boundary classification and surface velocity | initialized globe state at `tMyr=0` |
| plate motion / historical rotation provenance | Earth pack plus preset, named in `source.rotModel` |
| ore potentials | initialized globe fields; normally zero unless the actual initialization has populated them |
| section beds and section-local deposits | absent from the globe pack; constructed later only by the slice application |

The report and source provenance must make this visible: `source.pack` is the resolved Earth pack
name, `source.epochMa` is its input epoch, `source.tMyr` is zero, and the license string preserves
the data pack's existing source/attribution. A historical pack's `epochMa=100` and `tMyr=0` are
not contradictory.

The tool must not label zero potentials as surveyed absence or modelled deposits. They are simply
the state supplied by the chosen start initializer. This is important because the modern globe
catalogue is local, dynamically evaluated and newer than the old slice-port model.

## 5. Static examples and slice-side handoff

Use the CLI to create a small, deliberate corpus rather than a gallery of unreviewed generated
assets:

1. a modern Earth L5 great circle crossing ocean, continent, a seam and at least one boundary;
2. one historical Earth L5 circle with a nonzero `epochMa` / rotation-model provenance;
3. one small synthetic-state pack used for byte-level unit tests.

Keep the synthetic fixture in the shared `port/fixtures/` contract when it exercises codec
semantics. Put larger real examples in release artifacts or a documented generated-data location,
not both repositories by default. If the slice repository bundles a real example, it owns the
reviewed `SECTION_PACKS` wrapper around the exact generated JSON and records the globe revision,
command line, full checksum and license. The globe repository does not need to carry the section
renderer's bundle format.

For each handoff, give the slice agent:

- the exact tool command and globe revision;
- the raw JSON checksum and canonical path checksum;
- output from `SlicePack.validate` and the JSON report;
- an explicit declaration that beds/deposits shown after import are section reconstruction, not
  additional fields from the Earth pack.

The slice agent loads the pack through its v2 `SectionPack` reader, verifies the two identities,
shows the raw values before reconstruction, and returns the resulting section state checksum.
This manual round trip remains the integration release criterion.

## 6. Tests

Add `tests/slice-bake.js`, which invokes the CLI or its factored pure command function against a
small real/synthetic input. It must verify:

- the result uses the exact interactive writer/codec path and validates as v2;
- identical fixed arguments plus a fixed `--built` value give byte-identical JSON and checksum;
- changing only `--built` leaves full/path identities unchanged while changing the bytes only in
  that provenance value;
- output provenance names the selected Earth pack, epoch, preset and source license correctly;
- the first circle output has legal adjacency/full-span walk properties and matches direct
  `Slice.pack` fields for the same fresh state;
- invalid CLI inputs and partial-write failures leave no misleading successful output;
- a generated real pack loads in the slice-side v2 fixture/reader test;
- the ordinary `node tests/run-all.js` profile remains green.

Run a measured L5 bake in CI/short-profile scope. L6/L7 are release/manual measurements unless
runtime and fixture size make them safe for the existing suite; report their measured memory,
time and output size rather than turning an unknown machine-dependent number into a gate.

## 7. Exit criteria and boundaries

0.8.2 finishes when a documented command deterministically writes a valid v2 Earth-start section,
a counterpart reader accepts it, and its provenance makes source epoch/time/attribution and zero
or live field semantics unambiguous.

It does **not** finish with a continuously coupled pair of simulations. A static Earth-start bake
is a useful fixture and a portability test; it does not resolve the slice project's remaining
section-topology rebuild or mechanical diagnostic limitations. Those constraints remain explicit
in `0.8.3-plan-slice-bridge.md`.
