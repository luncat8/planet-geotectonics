# 0.6.0 review — local, click-driven prospecting

## 1. Review scope

The available branch base is `c587fad` (`plan`); it contains the prospecting specifications but no
prospecting implementation. This review checks the implementation against that baseline and the
single-cell-first interaction requirement. The existing plans had made a marker overlay and a
whole-map workflow part of the first increment, which did not match the intended common action:
point at one cell and explore it.

## 2. Findings and changes

1. **The first increment was too map-oriented.** The original 0.6.0/umbrella plans coupled a local
   click with marker coverage and treated the whole-map answer as a first-class action. The 0.6.0
   scope is now a click-only local survey with a separate report pinned to the last clicked cell;
   the ordinary column inspector remains free to follow the pointer. A world-wide catalogue build
   is not a hidden dependency of that click. Regional cataloguing and the viable map are deferred
   to an explicit, opt-in later action; page load, hover and ordinary clicks do not start a sweep.
2. **Drainage traversal needed the correct direction.** `state.low[cell]` points to the
   downslope neighbor. To sample material that drains into a clicked outlet, geochemistry must walk
   reverse edges (`state.low[upstream] === current`), not follow `low` away from the outlet. The
   implementation and a focused downstream/upstream test now pin that behavior.
3. **The asynchronous GPU click could lose its event state.** DOM `currentTarget` is cleared after
   the event handler returns, while GPU state download resolves later. The handler now snapshots the
   target, coordinates and selected instrument set synchronously, then runs the same probe-and-survey
   action after readback. The GUI test clears `currentTarget` and changes the checkbox before
   resolving the readback; the original cell and tool set are preserved.
4. **The magnetic reading omitted the planned source-depth result.** Detected sources now report
   the shallowest depth in 250 m buckets; a focused test verifies the bucket and that no source depth
   is reported for an undetected target.
5. **The first short-profile run found an integration omission.** `tests/adj.js` loads `js/ui.js`
   directly and initially lacked the new classic scripts. `deposits` and `instruments` are now in
   its module list; the full short profile was rerun after the fix.

The session ledger remains page-local, deduplicates surveyed cells, retains discoveries with
hysteresis, and does not change checkpoint bytes. Instrument selection is empty by default, so the
existing probe-only behavior is preserved until the user opts in.

## 3. Verification

- `node tests/deposits.js` — PASS.
- `node tests/instruments.js` — PASS (local footprints, drainage, depth/cover gates, deterministic
  noise, confidence ladder, lab behavior, hysteresis/reassociation and checkpoint isolation).
- `node tests/browser-scripts.js` — PASS.
- `node tests/gui.js` — PASS (empty default, query prefill/capture, click-only report, hover pinning,
  GPU click after `currentTarget` clears).
- `node tests/adj.js` — PASS after registering the new scripts.
- `node tests/run-all.js` — **PASS, short profile: 35 tests in 128 s**.

The full/release profiles were not run; the repository's sandbox guidance reserves those histories
for the owner rig. GPU click behavior is covered by the GUI's readback stub, not by a physical
WebGPU adapter in this environment.

## 4. Deferred work

core and, only on explicit request, the regional campaign and viable-map overlay. Neither is a
prerequisite for exploring one clicked cell, and restoring URL settings must not auto-start a
campaign.
