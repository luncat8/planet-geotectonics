# 0.4.8 review — sediment inputs and bake preflight

Reviewed `198cc98` ("0.4.8: replace the modern sediment prior with CRUST1.0") on
2026-10-11. Scope: `tools/earth/sediment.js`, the Python bake integration, committed
extract and modern packs, observation fixtures, provenance and roadmap status.

## What held up

The original `node tests/sediment.js` passed. Both modern packs contain the quantized
containing-cell CRUST1.0 sediment and are fixed points of the envelope rule. Unbound
inversion residuals stay below 80 m (75.0 m at 1°, 74.9 m at 0.5°); no residual sits on a
thickness bound. Datum, age, crust class and plate-bank checksums match the baseline.
The model is correctly labelled as CRUST1.0, not GlobSed or observed ore grades.

No committed pack, raster, manifest, physics kernel, runtime dependency or default changed
in this review. The elevation-envelope rule and the loader's five-iteration inversion
remain intact.

## Findings and fixes

### 1. Unknown point observations became measured zero

A valid row with `value: null` and an `unknown_reason` entered both inverse-distance sums.
JavaScript's `weight * null` is zero, so an unknown at the centre of a continental fixture
changed its 2000 m prior to 0 m and reported one touched cell. Mixed with a measurement,
the unknown also diluted that measurement's weight.

`correctPoints` now validates its input, then excludes unknowns as well as holdouts.
Measured zero still contributes when it has numeric nonnegative uncertainty. Tests cover
unknown-only input, mixed unknown/measurement equivalence, measured zero, holdouts,
crust-class isolation and the unchanged elevation pullback.

### 2. Input validation accepted data that could silently corrupt a correction

The observation validator accepted null provenance, nonfinite numbers and numeric strings
in uncertainty/radius fields. Required ids/provenance/reasons now require nonblank text;
coordinates, thickness, footprint, uncertainty and radius use finite-number checks with
their existing range requirements. An explicitly invalid default radius is rejected rather
than replaced by the default.

The binary reader previously accepted arbitrary dimensions although its sampling formula
assumes 360×180 at 1°. It now rejects other dimensions before a pack can be written.
The raw boundary extractor now rejects nonfinite or ascending boundaries and unrepresentable
uint16 thickness, rather than allowing NaN to become zero, taking absolute values of
inverted layers, or clipping bad source data. Longitude wrapping also works across multiple
turns. Tests exercise invalid dimensions, bad magic/length, malformed rows, overflow,
water/ice exclusion and preservation of an existing output on extraction failure.

Compatibility check: retrieved `model/crust1.bnds` from the documented
`jrleeman/Crust1.0` GitHub mirror into scratch space and ran the stricter extractor. All
64,800 rows passed; thickness remained 0–21,000 m. `cmp` against the committed extract
was identical (SHA-256 `6b25e1615bae065a7d5f9fc2041635c311dcddeaa33c6c81f71ed23161da551f`).
The raw table was not added to the repository.

### 3. Python refused historical sediment updates after writing output

`apply_sediment_pass` checked the target, but both bake paths called it only after producing
the pack and report. Thus a refused historical invocation could already have overwritten a
previous pack with its freshly baked prior.

The shared target check now runs as soon as the paleo epoch is loaded, or before raster
construction in the non-paleo path. It remains at the post-pass boundary as well. A separate
Python suite invokes the actual CLI on tiny fixtures, testing both existing and absent
output/report paths for historical epochs and non-`earth` names. Refusals leave all those
paths unchanged. It also checks default-off behaviour, allowed modern post-pass invocation,
subprocess failure propagation and manifest mismatch rejection. The checksum reader now
closes its input file explicitly.

## Development continuation

Added a validation-only entry point for a future observation table:

```
node tools/earth/sediment.js --validate-observations <json>
```

It prints a JSON `{ok, errors}` result, exits 1 on schema errors, and does not edit its input
or any pack. `correctPoints` uses the same validation contract, so calling it directly
cannot bypass those checks. This is row-schema validation, not source-registry verification,
licence verification or evidence of scientific accuracy. No observations dataset was invented.

Updated the roadmap to reflect the shipped CRUST1.0 increment without claiming a holdout
win, and to match its own header: height-mode slices 1–3 are shipped; slice 4 is device-gated.
Plans retain normative contracts; this file is the implementation review.

## Remaining boundaries

- There is no observation dataset, independent holdout evaluation or GlobSed ingestion.
- Preflight protects invalid target requests; the bake is not an atomic transaction across
  pack, report and post-pass. A later I/O or subprocess failure is still a separate concern.
  The Python report describes the pre-pass raster; use `sediment.js --report --pack <js>`
  for final sediment and elevation-bank statistics.
- Full/release histories and real-device Earth CPU/GPU parity remain owner-rig gates.
  No full/release profile was run in the sandbox, and no rendering default was changed.
