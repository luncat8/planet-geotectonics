# 0.8.0 — Slice exchange foundation and compatibility gate

Make a cross-section exchange with `planet-tectonics-2d-slice` reliable before adding a map
widget or a live link. The first product is a verified file that a user can copy or save from
this globe and load into the section application while both applications are opened with
`file://`.

This plan owns the shared contract, provenance and compatibility work. The globe-side cutter is
`0.8.1-plan-slice-cutter.md`; deterministic Earth bakes are
`0.8.2-plan-slice-bake.md`; live coupling and the return observation path are deliberately
later in `0.8.3-plan-slice-bridge.md`.

## 1. Baseline and decision

This plan was reviewed against:

| repository | reviewed revision | role |
| --- | --- | --- |
| `luncat8/planet-geotectonics` | `6b41d5225d684f8eac2f8c890f637756dd0b1279` | globe writer; this repository |
| `luncat8/planet-tectonics-2d-slice` | `4eb762d` | section reader/reconstructor |
| old globe pin in the slice manifest | `d909476` | historical reference only |

The old pin is the globe's 0.6.1-era revision and is 22 commits behind the reviewed revision.
The source review includes the slice repository's `0.4.0-sync-plan.md`, `0.4.1-draft.md`,
`0.4.1-plan.md`, later return/coupling follow-ups and `0.9.0-draft-sync.md`; those documents are
useful design evidence, not an API claim against the current globe. In particular, the old shared
`deposit-models.js` / deposit-economics assumptions no longer describe the globe's 13-row,
plate-frame-anchored catalogue. They must **not** be copied forward or presented as a shared
catalogue contract.

The useful existing exchange design is the small, pure `pgt-slice-pack` codec. Its current v1
implementation is not adopted verbatim, however: its checksum does not cover all semantic
metadata (notably the geographic path, sea block and plate table), and it normalizes malformed
raw fields before it proves they were present and integral. A changed path can therefore retain a
v1 checksum in some fixtures, contrary to the format's stated purpose. The clean answer is one
coordinated **`pgt-slice-pack` v2** release, not a compatibility branch or a second checksum.

All bundled v1 section packs and v1 fixtures are regenerated in the slice repository at the v2
cutover. Readers reject v1 with a clear version error. There is no legacy reader.

## 2. Product boundary

### 2.1 What 0.8.0 establishes

1. `port/slice-format.js` is byte-identical in both repositories and is the sole owner of:
   field order, units, quantisation, canonical metadata encoding, full-pack checksum, path
   checksum, validation and path geometry.
2. `port/PORT.json` records the two repository revisions, every shared file and its SHA-256.
   A local test checks hashes without accessing the network.
3. A small shared fixture proves that both sides decode the same bytes, reject the same
   corruptions and calculate the same two identities.
4. The two projects agree on writer/reader ownership before either page claims a live link.

### 2.2 What it does not establish

- no iframe, module build, server, package manager, submodule or runtime network request;
- no vendoring of the section engine into this page, and no second globe implementation in the
  section repository;
- no transfer of section beds, deposits, mass or tectonic authority back into this simulation;
- no port of the slice project's old deposit priors, checkpoint implementation, water code,
  particle engine or wall-clock eruption presentation;
- no promise that a section is a globally valid three-dimensional simulation. It is a
  depth-resolved reconstruction of one exported line.

Clipboard text and a downloaded `.json` file are the contract transport. `postMessage` and
`localStorage` can later make the same verified payload convenient, but never replace those two
file-safe transports.

## 3. Ownership and runtime authority

| concept | owner | other side may do |
| --- | --- | --- |
| globe geometry, cut path in world coordinates, cell walk, plate motion, crust aggregates, sea level and ore potentials | globe | read a verified snapshot |
| pack schema, validation, quantisation and identities | shared-identical `port/` file | neither side makes a local variant |
| vertical beds, section renderer, section-local thermal model and section-local deposits | 2D slice | report observations only |
| a returned core log | 2D slice | globe displays it as `observed (section)` in a side table |
| globe simulation state and all GPU buffers | globe | never modified by a section log or a section import |

A pack is a snapshot, not an authority handoff. `tMyr` names globe simulation time; `epochMa`
names the geological epoch of an Earth input pack. They are different values and both travel.

## 4. `pgt-slice-pack` v2

The v2 shape keeps v1's useful columnar fields and units, but makes the metadata and integrity
rules explicit:

```text
{
	format: 'pgt-slice-pack', version: 2,
	source: { repo, commit, pack, epochMa, rotModel, built, tMyr, level, gridSeed, simSeed },
	path: { kind, closes, arcKm, cellKm, lat0, lon0, az0 | verts },
	planet: { rKm: 6371 },
	sea: { mode, levelM, volScale },
	plates: [{ id, n, wx, wy, wz }],
	n,
	sKm, zM, hFelM, hMafM, hSedM, ageMyr, fert, damage,
	host, plate, bnd, pol, alive, wet, vt, vp, pot,
	license, checksum
}
```

`built` is human provenance and is intentionally excluded from identities so a capture timestamp
does not make identical geology look different. Every other value that affects how the snapshot is
located, interpreted or reconstructed is covered.

### 4.1 Per-sample field contract

| field | writer source | unit / meaning |
| --- | --- | --- |
| `sKm` | completed cell-run walk | start of the run; all runs tile `[0, path.arcKm]` |
| `zM` | `state.z[cell]` | displayed surface elevation in metres, including `zDyn` |
| `hFelM`, `hMafM`, `hSedM` | column selected by `state.owner[cell]` | aggregate crust thicknesses in metres |
| `ageMyr`, `fert`, `damage` | same owner column | intensive column values |
| `host` | shared host-code helper over the carried thicknesses | index into `SlicePack.HOSTS` |
| `plate` | owner column's current plate id | snapshot-local plate label, not a permanent Earth identifier |
| `bnd`, `pol` | directed edge from this cell to the next crossed cell | section boundary code and subduction sign |
| `alive` | `owner >= 0` | whether this run contains globe crust |
| `wet` | displayed sea comparison at the snapshot | `0` or `1` |
| `vt`, `vp` | cell surface velocity resolved on the local path tangent | m/Myr along the cut and non-negative out-of-plane magnitude |
| `pot` | `Diag.ORE_FIELDS` order | `oVms`, `oMaf`, `oArc`, `oOro`, `oBas`, `oPla` |

A source cell is not a plate. `state.owner[cell]` is a column index; the exported plate is
`state.plate[owner]`. This distinction remains named in the codec and every writer test.

A gap is not quietly fabricated into crust. v2 canonically writes a gap row as
`alive=0`, `host=0`, zero thicknesses and scalar/velocity/potential fields, `bnd=0`, `pol=0`,
`wet=0`, and `zM=sea.levelM`. The reader renders it as a gap because of `alive`; the finite
`zM` sentinel only makes the columnar JSON valid. The writer never dereferences an absent owner.

`bnd` uses the shared conversion:

| globe edge | globe polarity | pack boundary |
| --- | --- | --- |
| interior | any | `none` |
| transform | any | `neutral` |
| divergent | any | `open` |
| convergent | `2` | `collide`, `pol=0` |
| convergent | `-1` or `+1` | `subduct`, same sign |

The `plates` table is ordered by ascending `id`; `n` is the number of exported runs/samples using
that id and `(wx, wy, wz)` is the globe's angular-velocity vector in rad/Myr at capture. It is
snapshot metadata only. An Earth rotation-model code is not smuggled into the dense runtime id;
it can be added only by a future format version with a reader for its exact semantics.

### 4.2 Canonical paths and identities

`SlicePack.pathChecksum(path)` is a pure two-lane FNV identity of the canonical path only:
kind, `closes`, `arcKm`, and circle coordinates or every polyline vertex after six-significant-
digit quantisation. It intentionally excludes source level, state time and sampled fields, so a
later snapshot of the same geographic line can join the same section.

`checksum` is a separate full-pack identity. It hashes, in one documented order:

1. format/version and `n`;
2. every semantic `source` scalar and string except `built`;
3. every semantic path field, planet radius and sea field;
4. the ordered plate table and license;
5. every typed sample buffer in the declared field order.

The implementation may use the existing two-lane FNV byte primitive, but it must not depend on a
private `Deposits` helper: the codec owns its own stable implementation. Text is UTF-8 and numeric
metadata has one canonical byte representation. The test fixture changes each metadata group once
and proves that both identities change only when their documented inputs change.

### 4.3 Validation order

A decoder validates the raw parsed object before it creates typed arrays. It rejects rather than
coerces:

- a foreign format, any version other than 2, missing required fields or unrecognised semantic
  fields;
- a non-object header, non-string required provenance/license values, non-finite scalar or path
  values, invalid circle coordinates, a degenerate/antipodal circle, or a polyline with fewer
  than two non-zero great-circle segments;
- non-positive `arcKm`/`cellKm`, a path whose declared arc disagrees with its polyline, an invalid
  planet radius, an invalid sea block or an unordered/duplicate plate table;
- a field of the wrong raw length, a non-integral integer/flag/code, an out-of-range host,
  boundary, polarity, plate or flag, negative thickness/age, and non-finite numbers;
- `sKm` that does not start at zero and strictly increase, or a final span wider than the declared
  source cell budget;
- a non-canonical checksum or any checksum/path-checksum mismatch.

Only after this proof may it build the declared typed arrays, quantise the floats and expose a
pack. A malformed input must leave the currently loaded section or globe UI unchanged.

## 5. Shared-file procedure

Create these files in **both** repositories in one coordinated change:

```text
port/slice-format.js
port/fixtures/slice-pack-v2.json
port/PORT.json
```

`PORT.json` contains the two pinned revisions, a concise reason for each shared artifact and its
SHA-256. It contains no old deposit model or economics files. `tests/port.js` in this repository
and the slice repository's `experiments/port-check.js` calculate the local hashes with no network
access. A port bump is one reviewable change: update the codec/fixture in both trees, regenerate
hashes, update both pins, then run both local checks. No unrelated change edits a shared file.

The fixture is intentionally small and hand-auditable. It includes a circle path, a nonzero sea
level, two plates, all boundary kinds, a gap row and all six potentials. The fixture suite also
makes corrupt copies that independently alter the path, sea, plate table, an integer field, a
missing field, a raw array length and a payload byte.

## 6. Compatibility matrix and handoff to the slice agent

The slice-side work needed for the v2 cutover is limited and explicit:

1. Replace the v1 codec and manifest entry with the byte-identical v2 codec and fixture.
2. Regenerate `SECTION_PACKS` and all v1 pack fixtures through the v2 writer; delete the v1
   reader path instead of branching every future load.
3. Route `SectionPack.load`, bundled packs, the raw strip and the section seeder through one
   v2 decode path. Their existing arc-length box filter, raw/reconstructed overlay, assumption
   ledger and clock-off window rule remain good local behavior.
4. Replace the private coupling path hash with `SlicePack.pathChecksum` when coupling is planned.
5. Do not update the slice's old shared deposit ports to imitate the globe's current catalogue.
   The pack's six potentials are the cross-project geology contract; catalogue models remain
   local to their owners.

The globe agent supplies a generated v2 fixture and a short record of its source revision, source
state and checksum. The slice agent returns the decoder result, reconstructed state hash and any
schema ambiguity. Neither side begins a live channel until the manual fixture round trip agrees.

## 7. Tests and acceptance

Add `tests/port.js` and `tests/slice-format.js` to the short profile. The tests must prove:

- every manifest hash matches, and changing one shared byte fails locally;
- both Node and classic-script loading expose the same codec constants and fixture checksum;
- the v2 fixture decodes identically on both sides; its canonical encode/decode/encode text is
  stable;
- each semantic metadata group changes the full checksum; only a path change changes the path
  checksum; changing `built` changes neither;
- all listed malformed/corrupt variants refuse before any caller state changes;
- gap canonicalisation, host mapping, potential order and boundary conversion have exact fixtures;
- v1 is refused explicitly, and no v1 artifact remains in shipped section bundles;
- the existing short profile remains green.

The 0.8.0 exit condition is a checked-in, byte-identical v2 codec and fixture accepted by both
repositories. A map control is not an exit condition for this increment; it belongs to 0.8.1.

## 8. Risks held at this boundary

| risk | control |
| --- | --- |
| stale source assumptions masquerade as a shared API | pin both revisions and share only the pure codec |
| a changed line joins an unrelated section | full checksum covers path; later coupling uses the independent canonical path checksum |
| silent zero-fill turns corruption into valid geology | validate raw fields before typed-array normalization |
| current Earth / runtime plate ids are mistaken for permanent model ids | label `plate` snapshot-local and reserve model identifiers for a versioned extension |
| a gap produces fake crust or a non-finite JSON row | canonical zero-material gap row plus `alive=0` |
| transport works only on one browser or host | copy/paste and file transport are the release contract |
| copied code drifts in two repositories | local manifest/hash gates and deliberate port bumps |
