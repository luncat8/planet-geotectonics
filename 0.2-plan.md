# 0.2 — Project plan

Implements `0.1.5-final-design.md`. Self-contained: a fork can execute this plan with the
design document alone. Order: **CPU (plain JS, L5)** → **WebGPU (L6–L7)**, same kernel
structure in both. Frame step is a user setting in 0.01–0.1 Myr and every phase is tested at
both ends of that range.

## 0. Conventions

- Runtime per `AGENTS.md`: classic `<script>` tags, file:// friendly, no build, tabs, no
  allocation in the frame loop, `module.exports` guarded so files run under node.
- Hoist sort comparators out of kernels; do not create inline callbacks in hot paths.
- CPU geometry, rotations and physical fields use Float64Array; integer identifiers use
  integer arrays. GPU uses f32, so long trajectories are compared statistically, not pointwise.
- One file per kernel or entity; every kernel is a function `(state, dt)` that reads previous
  buffers and writes its own outputs — the GPU port is one WGSL file per JS kernel.
- All state in typed arrays with a fixed capacity (`colCap = 1.5·V`, `plateCap = 128`); a
  `state.js` module owns allocation, `params.js` owns the defaults from design §11.
- Tests are node scripts in `tests/` printing PASS/FAIL and the measured numbers; `npm` is not
  used, `node tests/run-all.js` runs everything. Each phase ends when its tests pass.
- Performance counter (`js/perf.js`, on-page HUD): `clock()` gives a `performance.now()` stamp,
  `lap(id, from)` adds `now − from` to `kern[id]` and returns the fresh stamp, `step(ms)`
  smooths the physics step time with a 250 ms EMA, `frame(now, steps, dt)` smooths fps,
  steps/s and Myr/s with a 500 ms EMA. The HUD text is rebuilt only when `due(now)` is true,
  i.e. at 2 Hz, so no string is built inside a frame and nothing is allocated.
- Linear speeds in `params.js` are m/Myr (5 cm/yr = 5e4). `Tm(t) = Tfloor + (Tm0 − Tfloor)
  exp(−t/τ_cool)` with map-start `Tm0 = 1` and hot-start `TmHot = 1.6`.
- `experiments/` holds throwaway measurements; kept are the ones behind a default —
  `advection-bench.js` (transport choice), `corridor-scan.js` (damage corridor fraction),
  `plate-sweep.js` (`minPlateCells`). Findings that change how something should be done go to
  `findings-pitfalls-skills.md`.

## 2. Phases

Estimates are working days for one developer; each phase has a done-criterion.

### Phase A — Foundation (2–3 d)

A1. `geodesics.js`: keep the mesh math, add flat tables `ring[V*6]` (−1 pad), `ringN`,
    `nbrDist`, `edgeLen`, `faceN` (tangent unit normal per edge, vec3), `A0`; remove the ocean
    bathymetry block (`cellC`, coast BFS) and the `opts` schema — land mask from the fbm stays
    for the map start. Keep `lookup`.
A2. `quat.js`, `params.js`, `state.js` with capacity-fixed typed arrays, `reset(seedState)`.
A3. `columns.js`: `climb`, MOVE, BIN (count / scan / scatter), RASTER with total order
    (distance, index) and `rGap`.
A4. `render.js` minimal: equirectangular canvas via `lookup`, layers `plate`, `z`, `owner`
    presence; `ui.js` play/pause/dt/seed.
Tests: `tests/raster.js` re-runs the transport bench through the real kernels (30° cap,
1000 Myr at dt 0.1 and 100 Myr at dt 0.01): IoU ≥ 0.95, interior gaps 0, ≤ 3 climb steps
p99. Test the moving cap without stationary competing columns: nearest-distance ownership
is not the priority override used by the original bench. Keep overlap/contact physics in C.
`tests/determinism.js`: identical seed and inputs produce bit-identical arrays and scalars;
reset reproduces initialization. `tests/alloc.js`: run with `node --expose-gc`, warm up,
collect before and after 1000 frames, report heap and ArrayBuffer deltas with bounded retained
growth. This is a leak smoke test, not proof of zero transient allocation; audit hot kernels
and use GC/profiler traces separately.

### Phase B — Kinematics and boundaries (3–4 d)

B1. `mantle.js`: 4 poloidal + 4 toroidal plane-wave octaves (degrees ~2–6), directions
    precessing on great circles with periods 200–500 Myr, 4 Gaussian plumes (radius 500 km,
    life 50–150 Myr). One scale factor so mean cell `|raw| = 1` at t = 0, hence mean `|u| =
    U0·Tm^2.5`. Test: divergence of `∇ₛΦ` non-zero (neighbour-difference flux; midpoint flux
    is polluted because `Σ n_ij L_ij ≠ 0` on this dual), mean speed, analytic-field spectrum
    on spherical directions — the lookup image is piecewise-constant per cell and always has
    grid-scale energy.
B2. `plates.js`: `M` and `rhs` over raster owners, 3×3 solve, relaxation, `vMax`. Test: with
    `u = Ω × r` every plate returns `ω = Ω` to 1e-9; with drag only, a plate under the mantle
    field gets the least-squares rotation (no cheaper residual nearby). `w_i` is Phase C.
B3. `edges.js`: `relN/relT`, hysteresis, polarity, `trenchDist`. Edge records are `V×6`, same
    indexing as `ring`. Polarity `1` = cell i overrides, `−1` = j overrides, `2` = C–C
    collision. Test: two prescribed plates (analytic ω) classify all boundary edges correctly;
    flicker < 5 % under added noise of 0.5 mm/yr.
B4. Seed plates: Voronoi on N random seeds → `plate` per column, `q = identity`, `b = r`,
    `ω = 0` until the first K10. Prescribed-ω tests set `state.fixedOmega` to skip
    K0/K5/K10/K11 so the Phase A transport bench keeps its ω.
B5. `diag.js`: preallocated counters and history ring, finite-value and rigid-motion
    assertions (`w = q b`, `|q| = 1`), source/sink ledgers (`produced`, `subducted`) for later
    mass-balance tests.
Boot (`sim.raster`) solves K10 once with `dt = τ_ω` before classifying, so the first painted
frame has velocities and boundary types. `sim.step` classifies with the integrated ω then
reduces for the next frame.
Tests: `tests/mantle.js`, `tests/plates.js`, `tests/edges.js`, `tests/kinematics.js` (L5, 16
plates, 500 Myr at dt 0.1 and 50 Myr at dt 0.01 — same 5000-frame budget; a 500 Myr dt 0.01
run waits for Phase E `longrun.js`).
Done: 16 plates move under the mantle field for 500 Myr, boundaries drawn by type; velocity
spread within a plate is exactly rigid (assert), speeds 1–10 cm/yr with default `U0`.

### Phase C — Gaps and overlaps (4–5 d)

C1. `contact.js` gap spawn: donors, oceanic vs rift branch, deterministic slot allocation
    (prefix sum over gap flags), plate choice with hash tie-break. The spawn threshold
    `rSpawn` (0.85 d) sits above the raster's `rGap` (0.75 d): both cells of an opening pair
    become gaps in the same frame, and spawning at `rGap` makes 33 % more crust than the
    divergence flux can pay for. A cell still empty after `fillDelay` (20 Myr) is a packing
    hole in fresh crust rather than an opening rift, and is filled regardless — that bounds
    hole lifetime at any spreading rate.
C2. Overlap detection in bins, polarity, `consumedBy` marks; APPLY: winner gather,
    accretionary prism, arc growth on `trenchDist 1–2` cells, deletion, compaction in `events.js`.
    Subduction accretes the loser's `hFel` onto the overriding column and books a C–C loser's
    `hMaf` as delaminated, so both ledgers hold by construction. `kArc` comes from calibrating
    Earth's 2.3 km³/yr of arc growth against the rate-weighted arc area, not from design §11
    (8000 grows an arc past 100 km in 100 Myr): 65.
C3. Collision branch (C–C) with merge into winner; collision resistance force in `plates.js`.
C4. Slab pull and ridge push contributions (`w_i`) in `plates.js` (ridge push needs `z` from
    Phase D — use `age`-only Parsons–Sclater until then).
C5. Dynamics audit before adding more crust: collision resistance must increase with both closing
    normal speed and continental thickness, and it must ignore an edge whose neighbour was consumed
    later in the same frame. The contact search chooses the nearest *closing* foreign column rather
    than rejecting a pair because an even nearer transform is separating. Keep `tauOmega` short
    enough that changing boundary loads is not visibly viscous (`0.5 Myr` default), while keeping
    `vMax` as the hard safety cap. Add a prescribed C–C rig that checks the normal barrier grows
    monotonically with `hFel` and a natural map-start run that has no NaN after contact deletion.
C6. `js/perf.js` (§0) wired into `sim.js` — one `Perf.lap` per kernel, `Perf.step` per frame —
    and into `ui.js`, which paints `Perf.text` / `Perf.detail` when `Perf.due(now)`.
Tests: `tests/conveyor.js` — two counter-rotating hemispheres at prescribed ω (|ω| = W about
±x̂, 25 mm/yr at the pole) for 140 Myr after a 20 Myr warm-up, window and ledgers reset by
`state.rebase()`. Both halves of the shared equatorial boundary carry the analytic area flux
`4WR²` (`2WR²∫|sin φ|dφ` per half), and consumed and spawned area per Myr must each match it
within 10 %. Do not compare against speed × trench length: a rigid rotation is transform
almost everywhere and its normal speed vanishes at two points. Also asserted: the two plates'
spawn counts within 20 %, `hMaf` and `hFel` ledgers exact (Σ + subducted − produced = const to
1e-6), column count within 2 % of flux/dt, arc crust ≤ 45 km, no hole older than `fillDelay`.
`tests/rift.js` — one plate split by a prescribed pull: at 40 Myr `hFel` falls monotonically
from 35 km to ≤ 15 km within 4 cells of the boundary, and by 150 Myr oceanic columns exist and
the `hFel` ledger is exact. `tests/perf.js` — ms/step and frames/s at L5 with the per-kernel
breakdown, asserting a 40 frames/s floor. Phase C rigs set `state.prescribedOmega = 1`, which
skips K10 and keeps the caller's ω while still running `Edges.velocities`, so `plateCells`
stays fresh for the `loser()` tie-break.

### Phase D — Surface (3–4 d)

D1. `surface.js` isostasy (`z`, `wet`, `∇z`), calibration asserts for the four reference
    columns of design §7.1; make `z` authoritative here rather than keeping a second preview in
    `columns.js`. `zDyn` relaxes once per frame, then flexure and plume/trench loads are applied;
    ridge push consumes the resulting physical slope.
D2. Erosion, one-hop routing in gather form, deposition into owner columns, mobile buffers. The
    sediment buffer is part of the mass ledger even when a gap has no owner; routed material is
    deposited only after all outflows have been gathered.
D3. `column-update.js`: age, damage / heal / strength, symmetric collapse diffusion, plume swell
    and LIP. Eroding felsic or mafic crust is a transfer into mobile sediment, not a source/sink;
    signed source ledgers record that transfer so Phase C balance checks remain valid.
Tests: `tests/isostasy.js` (reference elevations ± 50 m); `tests/erosion.js` (a 6 km cone
    erodes and the mass lands in the adjacent basin; total `hFel+hMaf+hSed+mobile` conserved to
    1e-12 relative; no two-hop/checkerboard oscillation after 1000–10,000 frames);
    `tests/collapse.js` (an 80 km plateau spreads, peak falls below 70 km, mass conserved).

### Phase E — Events and cooling (3 d)

E1. `events.js`: `cycle` runs compact → census → suture → absorb → retire → compactPlates →
    split on a `eventCadence` (1 Myr) trigger, so no per-frame cost.
    `census` recounts `plateCells` from `cellPlate` and fills the boundary pair tables
    (`pairLen`/`pairVel`, keyed `lo·plateCap + hi`) that suture and absorb read. Every plate
    judgement counts cells from `cellPlate` — which K4 rewrites each frame — and never from a
    count K5 produced: a rig that prescribes ω skips K5, the stale count retires a populated
    plate, and compaction then writes `remap = -1` into live columns, which lands as `Uint16`
    65535 and reads out of bounds in K3.
    Split extracts the corridor (`owner ≥ 0 && damage > splitDamage`), BFS-labels the
    connected components of the plate's remaining cells, absorbs components under `minCells`
    into the nearest labelled cell, then keeps the components that open.
    Damage rates calibrate the *corridor fraction*, not absolute damage: at design §11's
    `kDam 0.05, kDamT 0.02` an L4 plate passes 0.8 on 70–95 % of its own cells, which
    fragments every plate every cycle instead of cutting a few rifts. `kDam 5e-4,
    kDamT 1e-3, kHeal 5e-3` hold the 0.6 corridor at 15–60 % of a plate and let healing close
    it. Corridor damage resets to `0.5·splitDamage`, so a newborn boundary starts weak
    instead of re-rifting on the next cycle, and `splitAge` (40 Myr) bars a plate from
    splitting again before then.
    `minPlateCells` is 100 at L5 (design §11 says 40) because 40-cell fragments survive long
    enough to multiply to the 128-plate cap; `Events.minCells` scales it with V. Components
    below it are re-absorbed, never dropped: dropping strands their columns (no owner → never
    advected) and leaks both ledgers.
    Each part gets ω fitted to `uMantle` by area-weighted rigid least squares
    (`Plates.dragFit`, reusing the K10 solve) rather than inheriting the parent's — inherited ω
    makes the halves move rigidly together and the rift never opens. A part is promoted to a
    plate only if the positive length-weighted opening across the cut,
    `R·((ω_part − ω_keep) × r̂)·t̂`, exceeds `vRift` (100 mm/yr). The signed mean is identically
    zero for two rigid pieces on a sphere (a polar-cap pair has orthogonal centroids and Δω),
    so only the positive half is a rift criterion, and fits are cached per label per cycle.
    New plates inherit the parent's `q`, so every column's `world` is bit-exact across a split.
    Merge is the suture rule: a pair sutures when convergent with continental polarity
    (`polarity === 2`) or transform at speed below `vSuture`, held for `mergeTime` (20 Myr);
    the winner absorbs the loser by rebasing the loser's per-column `b`
    (`b' = q_winner⁻¹ (q_loser b)`) and area-weighting the two ω, leaving `world` unchanged.
    `retire` skips a cycle in which no plate covers a cell, and returns early rather than
    compacting an empty world.
E2. Cooling schedule hooked into all `Tm`-scaled quantities; hot start initial state
    (design §9: all oceanic, `age ~ U(0,20)` Myr, 8–16 plates). At §6.4's `Tm0 1.2`/`1.6`
    and `τ 2500 Myr`, `Tm` reaches 0.45 only at t ≈ 6300 Myr, so §6.4's "≤ 1 mm/yr once
    `Tm < 0.45`" is a late-plateau statement unreachable in a 1500 Myr run; the speed
    criterion is read at mid-epoch instead.
E3. Checkpoints (`js/checkpoint.js`): a ring of `ckptCap` (16) full states every `ckptEvery`
    (20 Myr), plus save/load to one binary blob — a 64-byte header (magic `0x31544750`, format
    version, level, seed, V, colCap, plateCap, scalar and array counts, data bytes), then the
    f64 scalars, then one 16-byte record (id, offset, length) per array followed by 8-byte-
    padded blocks. `SCALARS` and `ARRAYS` are shared by both directions, so a field cannot be
    saved but not restored. Load validates magic, version, header arithmetic, level, V,
    capacities, every declared length against capacity and the exact data length *before*
    touching live state, then recomputes `world` from the restored `b`/`q` with `Sim.raster`,
    so nothing derived needs storing. `world` on a dead column is scratch in both directions.
Tests: `tests/split.js` (a plate with a prescribed damage corridor splits into exactly two
components with column world positions preserved to 1e-9, plus direct `Events.merge` and
`Events.retire` rigs); `tests/checkpoint.js` (round trip bit-identical on alive columns,
ring wrap, replay from a snapshot, malformed blobs rejected with live state untouched);
`tests/longrun.js` (hot start, 1500 Myr at dt 0.1 and 300 Myr at dt 0.01: no NaN, invariants
within 1 %, plate count in 6–40, speed statistics per epoch as in acceptance 3, at least one
split and one merge).

### Phase F — Metallogeny (2–3 d)

F1. Six saturating potentials per column (`oVms oMaf oArc oOro oBas oPla`) plus a `fert`
    drawn once at birth, in the kernel that owns the factory:
    - `contact.js` (K7): `oVms` as a one-shot at oceanic birth scaled by the spreading rate
      the ridge flanks are opening at (the gap cell itself has no owner, so its own edges were
      never classified — read the flanks); `oMaf += kM2·fert` at rift birth; `oArc` on
      `trenchDist 1–2` cells of the overriding plate, enriched by
      `1 + kRec·mean(oVms + oBas + hSed/1 km)` over the columns that plate consumed this frame
      (`arcFeed`, the same per-plate reduction `subRate` uses). A C–C merge averages the two
      columns' potentials (equal nominal area); a subducted column's potentials die with it
      after feeding `arcFeed`.
    - `column-update.js` (K8): `oMaf` from plume heat, `oOro` for continental columns within
      one ring of a C–C convergent or continental transform edge (`belt`, marked once per
      frame) or thicker than `hOro`, `oBas` for thick sediment under water, and `kDecay` on
      all six. The ring scan is shared with the damage pass — a second walk of the ring costs
      ~0.9 ms/step at L5.
    - `surface.js` (K9): `oBas += kB·deposited·mFel` and `oPla` from the placer load, both
      only where `z < zBasin`. Placer is liberated at erosion in proportion to the source
      column's `oOro + oArc` and rides `mobilePla`, which K9 already routed, so placer can
      only end up downslope of an orogenic or arc maximum.
    Every rate carries `(1 − o)`, so a potential is bounded by 1 with no clamp, and K11 fails
    the finite check if one ever exceeds it. `Σ` per class is a diagnostic, not a ledger:
    potentials saturate and decay.
F2. `extract.js` (CPU, on demand, may allocate): 1-cell blur onto cells, local maxima above a
    threshold with plateaux resolved by cell index, ranking, and a context tag (kind, host
    crust, depth, age, epoch, plate, latitude) plus a JSON dump. The core never reads it.
F3. One shared ramp for all six potentials in `render.js` (`Renderer.ORE`), a probe line with
    the six values and `fert`, and a Deposits JSON button.
Tests: `tests/ores.js`. Acceptance 5's percentages are checked where they are properties of
the factories, not of the end state: each production site is asserted exactly by calling the
owning kernel and diffing (`oArc` only within 2 cells of a trench on an overriding plate,
`oVms` only on oceanic crust, `oOro` only on continental, `oBas` only on thick sediment). The
end-state shares are *lower* and fall with run length, because a deposit is a fossil record
that its plate carries away from the trench that made it — after 800 Myr at L4 only ~48 % of
`oArc` mass is still within 2 cells of a trench. Placer gets its own rig, since in a full
world almost all continental crust is orogenic and the statistical contrast is only ~1.1:
erode one orogenic summit and assert placer lands only downhill of it, in a submerged or low
cell, and nowhere at all when the summit is not orogenic. Also: no potential above 1, every
class populated and bounded, ranked deterministic deposits, and a checkpoint round trip.

### Phase G — CPU release and calibration (2–3 d)

G1. Parameter sweep script (`experiments/sweep.js`): U0, vSlab, kArc, kCollapse against
    acceptance 3–5 at dt 0.02 and 0.1; record chosen defaults in `params.js`.
G2. Performance pass at L5: profile, remove hot allocations, target ≥ 100 frames/s in Chrome
    (`tests/perf.js` in node ≥ 60 frames/s as a proxy).
G3. `findings-pitfalls-skills.md` entries: raster threshold, no-advection decision, hysteresis,
    order-independent gathers; move this plan's finished parts to `archive/` only when the GPU
    phase supersedes it.
Done: all tests pass; a 4.5 Gyr history plays at L5 in the browser with layer switching.

### Phase H — WebGPU port (6–8 d)

H1. `sim-gpu.js`: device, buffers mirroring `state.js` (storage buffers of `vec4<f32>` /
    `u32`), bind groups per kernel, uniform block for params/dt/Tm.
H2. Kernels in order of data flow, each validated against the CPU kernel on the same state
    (`tests/gpu-parity.js` runs in the browser with a manual harness or via Chrome headless if
    available; load identical E3 checkpoint blobs; per-kernel tolerance
    abs 1e-6 + rel 1e-5 in normalized units, exact integer outputs away from decision thresholds;
    explicitly test tie and threshold behavior separately):
    K1 PLATES (one workgroup), K2 MOVE, K3 BIN (count via atomicAdd — integer, order-free;
    scan; scatter via atomicAdd cursor; then per-cell sort by (distance,index), with no assumed occupancy cap;
    detect capacity overflow and fail explicitly rather than drop entries),
    K4 RASTER, K5 EDGES (+ 2-ring gather), K6/K7 CONTACT and APPLY (spawn slots via scan),
    K8 COLUMN, K9 SURFACE ×3, K10 REDUCE (workgroup partial sums in fixed order, second pass
    per plate, solve in the same kernel), K11 DIAG (atomic counters, u32 fixed point).
H3. Events (split/merge/compaction) stay on the CPU: readback of `plate`, `damage` per column
    every ~1 Myr (asynchronous `mapAsync`, applied one event-cycle late), upload of the plate
    table. Compaction on the GPU by scan.
H4. Renderer: equirect and globe from `lookup` + cell buffers directly (no readback);
    layers as in the CPU version.
H5. L6 then L7: memory (derive bytes from the actual buffer schema including scratch, double buffering,
    staging and checkpoints; do not use a 64-byte column estimate for the full design), timing
    per kernel with timestamp queries, target ≥ 60 frames/s at L7 including render.
Done: from identical checkpoints, compare short coupled runs (50 frames) with tolerances
calibrated against f32 reference arithmetic and document threshold-triggered divergence.
At 1000 frames compare ensembles of seeds: plate count, speed histograms and area-age
distributions within predeclared statistical bounds, not per-column trajectories. Same-device
GPU repeat runs must be deterministic. L7 runs in real time; acceptance 1–7 met.

### Phase I — Polish (open-ended)

Timeline scrubbing over checkpoints, deposit inspector, plate labels and history tree, presets
(hot start, map start), export of `z`/`wet`/deposits for the game.

## 3. Risks and how the plan handles them

| risk | mitigation | phase |
|---|---|---|
| overlap detection misses fast closers (0.18 cell/frame at L7, 10 cm/yr) | search in cell ∪ ring bins covers ≥ 0.85 d; test with vMax | C |
| gap spawn oscillation at slow divergent boundaries (spawn, then overlap, then delete) | spawn only when the gap persisted 2 frames and no opposing column within `rContact·d`; `vSuture` dead zone | C |
| divergence over-produces crust, so the column count grows without bound | spawn at `rSpawn = 0.85 d`, above the raster's 0.75 d gap threshold, calibrated against the `4WR²` flux test; `fillDelay` still fills holes that never open | C |
| permanent uncovered cells inside fresh crust | `fillDelay` fallback in the gap scan; assert no gap outlives it | C |
| collision never stops (winner keeps eating) | collision resistance grows with `hFel` and `−relN`; stale edges are skipped after contact deletion; merge rule after 20 Myr of near-zero closing | C, E |
| collision barrier becomes visibly viscous | use a 0.5 Myr angular relaxation and calibrate against the prescribed C–C normal-load rig; do not raise basal drag globally to hide contact errors | C |
| continents drift apart from their arcs → felsic never accumulates | arc growth on `trenchDist 1–2` cells of the overriding plate regardless of crust type; hot early `kArc·Tm` | C |
| damage never localises → no splits | ext from poloidal flow + plumes, `strength` low on young/hot crust, corridor threshold sweep in G1 | E, G |
| damage saturates everywhere → every plate fragments every cycle | calibrate damage rates against the corridor *fraction* (0.6 threshold, 15–60 % of a plate), reset corridor damage after a split, `splitAge` gate | E |
| split produces halves that never separate | fit ω per part from `uMantle`, then gate on the positive length-weighted opening across the cut (`vRift`); a signed mean is exactly zero for rigid bodies | E |
| compaction wipes a populated plate and poisons `plate` with 65535 | judge plates from `cellPlate` (rewritten every frame by K4), never from a count only K5 fills; `retire` returns early on an empty census | E |
| restored state drifts because a derived buffer was not saved | store only primitives; recompute `world`, `z`, `vel` with `Sim.raster` after load | E |
| grid banding in erosion routing (hexagonal lattice directions) | lowest-neighbour hop with δ dead zone and 50 % under-water pass-through; check spectrum in tests | D |
| GPU nondeterminism | only integer atomics; explicit per-cell sort; fixed-order reductions | H |
| dt insensitivity fails (0.01 vs 0.1 give different worlds) | statistics-level comparison in `tests/longrun.js` at both dt; all rates ∝ dt, events threshold-based | every phase |
