# 0.2 — Project plan

Implements `0.1.5-final-design.md`. Self-contained: a fork can execute this plan with the
design document alone. Order: **CPU (plain JS, L5)** → **WebGPU (L6–L7)**, same kernel
structure in both. Frame step is a user setting in 0.01–0.1 Myr and every phase is tested at
both ends of that range.

## 0. Conventions

- Runtime per `AGENTS.md`: classic `<script>` tags, file:// friendly, no build, tabs, no
  allocation in the frame loop, `module.exports` guarded so files run under node.
- Hoist sort comparators out of kernels; do not create inline callbacks in hot paths.
- CPU geometry, rotations and physical fields use Float64Array; integer identifiers use
  integer arrays. GPU uses f32, so long trajectories are compared statistically, not pointwise.
- One file per kernel or entity; every kernel is a function `(state, dt)` that reads previous
  buffers and writes its own outputs — the GPU port is one WGSL file per JS kernel.
- All state in typed arrays with a fixed capacity (`colCap = 1.5·V`, `plateCap = 128`); a
  `state.js` module owns allocation, `params.js` owns the defaults from design §11.
- Tests are node scripts in `tests/` printing PASS/FAIL and the measured numbers; `npm` is not
  used, `node tests/run-all.js` runs everything. Each phase ends when its tests pass.
- `experiments/` holds throwaway measurements (kept: `advection-bench.js`, the evidence for the
  transport choice). Findings that change how something should be done go to
  `findings-pitfalls-skills.md`.

## 2. Phases

Estimates are working days for one developer; each phase has a done-criterion.

### Phase A — Foundation (2–3 d)

A1. `geodesics.js`: keep the mesh math, add flat tables `ring[V*6]` (−1 pad), `ringN`,
    `nbrDist`, `edgeLen`, `faceN` (tangent unit normal per edge, vec3), `A0`; remove the ocean
    bathymetry block (`cellC`, coast BFS) and the `opts` schema — land mask from the fbm stays
    for the map start. Keep `lookup`.
A2. `quat.js`, `params.js`, `state.js` with capacity-fixed typed arrays, `reset(seedState)`.
A3. `columns.js`: `climb`, MOVE, BIN (count / scan / scatter), RASTER with total order
    (distance, index) and `rGap`.
A4. `render.js` minimal: equirectangular canvas via `lookup`, layers `plate`, `z`, `owner`
    presence; `ui.js` play/pause/dt/seed.
Tests: `tests/raster.js` re-runs the transport bench through the real kernels (30° cap,
1000 Myr at dt 0.1 and 100 Myr at dt 0.01): IoU ≥ 0.95, interior gaps 0, ≤ 3 climb steps
p99. Test the moving cap without stationary competing columns: nearest-distance ownership
is not the priority override used by the original bench. Keep overlap/contact physics in C.
`tests/determinism.js`: identical seed and inputs produce bit-identical arrays and scalars;
reset reproduces initialization. `tests/alloc.js`: run with `node --expose-gc`, warm up,
collect before and after 1000 frames, report heap and ArrayBuffer deltas with bounded retained
growth. This is a leak smoke test, not proof of zero transient allocation; audit hot kernels
and use GC/profiler traces separately.

### Phase B — Kinematics and boundaries (3–4 d)

B1. `mantle.js`: `Tm(t)`, potentials Φ Ψ from the existing harmonic machinery with precessing
    directions, plumes, `u_mantle(r,t)`, `ext`. Test: divergence of `∇ₛΦ` non-zero, mean
    speed ≈ U0·Tm^2.5, field is smooth (no grid banding: spectrum check on the lookup image).
B2. `plates.js`: `M` and `b` accumulation, 3×3 solve, relaxation, `vMax`. Test: with
    `u = Ω × r` every plate returns `ω = Ω` to 1e-9; with drag only, a plate under a divergent
    field gets the least-squares rotation (compare against a brute-force fit).
B3. `edges.js`: `relN/relT`, hysteresis, polarity, `trenchDist`. Test: two prescribed plates
    (analytic ω) classify all boundary edges correctly; flicker < 5 % under added noise of
    0.5 mm/yr.
B4. Seed plates: Voronoi on N random seeds → `plate` per column, `q = identity`, `b = r`.
B5. `diag.js`: preallocated counters and history ring, finite-value and rigid-motion
    assertions, source/sink ledgers for later mass-balance tests.
Done: 16 plates move under the mantle field for 500 Myr, boundaries drawn by type; velocity
spread within a plate is exactly rigid (assert), speeds 1–10 cm/yr with default `U0`.

### Phase C — Gaps and overlaps (4–5 d)

C1. `contact.js` gap spawn: donors, oceanic vs rift branch, deterministic slot allocation
    (prefix sum over gap flags), plate choice with hash tie-break.
C2. Overlap detection in bins, polarity, `consumedBy` marks; APPLY: winner gather,
    accretionary prism, arc growth on `trenchDist 1–2` cells, deletion, compaction in `events.js`.
C3. Collision branch (C–C) with merge into winner; collision resistance force in `plates.js`.
C4. Slab pull and ridge push contributions (`w_i`) in `plates.js` (ridge push needs `z` from
    Phase D — use `age`-only Parsons–Sclater until then).
Tests: `tests/conveyor.js` — two plates driven at prescribed ω converge at 5 cm/yr for 100 Myr:
consumed area per Myr = speed × trench length ± 10 %, ridge behind spawns columns
symmetrically ± 20 %, `hMaf` mass balance exact (Σ + subducted − produced = const to 1e-6),
column count stable ± 2 %. `tests/rift.js` — one plate split in two by a prescribed pull:
margins thin 35 → 15 km over ≤ 4 cells, oceanic crust appears, no interior gaps.

### Phase D — Surface (3–4 d)

D1. `surface.js` isostasy (`z`, `wet`, `∇z`), calibration asserts for the four reference
    columns of design §7.1; `zDyn` relax + flexure; collapse diffusion in `column-update.js`.
D2. Erosion, one-hop routing in gather form, deposition into owner columns, mobile buffers.
D3. `column-update.js`: age, damage / heal, strength, plume swell and LIP.
Tests: `tests/isostasy.js` (reference elevations ± 50 m); `tests/erosion.js` (a 6 km cone
erodes and the mass lands in the adjacent basin; total `hFel+hSed+mobile` conserved to 1e-9;
no checkerboard after 10,000 frames); `tests/collapse.js` (an 80 km plateau spreads, peak
falls below 70 km, mass conserved).

### Phase E — Events and cooling (3 d)

E1. `events.js` split: corridor extraction from `damage`, connected components (BFS over
    cells of the plate), new plate creation, `minPlateCells`; merge/suture rule; compaction.
E2. Cooling schedule hooked into all `Tm`-scaled quantities; hot start initial state.
E3. Checkpoints (ring of full state every 20 Myr), save/load to a binary blob (typed arrays
    concatenated, header with magic, format version, level/seed/t, numeric types,
    per-array lengths and byte lengths; reject unknown versions, malformed lengths and
    truncated/trailing data before mutating live state; include all persistent event/RNG state); fast-forward loop without render.
Tests: `tests/split.js` (a plate with a prescribed damage corridor splits into the right two
components, columns keep world positions to 1e-9); `tests/longrun.js` (hot start, 1500 Myr at
dt 0.1 and 300 Myr at dt 0.01: no NaN, invariants within 1 %, plate count in 6–40, speed
statistics per epoch as in acceptance 3, at least one split and one merge).

### Phase F — Metallogeny (2–3 d)

F1. Six potentials in `column-update.js`/`contact.js`/`surface.js` per design §8, fertility
    noise at column birth, saturation and decay, recycling enrichment term at arcs.
F2. `extract.js` (CPU, on demand): 1-cell blur, local maxima, ranking, context tag; JSON dump.
F3. Layers in the renderer for each potential; probe panel (click a cell → column fields).
Tests: `tests/ores.js` on the long run of E: acceptance 5 percentages, per-class totals
monotone-saturating, no potential > 1.

### Phase G — CPU release and calibration (2–3 d)

G1. Parameter sweep script (`experiments/sweep.js`): U0, vSlab, kArc, kCollapse against
    acceptance 3–5 at dt 0.02 and 0.1; record chosen defaults in `params.js`.
G2. Performance pass at L5: profile, remove hot allocations, target ≥ 100 frames/s in Chrome
    (`tests/perf.js` in node ≥ 60 frames/s as a proxy).
G3. `findings-pitfalls-skills.md` entries: raster threshold, no-advection decision, hysteresis,
    order-independent gathers; move this plan's finished parts to `archive/` only when the GPU
    phase supersedes it.
Done: all tests pass; a 4.5 Gyr history plays at L5 in the browser with layer switching.

### Phase H — WebGPU port (6–8 d)

H1. `sim-gpu.js`: device, buffers mirroring `state.js` (storage buffers of `vec4<f32>` /
    `u32`), bind groups per kernel, uniform block for params/dt/Tm.
H2. Kernels in order of data flow, each validated against the CPU kernel on the same state
    (`tests/gpu-parity.js` runs in the browser with a manual harness or via Chrome headless if
    available; load identical E3 checkpoint blobs; per-kernel tolerance
    abs 1e-6 + rel 1e-5 in normalized units, exact integer outputs away from decision thresholds;
    explicitly test tie and threshold behavior separately):
    K1 PLATES (one workgroup), K2 MOVE, K3 BIN (count via atomicAdd — integer, order-free;
    scan; scatter via atomicAdd cursor; then per-cell sort by (distance,index), with no assumed occupancy cap;
    detect capacity overflow and fail explicitly rather than drop entries),
    K4 RASTER, K5 EDGES (+ 2-ring gather), K6/K7 CONTACT and APPLY (spawn slots via scan),
    K8 COLUMN, K9 SURFACE ×3, K10 REDUCE (workgroup partial sums in fixed order, second pass
    per plate, solve in the same kernel), K11 DIAG (atomic counters, u32 fixed point).
H3. Events (split/merge/compaction) stay on the CPU: readback of `plate`, `damage` per column
    every ~1 Myr (asynchronous `mapAsync`, applied one event-cycle late), upload of the plate
    table. Compaction on the GPU by scan.
H4. Renderer: equirect and globe from `lookup` + cell buffers directly (no readback);
    layers as in the CPU version.
H5. L6 then L7: memory (derive bytes from the actual buffer schema including scratch, double buffering,
    staging and checkpoints; do not use a 64-byte column estimate for the full design), timing
    per kernel with timestamp queries, target ≥ 60 frames/s at L7 including render.
Done: from identical checkpoints, compare short coupled runs (50 frames) with tolerances
calibrated against f32 reference arithmetic and document threshold-triggered divergence.
At 1000 frames compare ensembles of seeds: plate count, speed histograms and area-age
distributions within predeclared statistical bounds, not per-column trajectories. Same-device
GPU repeat runs must be deterministic. L7 runs in real time; acceptance 1–7 met.

### Phase I — Polish (open-ended)

Timeline scrubbing over checkpoints, deposit inspector, plate labels and history tree, presets
(hot start, map start), export of `z`/`wet`/deposits for the game.

## 3. Risks and how the plan handles them

| risk | mitigation | phase |
|---|---|---|
| overlap detection misses fast closers (0.18 cell/frame at L7, 10 cm/yr) | search in cell ∪ ring bins covers ≥ 0.85 d; test with vMax | C |
| gap spawn oscillation at slow divergent boundaries (spawn, then overlap, then delete) | spawn only when the gap persisted 2 frames and no opposing column within `rContact·d`; `vSuture` dead zone | C |
| collision never stops (winner keeps eating) | collision resistance grows with `hFel` and `−relN`; merge rule after 20 Myr of near-zero closing | C, E |
| continents drift apart from their arcs → felsic never accumulates | arc growth on `trenchDist 1–2` cells of the overriding plate regardless of crust type; hot early `kArc·Tm` | C |
| damage never localises → no splits | ext from poloidal flow + plumes, `strength` low on young/hot crust, corridor threshold sweep in G1 | E, G |
| grid banding in erosion routing (hexagonal lattice directions) | lowest-neighbour hop with δ dead zone and 50 % under-water pass-through; check spectrum in tests | D |
| GPU nondeterminism | only integer atomics; explicit per-cell sort; fixed-order reductions | H |
| dt insensitivity fails (0.01 vs 0.1 give different worlds) | statistics-level comparison in `tests/longrun.js` at both dt; all rates ∝ dt, events threshold-based | every phase |
