## 0.7.0 — live resolution is state transfer, not Earth.apply

`Earth.apply` seeds fields from a pack, sets plate state and rebases ledgers. It does not
conservatively transfer a live Lagrangian world. Reusing its interpolation helpers may
be useful, but applying it to a running world discards history. A surface RMS score is
necessary for visual quality, not sufficient for physical equivalence.

Implementation sequence:
1. Inventory authoritative state, derived fields, grid-indexed transport fields, column
   and plate capacity, event timers, RNG, mantle, ledgers and exploration identity.
   First prototype retaining columns while rebuilding the neighbour/raster frame;
   measure whether coverage/contact assumptions remain valid. If columns must split or
   aggregate, define an explicit conservative remap rather than interpolate thickness.
2. Preserve material volumes `Σ(area × thickness)` and area-weighted inventories;
   handle columns representing multiple materials and discontinuous plate boundaries.
   Define age/fertility/potential weighting, plate quaternions/body coordinates and
   mobile sediment transfer. Recompute derived raster fields, not crust advection.
   Audit `A0ref`, spawn area and column capacity as resolution changes.
3. Pause/drain/read back once. Build and validate a candidate world off to the side.
   Preserve time/RNG/history and declared settings. Rebind render lookup, buffers,
   pick state, water/hypsometry, events and checkpoint layout. Commit atomically;
   failure/cancel keeps the old world usable, including its renderer and deposits.
4. Test L5→L6→L5 and L7 paths, synthetic and Earth starts, CPU and GPU. Define numeric
   conservation tolerances from a reference remapper before UI work. Check no time or
   RNG advance during rebuild, no duplicated/lost deposit IDs, correct next-step event
   behaviour and checkpoint replay. Report field/surface error separately from volume
   error; reject unbounded round-trip drift.
5. Wire an explicit live resolution action with progress/confirmation. `?level=` remains
   startup configuration, not a mechanism for preserving a live state. Measure peak
   memory with old and new worlds simultaneously resident before enabling the action.

## 0.7.1 — L8 is a feasibility gate

L8 has 655,362 cells, four times L7. `GpuSim.layout` uses 83 f32 per cell for gridF
alone: about 207.5 MiB at L8, above the common 128 MiB storage-binding limit. Query
adapter limits and account for every buffer, maximum binding, dispatch and CPU mirror;
request supported limits or redesign layouts before offering L8. Include temporary
rebuild/readback allocations, not just steady-state storage.

Benchmark event cycles, plateCap/minPlateCells scaling, lookup quality, startup and
water-volume histogram cost. Adopt incremental/device-side hypsometry only if profiling
justifies it. Fine Earth packs depend on source fidelity and memory, not just cell count;
0.5°/0.25° inputs must win independent accuracy tests before adding page weight.

## 0.7.2 — physics selection

Choose one of climate/eustasy-coupled erosion, elastic flexure, or intraplate/back-arc
mechanics only after specifying a measurable target and cost. Display water level is
not a climate model. Extend CPU first with matching GPU structure, demonstrate
10–100 kyr timestep robustness, run one-factor `sweep.js` experiments and recalibrate.
No commitment to all three in one release; each changes physical meaning and history.

## 0.7.3 — historical coastline evaluation

Evaluate PaleoCoastlines v7 (DOI 10.5281/zenodo.7994000) in an offline ingest prototype.
Declare how polygon coastlines relate to each pack's PaleoDEM vintage and keep training
and evaluation sources distinct. Re-run `reconstruct-score.js`; publish ceiling and
forward scores separately. Do not tune erosion to force a prescribed-rotation forward
run to equal a rigid reconstruction ceiling. Improved polygons are not automatically
improved physics or valid modern sediment/ore evidence.

## Data-loading stream

Classic-script lazy loading is a plausible file://-friendly alternative to eager packs;
it still needs browser tests. A loader needs a loading/error state, request deduplication,
latest-selection-wins generation token, reset cancellation, bounded decoded-pack cache
and validation before apply. Test offline file:// and HTTP, rapid epoch switches and
missing/corrupt packs. Keep URLs local. Measure initial parse/ready time and retained
memory before adding loader complexity.

`experiments/logs/heightfield-calibration-2026-10-03.log`, short profile `tests/heightfield.js`:

| --- | --- | --- | --- | --- | --- | --- |
| L5 | 2048x1024 | 32.0 MiB | 1268 ms (0.60 µs/texel) | 0 / 0 | 0.026/65535 of range | 93.6 % → 0 % |
| L6 | 2048x1024 | 32.0 MiB | 1356 ms (0.65 µs/texel) | 0 / 0 | 0.013/65535 of range | 87.4 % → 0 % |
| L7 | 2048x1024 | 32.0 MiB | 1514 ms (0.72 µs/texel) | 0 / 0 | 0.006/65535 of range | 75.9 % → 0 % |

Shared edges agree to 1.4e-11 m (L5) and 7.7e-11 m (L7) over a 13 km synthetic range; constants
and sample centres are exact; the CPU reference gathers 2048x1024 in 24-43 ms, which is what a
readback comparison costs, not what a frame costs. The plateau column is the reason the mode
exists: three quarters to nine tenths of horizontally adjacent texel pairs carry *exactly* the
same height under the nearest-cell gather, and none do afterwards.

Two things the slice changed against the plan's wording, both recorded here so slice 2 does not
re-derive them:

- **No 2x2 Gram solve.** The plan says to intersect the ray with the face plane and take planar
  barycentric weights. The determinant form - `dot(dir, cross(b,c))` and its two cyclic partners,
  divided by their sum - is the same ratio, because the intersection point is a positive
  combination of the three vertices and each triple product isolates one coefficient. The Gram
  determinant at L7 face sizes is ~1e-19: it produced 4 fallbacks and weights of ±50 per 2M
  texels. The determinant form gives 0 and 0. The three numbers are also the containment test,
  so the builder computes them once.
- **The seed needs four lookup texels, not one.** `grid.lookup` is a nearest-cell raster built by
  a chained hill climb, and at the pole corner of row 0 it lands a whole cap away (cell 116690
  against the true 36 at L7, 32 climb hops). Reading the best of the four lookup texels around
  the direction fixes it for one extra read; the climb cap is 64 with an early exit, so the cap is
  never the cost. This is a pre-existing one-texel blemish in the 2D map's own lookup, left
  alone here: fixing the builder's first-row guess is a `geodesics.js` change with its own gate.

Two more things the review changed, both in `0.5.6-review.md` with reproductions:

- **The containment predicate now needs the plane offset too.** The shared-sign test on the
  three triple products accepts the face at the antipode as well; `faceInside` requires the
  barycentric sum and `det(a, b, c)` to share a sign, which is exactly "the ray meets the face
  from the front". No shipped record changed (the candidate set is local), but only now can a
  full scan over every face be used to validate a lookup - and it is: exactly one face covers
  every texel direction of an L3 lookup, it is the recorded one, and the weights match an
  independent planar solve to 1e-9. The determinant is only needed for candidates that already
  share a sign, so the build stays at 1.18-1.28 s for 2048x1024.
- **The calibration's `[seed]` argument now varies the sampled field.** The geodesic grid's
  geometry does not depend on the seed, so four seeds used to print identical tables; the seed
  shifts the synthetic relief's phase and the header says what it varies.

Slice 2 (`js/render3d.js`, `0.5.6-review.md` §4): the record variant is the same shader with the
`M_TEXEL` body swapped, the record binding declared only in `vertex`, both pipelines and bind
groups cached at init so the live swap allocates nothing, and the record word decoded by mask
rather than `unpack2x16unorm` so the device accumulates the reference's own integers (a
deliberate deviation from §14.2's wording). Every generated shader source - 60 of them, the four
3D variants included - compiles clean under `naga`; the `hex` variant's SPIR-V is byte-identical
to the one shipped in `49aeb39`. The device readback diff lives in `webgpu-smoke.html` and runs
on the owner rig.
