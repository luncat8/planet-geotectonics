# 0.8.3 — Backport decisions, observation return path and deferred live bridge

This plan records what is worth carrying across from `planet-tectonics-2d-slice`, what must stay
there, and the only safe direction of travel after a verified globe cutter exists. It prevents an
ambitious “integration” from silently becoming two competing tectonic simulations.

The immediate 0.8 deliverables remain the v2 exchange contract, manual cutter and optional Earth
bake (`0.8.0`–`0.8.2`). The live bridge described here is a gated follow-on design, expected no
earlier than a subsequent coordinated release.

## 1. Review outcome: adopt, adapt, or leave local

| reviewed slice feature | decision in this repository | reason |
| --- | --- | --- |
| pure section-pack codec, explicit units, quantisation and malformed-input rejection | **adopt, as coordinated v2** | a small file-safe interchange is the correct integration seam; 0.8.0 closes its v1 checksum/schema holes |
| copied-code manifest and drift test | **adopt** | byte-identical shared code is viable only for a tiny pure protocol with an explicit hash gate |
| Copy, Save and load-before-live transport | **adopt** | works under `file://`, exposes the actual artifact and avoids host/origin assumptions |
| raw strip beside reconstructed section, assumption ledger, layer-resolution warning | **leave in the slice UI; require in handoff** | it honestly distinguishes globe facts from section interpolation, but belongs beside the section renderer |
| conservative arc-length box filter and fixed physical constants | **leave in the slice solver** | they are correct one-dimensional reconstruction concerns, not globe raster semantics |
| returned core logs treated as observations rather than material | **adapt later** | this is the only safe return path, after a portable validation schema exists |
| path checksum, stale demotion, atomic validation in coupling code | **adapt later through shared v2 identities** | good safeguards, but the current implementation has private hash/model dependencies |
| old deposit models/economics and port manifest pin | **do not backport** | the globe now owns a newer 13-class, plate-frame-anchored catalogue and different economics semantics |
| section beds, section-local deposits, narrow belt/topology machinery | **do not backport** | they answer a different, one-dimensional reconstruction problem and must not mutate globe state |
| checkpoint envelope, clipboard/env helpers, DOM harness style | **do not replace** | this repository already has its own current checkpoint/GPU/UI paths; duplicate infrastructure adds drift without integration value |
| continuous C3/C4 reconcile | **defer** | it is not scientifically or operationally ready to become globe authority |

The source comparison also means that `d909476` is a provenance boundary, not a target API.
Features added after that pin—live resolution, current deposits/economics, current GPU readback
and view interaction—must be handled through the current globe modules, not repaired by copying
old slice-side ports.

## 2. A narrow, safe return contract: imported observations

After 0.8.1 has exported real v2 packs and the slice repository has reconstructed them, the first
return feature may be a **manual core-log import**. It is read-only evidence from the section,
not an alternate source of tectonic truth.

### 2.1 Required v2 core-log protocol work

The current slice `pgt-core-log` v1 is not yet portable enough to place in this repository: it
uses a private section FNV helper and section-local numeric lithology/flag tables. Do not paste
that module into the globe.

Instead, coordinate a small `port/core-log-format.js` v2 only when the import is actually
scheduled. It must be byte-identical and independently testable in both projects. Its canonical
body includes:

```text
format/version
pathChecksum               // SlicePack.pathChecksum(active pack.path)
packChecksum               // exact full v2 source pack checksum
arcKm, tMyr, epochMa
lithologySchema            // named/versioned portable vocabulary, not an implicit local index
records: [{ sKm, div, hTotM, beds: [{ lithology, thicknessM, formedMyr, flags }] }]
checksum
```

The pure codec owns fixed key ordering, UTF-8 checksum, six-significant-digit quantisation and
all validation. It rejects a missing checksum on parsed input, foreign versions, unknown
lithology schema, duplicate/out-of-order arc records, non-finite values, empty/oversized bed
stacks, non-positive thicknesses, thickness totals outside an explicit quantisation tolerance and
non-monotone depositional ages except where both named intrusion flags permit an inversion.

`packChecksum` is mandatory. `pathChecksum` alone says two lines have the same geometry; it does
not prove that a returned bed stack came from the same globe snapshot. A log that has valid
structure but references a different full pack may be archived as an explicitly stale external
observation only after user confirmation; it is never displayed as a current probe result.

### 2.2 Globe-side import behavior

Add a globe-owned `SectionObservations` side table rather than fields on `State`:

```text
key = pathChecksum + ':' + packChecksum
value = { importedAt, sourceMetadata, records, validationReport, staleReason }
```

The importer accepts pasted text and a `.json` file through the same file-safe UI pattern as other
imports. Its order is strict:

1. parse and validate into a new temporary object;
2. compare its path/full-pack identities and arc against the selected exported artifact;
3. create a compact immutable side-table entry only on success;
4. redraw an `observed section log` panel / optional probe annotation;
5. never touch `state`, `grid`, `Checkpoint`, GPU buffers, plate ids, crust arrays, ore
   potentials, diagnostics, water, simulation clock or random state.

A probe can show the nearest matching record as, for example, `Observed section log · 37 km from
cut point · source pack abcdef12 · stale after world changed`. It must show raw named beds and
formation-time semantics as supplied, not call them globe crust layers. The section retains
ownership of its lithology vocabulary and reconstruction assumptions.

An imported observation does not persist inside a world checkpoint. It may be exported/imported
as its own validated JSON and may be kept in page-local UI state; restoring a globe checkpoint
cannot make an unrelated observation appear current. Rebuilds, path edits, state time changes and
new exports evaluate freshness against the stored full pack identity and visibly demote old logs.

### 2.3 Observation acceptance tests

Before shipping this narrow return route, test:

- valid v2 logs at exact path/full-pack identity import atomically and display without state
  mutation;
- every malformed schema/boundary/stratigraphy/checksum case leaves the previous side table and
  UI intact;
- same path but different source checksum becomes stale rather than current;
- same source checksum but a different canonical path is refused;
- changing a globe state field, rebuilding or changing cut flags an otherwise valid imported log
  as contextual/stale;
- a log cannot influence a later exported pack, simulation result, prospect ledger or GPU
  upload/download;
- both repositories pass the shared port-hash and fixture tests.

## 3. Live bridge: prerequisites, not a 0.8 promise

A future host may make a verified v2 snapshot convenient to send between two pages. It must retain
the manual file path as its debugging/escape hatch and use a named link state machine:

```text
C0 no compatible pack
C1 verified globe snapshot available
C2 slice reconstruction initialized from that exact snapshot
C3 section-only evolution / observations
C4 optional read-only comparison report
```

At C1/C2, the source artifact is still a `pgt-slice-pack` v2 payload and its full/path identities
are checked before any receiver state changes. A host must use relative URLs and an explicit
allowed origin when served, while the standalone pages continue to work from a file. It must not
make browser-facing calls to localhost or rely on a hidden loopback service.

The current slice coupling envelope should not be copied wholesale. Before a C4 design is
implemented, extract and audit only its useful pure notions into a new versioned shared module:
canonical interval coverage, full/path identity checks, atomic parse/validate/apply ordering and
stale status. A coupling message must include source pack checksum, path checksum, source time,
sea metadata and exact interval semantics. It must not use a private section hash or assume the
globe's dense plate ids remain stable across worlds.

### Hard gates before C3/C4

Do not start a live reconcile or any globe feedback loop until all are demonstrated:

1. repeated manual v2 round trips for CPU and GPU globe snapshots succeed;
2. both sides reject path/checksum/schema mismatches without partial mutation;
3. a source snapshot and all returned observations remain correctly stale after either world
   changes;
4. the slice side automatically rebuilds its section plate topology after incoming crossings;
5. the slice side closes its documented R4 mechanical diagnostic: a narrowing belt must not show
   a rising closing-speed trend without an explained, measured exception;
6. fixed-seed, fixed-cadence runs prove no mass/clock/ownership ambiguity at every handoff;
7. a review explicitly decides whether C4 remains comparison-only or has any permitted feedback.

Current slice follow-up work reports items 4 and 5 as unresolved. That is a block, not a minor
test gap. In particular, no 0.8 acceptance condition may claim mechanically validated two-way
coupling, topology mutation on the globe, or section-derived mass transfer.

## 4. Agent handoff checklist

### Globe integration agent

- implement `0.8.0` first and make no wire format decision locally;
- use `Resolution.nearestCell`, owner/column semantics and the existing GPU idle/download pattern;
- export raw current fields only, with explicit gaps and provenance;
- keep all section result imports outside `State` and GPU state;
- measure each offered resolution rather than inheriting stale cut-size estimates;
- give the counterpart a raw v2 fixture, command/state provenance and both identities.

### Slice integration agent

- migrate its v1 codec/fixtures/bundles as one v2 cutover; do not retain a legacy reader;
- preserve the raw/reconstructed distinction and label all extrapolated beds/deposits as section
  assumptions;
- return only validated observations whose identity points to the exact received pack;
- keep its section physics/topology local and report unresolved topology/R4 gates candidly;
- do not import the globe's current deposit catalogue by copying code; consume the six exported
  potentials as the intended interface.

### Review agent

- compare SHA-256 entries in both `PORT.json` files before accepting a protocol change;
- independently perturb path, sea, plate metadata, gap rows and payload fields to prove integrity;
- audit browser transport under `file://` as well as a hosted preview;
- reject any patch that lets a section observation alter globe physics, says a stale artifact is
  current, or treats the old `d909476` port as current compatibility.

## 5. Completion definition

0.8.3 is complete as planning/architecture work when the backport boundary is documented, a
portable observation protocol is specified but not prematurely merged, and the live bridge's
scientific gates are explicit. Implementation may stop after 0.8.2 without being incomplete:
one-way, file-safe, validated export is the intended useful integration milestone.
