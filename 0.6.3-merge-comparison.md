# 0.6.3 — merging two independent implementations of the deposit prospector

Two Arena sessions started from the same 0.6.0 base and each implemented the next
increment on its own. This records what each one built, what was taken from which, what was
thrown away and why, and what the measurement says about the result.

The two histories are **unrelated**: `git merge-base` between them returns nothing, because
one branch is a single squashed commit and the other carries 76. The merge was therefore
`git merge --allow-unrelated-histories -X theirs`, which takes the alternate tree for every
file both sides touched and keeps the files only one side had — followed by hand work on
the pieces that survived but no longer ran.

## 1. The core disagreement: how a deposit is generated

This is the load-bearing difference, and the two answers are not compatible.

**This branch** generated a deposit as a **continuous statistical object**: three families
(`vms`, `arc`, `orogenic`), lognormal grades and tonnages about a published median, a stored
grade–tonnage correlation, ellipsoid axes with strike and dip, and a cube-sphere tile grid
(64 × 64 × 6 = 24,576 tiles, level-independent) as the identity frame. Identity came from
`(seed, generator version, snapshot checksum, tile, fu, fv)`. The payoff was real geometry:
`verticalIntersection`, `axisUnits` and `topAltitudeM` let a drill hole intersect an
ellipsoid and a magnetic anomaly fall off with true distance.

**The alternate branch** generated a deposit as a **quantized class-table record**: thirteen
rows over seven kinds, each with a percentile tonnage ladder `[min, T10, T50, T90, max]`,
log-uniform grade bands, a `hosted: basement | sediment` flag, a named published `source`,
and an industry screen (`grade` / `sum` / `seam`). Every number is an integer bucket
(contract S1) drawn from a salted hash of `(seed, class, anchorKey)` where `anchorKey` is
the column's position in its **plate's body frame** (contract S2), so a plate carrying a
prospect across the map does not re-roll it.

The alternate branch is the better trunk, for four reasons that are checkable rather than
matters of taste:

1. **Coverage.** 7 kinds and 13 classes against 3 families. It has iron (both Superior-type
   BIF and Algoma), diamond, uranium, coal, potash and placer; this branch had none of them.
2. **The anchor is the right one.** A cube-sphere tile is fixed to the *planet*; a deposit
   belongs to a *plate*. Their body-frame anchor survives plate motion by construction.
   This branch's own snapshot checksum had to be carried alongside to catch the same thing.
3. **The class table is calibrated against sources, per row**, and the numbers were revised
   where measurement contradicted them — `0.6.1-review.md` §2 records five such revisions
   (host-dependent burial depth, a per-kind `FIELD_SCALE` because `oPla` tops out at 0.144
   and the placer half was otherwise dead code, two iron settings, two ladder corrections,
   an exclusive arc variant split). This branch had no equivalent measurement step.
4. **More was built on it.** The core logs and the regional campaign both read the finished
   record; neither would have been free against an ellipsoid model.

## 2. What this branch had that the alternate did not

Four things, all of which survived the merge:

1. **A monetary scenario.** The alternate branch's `viable` is a *geological* screen — grade
   against the class cutoff, size against the row floor, depth against `maxTop`. It never
   mentions a price. `js/data/deposit-economics.js` is the second question, and it is kept
   as a separate object so neither screen can hide behind the other. **Ported**, re-targeted
   at the 0.6.1 record (see §3).
2. **Reflection seismic.** The alternate branch has seven instruments and none of them
   images structure at crustal scale. **Ported** into `Instruments.LIST` as an eighth (see §4).
3. **`0.7-proposed.md`** — the roadmap that reserves 0.6.x for deposits and moves live
   resolution to 0.7.0. The alternate branch's `AGENTS.md` document index still cited it,
   but the file was absent there: a dangling reference. **Restored.**
4. **`data/deposits/SOURCES.md`** — the priors provenance. **Restored and rewritten** to
   describe the shipped thirteen-row class table rather than the three deleted families.

## 3. The monetary scenario, ported and re-calibrated

Porting was not a copy. The original screened an ellipsoid body (`oreTonnes`,
`burialTopM`, `waterDepthM`); the 0.6.1 record carries `sizeMt`, `contained`, `top` and
`water` instead, so the module reads those. Two things then had to be fixed, both found by
measuring rather than by reading:

**A flat cost per tonne is wrong by an order of magnitude in both directions.** The ported
version charged $44/t of ore to everything. That makes every placer and every porphyry
uneconomic whatever the grade — a gold dredge moves a tonne of gravel for a few dollars
while a selective stope costs ten times that. Cost is now **method-based**: seven methods
(`openpit`, `underground`, `dredge`, `bulk`, `beneficiation`, `inSitu`, `potash`), each with
its own mining and processing rate, depth and water escalation, capital and scale floor, and
a `methodOf` table keyed `kind/variant` exactly as the class table names it, so a new row
has to declare its own mining method rather than inherit one.

**One commodity is not counted in tonnes.** `containedOf` folds a `%` grade by 0.01 and a
`g/t` grade by 1e-6 — both land in tonnes — but a `ct/t` grade by 1, which lands in
**carats**. Diamond is the only such row, and pricing it per tonne produced a kimberlite
with a median net of **13,125 G$**. `pricePer` now names the unit each price is quoted in,
`gradeUnitTo` names what a catalogue grade unit implies, and `screen` refuses a record whose
own `gradeUnit` disagrees instead of printing a number four orders of magnitude out. The
same kimberlite now reads 0.77 G$, and `tests/instruments.js` asserts the invariant across
all thirteen rows so a new row cannot inherit a mispriced metal.

Measured on the L5 1500 Myr seed-7 world (`experiments/logs/economics-calibration-L5-1500.log`,
977 records):

```
geologically viable (grade/size/depth, no price): 584 / 977 (59.8 %)
monetary positive (priced, method-based cost)  : 338 / 977 (34.6 %)
both screens pass                              : 235
geological only (real rock, does not pay)      : 349
monetary only (pays, fails the class screen)   : 103
neither                                        : 290
```

The two screens disagree on 452 of 977 records. That disagreement is the argument for
keeping them apart: `basin/coal` passes both on every record, `placer/gold` is
geologically viable 40 times and pays 7, and `iron/bif` pays 38 times while passing the
class screen only 10 — because a bulk iron tonnage still carries its capital at a depth the
class row rejects. Both lines are printed on the found report and both counts on the
regional summary, so neither can hide behind the other.

## 4. The seismic line, ported

The original seismic had a 70 km footprint and reported a Moho, a sediment interface and an
occasional bright reflector with ±10–20 % uncertainty. Ported into the alternate branch's
instrument model as `{ id: 'seis', reach: 15000, coverMax: Infinity, footprint: 2,
detect: 0.32, tier: 'indirect' }`, with three deliberate choices:

- **The gain row is not magnetics'.** Seismic gains where a body is massive, tabular or
  layered (`vms`, `mafic`, `iron`) and where a shear-zone fabric reflects (`orogenic`), and
  it is blind to the diffuse porphyry stockwork that magnetics does pick up, and to
  unconsolidated basin fill. `tests/instruments.js` reads `Instruments.KIND_GAIN` back out
  of the module rather than restating it, and asserts the two rows differ.
- **It never assays.** Its tier is `indirect`, so on its own it reaches `inferred` or
  `indicated` and never `measured`; the report line ends `images structure, not
  composition: no assay, depths ±10-20 %`.
- **A reflector is a property of the body**, drawn from its own salted hash, so the same
  deposit is either always a bright event or never one and does not flicker between
  surveys. A little over half the time it is seismically quiet even when it is there —
  a null is not an absence.

One incidental fix: the confidence ladder used to be inferred from an instrument's position
in `LIST` (`instIndex <= 3` was indirect, `4` and `5` were a drill). Appending seismic at
the end would have silently promoted it to a drill, so the tier is now declared per
instrument and the ladder no longer depends on list order.

## 5. What was thrown away

Four files survived the merge that could no longer run, because `js/deposits.js` no longer
exports the API they were written against. Verified, not assumed: `node tests/prospector.js`
failed with `TypeError: Deposits.snapshot is not a function`, and `snapshot`, `near`,
`tileOf`, `nearestCell`, `scratchUv`, `MAX_QUERY_M`, `combine`, `HOSTS`,
`verticalHalfExtent` and `axisUnits` all returned zero matches in the merged `deposits.js`.

| deleted | why |
| --- | --- |
| `js/prospector.js` | superseded by `js/instruments.js` |
| `js/data/deposit-models.js` | superseded by the `CLASSES` table |
| `tests/prospector.js` | tested the deleted module; not in `run-all.js` |
| `experiments/deposit-stats.js` | superseded by `experiments/deposit-calibration.js` |

The ellipsoid geometry went with them, and that is a real loss rather than a clean win: the
alternate branch's bodies are depth intervals with a footprint area and a thickness, so a
drill intersection is an interval test rather than a ray through a solid, and a magnetic
anomaly has no true distance falloff. If strike and dip are ever wanted, they should be
added as quantized attributes on the existing record — not by reverting the generator.

## 6. Verification

- `node tests/run-all.js` — **PASS, 36 tests, short profile** (`browser-scripts`, `deposits`,
  `core`, `instruments`, `gui`, `adj` and the rest). The `no WebGPU adapter` line inside
  `gpu-parity-ui` is that test exercising its own abort path; it reports `ok`, and it did so
  on both branches before the merge.

  the thirteen-row price-unit invariant.
- `node tests/gui.js` — PASS, with the campaign summary's new money line.
- `node experiments/economics-calibration.js 5 1500 7` — the log committed above; catalogue
  build 38 ms at L5.
- The campaign chunk budget was re-measured, not assumed: L5 median 1.34 ms against the
  1.25 ms target, unchanged by the eighth instrument.

Not run here: the `--full` and `--release` profiles and the owner-rig GPU gates, which the
sandbox guidance reserves for the owner machine. The `tests/longrun.js` core-vs-catalogue
check is a full-profile test and so is unverified in this sandbox.

## 7. Deferred

  monetary filter would be a third pass over the same catalogue; it is cheap but it is a UI
  decision, not a merge one.
- Strike, dip and a true ellipsoid, as above.
- `iron/algoma` produced one record on the calibration world, against `0.6.1-review.md`'s
  measured 38 `bif` and 1 `algoma`. The rule is right; the planet is wet.
