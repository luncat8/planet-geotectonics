Planet Geotectonics — GPU (WebGPU) benchmark

Two time-boxed measurements per config, on your GPU. iso = the kernel graph only: submit steps frames as one batched encoder (the Phase V play path, each frame rebound at its own frameIn block offset) and await onSubmittedWorkDone — no event round trips, no drawing. smooth = the full play path (GpuSim.play, including the event and checkpoint round trips) under requestAnimationFrame, reporting the frame-gap distribution. The sim pipeline is one segment deep, so the gaps and Myr/s are the rate your GPU actually achieves, and the map shows the last completed frame at all times (a setting heavier than the refresh cannot present undrawn, black frames). Rows whose smooth median clears ~16.7 ms sustain 60 fps and are highlighted. The top-kernel GPU ms table (timestamp queries) prints under the table when the adapter supports it. iso ms/step is one batched encoder of steps frames divided by steps (one submit and one onSubmittedWorkDone per sample); the 1-vs-5 gap is the per-submit cost batching removes, and steps=1 is the one-frame-encoder baseline. smooth med/p95/max are rAF frame gaps in ms; a hitch is a gap over 2× the median, shown as hitches/frames sampled. Compare the fraction, not the count: a faster median lowers the 2× threshold, so a smoother run can show a higher count than the slower run it replaced. Myr/s = simulated time per wall second. Sampling is time-boxed (~1.2 s per iso config, ~5 s per smooth config, capped sample counts) so a heavy level returns in bounded time. Values outside the accepted ranges (levels 4–7, steps 1–20) are named in the status line and in a BENCH ignored: line instead of being dropped silently — a config the page did not run must not look like one it did. ?fast=1 shrinks the boxes for a quick pass on slow renderers; ?noauto=1 suppresses the auto-run; ?level=6&steps=8&dt=0.1 pre-fills the inputs (used by experiments/gpu-bench.js via PGT_QUERY).
