# 0.5.7 — deferred 3D globe and terrain quality review

## Purpose

Review the displayed shape and terrain quality of the 3D planet without changing simulation
state, Earth data, or the sampled elevation field. The work is deliberately diagnostic first:
mesh density is not a substitute for input detail, so do not raise the default tessellation or
change the height-field algorithm until the source of the visible artifacts is isolated.

The two visual concerns are separate:

1. The canvas must display the same aspect ratio used by the camera projection and picking.
2. High mesh-detail settings should not expose distracting facets or texture-like noise without
   providing a meaningful improvement in the planet's shape.

The first is a layout invariant. The second requires an owner-GPU visual comparison before an
algorithm or default is chosen.

## Current renderer contract

The render path is in `js/render3d.js` and is controlled from `js/ui.js` / `index.html`.

- `map3d` has a 2048 × 1024 backing size. Its camera matrix uses the backing width / height
  ratio, and `Render3D.pick` uses that same projection for pointer rays. The displayed canvas
  and map stage must therefore remain 2:1; CSS may scale the canvas but must not clamp only its
  height or stretch its width.
- The mesh selector offers an icosphere (`k6`–`k9`) and an equirectangular lattice. The detail
  value is geometric subdivision, not a terrain-frequency or source-data-quality setting.
  Icosphere k8 has about 655k vertices; k9 has about 2.6M. The lattice has its own 512 × 256
  through 2048 × 1024 choices.
- The 3D surface reads the simulation's cell elevations through a 2048 × 1024 `R32Float`
  height texture. `hex` gathers nearest-cell samples; `vertex` uses the cached barycentric
  height-field records to interpolate between cell centres. `vertex` is the normal page default.
  The renderer manually bilinearly samples that texture and displaces mesh vertices radially.
- `deriv` normals are screen-space derivatives of the rendered triangles; this gives flat
  per-triangle geometric normals. `analytic` normals use central differences from the height
  texture and are interpolated across the mesh. Both render the same height values and neither
  changes the simulation.
- The default displacement is 10×. It scales the visual relief only. Keep any visual adjustment
  on the renderer side; do not clamp, smooth, or rewrite simulation elevations as a visual fix.
- `experiments/logs/2026-10-12-3d-height.webp` is a visual repro artifact. It shows an
  obviously faceted / irregular surface at the selected icosphere k8 and `deriv` normals. It is
  not sufficient by itself to determine whether the dominant cause is shading, height sampling,
  relief scale, the projection, or the displayed canvas size.

## Investigation sequence

### 1. Reproduce a controlled baseline

Record the browser and GPU, viewport size, device-pixel ratio, CSS canvas rectangle, backing
canvas size, start / seed / resolution / simulation time, `disp`, height mode, normal mode, mesh
mode and detail, and camera yaw / pitch / distance. Use the same world and camera for every
comparison; do not compare unrelated starts or rely on a moving simulation.

Capture the visible 2D elevation map and 3D view side by side at the same moment. Include the
current repro image and a clean, constant-height reference. Keep raw captures in
`experiments/logs/` only when they are useful to reproduce a result.

### 2. Separate projection from surface quality

Verify the canvas rectangle stays 2:1 at a wide desktop, a short landscape viewport, and a
narrow viewport. A constant-radius sphere must remain circular in the displayed view while
orbiting; its horizontal and vertical radii should differ by less than 1% after pixel rounding.
Check that marker / pointer coordinates and `Render3D.pick` still agree with the rendered view.

Use a constant-height sphere as the projection control. If it appears elliptical, fix the canvas
sizing or projection before interpreting any terrain comparison. Do not use a displaced,
rotated globe as the aspect-ratio test: real relief changes its silhouette.

### 3. Isolate mesh, field and normal effects

Use a deterministic render fixture, separate from the live simulation, with these height fields:

- constant zero, to pin the round-sphere baseline;
- a low-frequency smooth mound, to test curved displacement and smooth lighting;
- a single sharp step, to show what the chosen interpolation actually promises;
- one captured simulation height field, to compare against the 2D elevation map.

For each field, keep the camera, displacement and canvas size fixed and compare:

- `deriv` versus `analytic` normals;
- `hex` versus `vertex` height sampling where applicable;
- icosphere versus lattice mesh;
- the lowest, default and highest offered details.

Interpret the comparisons rather than assuming that more vertices are better:

- Facets that change mainly with the normal mode are a shading-normal issue.
- Features that follow cell boundaries or persist in both meshes are in the source field or its
  sampling, not a lack of tessellation.
- Artifacts that follow mesh orientation, the antimeridian or the poles point to direction-to-UV
  mapping or sampling seams.
- Changes caused only by displacement scale point to relief exaggeration or unusually large
  source elevations; inspect the elevation range before selecting a visual scale.
- A higher detail setting that only subdivides already smooth areas is extra geometry, not new
  terrain detail. Measure whether it changes the silhouette or pixel coverage at normal viewing
  sizes before keeping the cost.

### 4. Choose one targeted change

After the cause is established, make the smallest renderer-only change that addresses it. Candidate
approaches, conditional on the comparisons above:

- If triangle lighting dominates, evaluate `analytic` as the default or improve the normal
  estimate while preserving the displaced silhouette.
- If cell-scale transitions dominate, review height-field filtering / level of detail against
  the actual texel footprint. Any smoothing must be display-only, measurable against the 2D map,
  and must not silently alter simulation data.
- If displacement dominates, calibrate the display scale on captured height distributions and
  document what the slider means; do not hide pathological elevations by clipping the data.
- If detail controls have no useful visual range, relabel them explicitly as tessellation and
  remove or retune levels only after measuring edge coverage, build time, GPU memory and frame
  cost. Do not promise that k9 adds geological detail.
- If the icosphere is intrinsically the wrong sampling domain for the chosen height texture,
  compare the lattice as the reference and decide whether the icosphere remains a supported
  option. Preserve seam and pole correctness for either mode.

Do not combine a new filter, a new normal model, a displacement retune and a new mesh default in
one change. Each needs a separate before / after capture so its visual effect and performance
cost are attributable.

## Acceptance gates

- Canvas and projection remain 2:1 at every supported layout size; a constant-height sphere is
  round within 1%, and picking remains aligned with the displayed image.
- The smooth-mound fixture has no conspicuous faceting at the shipped detail and normal defaults
  at ordinary page scale. The sharp-step fixture remains understandable and does not grow
  uncontrolled spikes or holes.
- The captured simulation view remains consistent with the 2D height field. Any display filter
  has a documented error bound and leaves `state.z` and saved worlds untouched.
- Raising mesh detail has a demonstrated geometric benefit at the target display size, or the
  UI labels / available settings make clear that the control is tessellation rather than added
  terrain information. High detail must not be retained just because it has a larger vertex
  count.
- Preserve the existing renderer guarantees: no per-frame allocation; CPU and GPU paths use the
  same displayed heights; the height gather remains within the existing 0.5 ms gate and 3D draws
  within the 5 ms gate on the owner rig at 2048 × 1024; release and detail-change ownership stays
  covered by `tests/render3d.js`.
- Run the short suite with `node tests/run-all.js`. Run `run-smoke.bat` / `run-smoke.command` on
  an owner GPU for screenshots, shader execution and timing; sandbox SwiftShader numbers are not
  a substitute for those measurements.

## Scope boundary

This work does not recalibrate long-run geology, change topography production, change height-field
records, or alter Earth packs. The supplied full-profile log has a separate `tests/longrun.js`
continental-area assertion failure; treat it as a simulation calibration gate, not as evidence
for or against 3D rendering quality. Keep that investigation independent so a visual fix cannot
mask a simulation regression.
