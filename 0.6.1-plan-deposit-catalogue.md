# 0.6.1 — The deposit catalogue and its economics

The second increment of the deposit prospector (`0.6.x-plan-deposit-prospector.md`). 0.6.0 gave the
instruments a local, on-demand candidate interface; this file gives each found record its numbers:
size, grade, geometry, depth and contained metal, drawn from a flat class table whose bands come
from published Earth grade–tonnage models, plus the viability screen that turns "a deposit" into
"a commercially viable deposit".

A clicked-cell survey enriches only candidates in the instrument footprint. The full catalogue is
built only after an explicit regional-map/campaign or export action; that all-cell build is never a
hidden prerequisite for a local click. `Deposits.json` supersedes the old `Extract.json` dump
(`Extract.deposits` and `Extract.json` are deleted in the same commit — the primitives
`blur`/`peaks`/`host` stay).

## 1. The catalogue contract

`Deposits.at(state, kind, cell)` lazily returns the record for one deposit kind at one cell; it
checks that cell's local peak neighborhood and does not call the world builder. This is the local
primitive used by the survey inside each instrument footprint. `Deposits.build(state, opts)` is a
separate, explicit O(V) operation for the regional view or a full export and returns a cached,
read-only catalogue. A record has the same format in either path:

```js
{
  id:        '3f2a91c4',        // base-16 of hash(seed, kindIndex, anchorKey) — stable per S2/S3
  kind:      'arc',             // 'vms'|'mafic'|'arc'|'orogenic'|'basin'|'placer'|'iron'
  variant:   'porphyry',        // the row of the class table that was drawn
  commodity: 'Cu-Mo-Au',        // principal first; byproducts reported, not screened
  cell:      4812,              // the cell the record's column owns now
  plate:     3, anchorKey: [10412, -3211, 8760],   // quantized body direction, the identity
  lat: 0.752, lon: -2.883,      // record's current position (radians, as the probe prints them)
  potential: 0.4196,            // quantized blurred value that produced the record (q/255)
  host:      'thick continental',
  ageMyr:    312,               // column age at extraction
  epochMyr:  1500,            // state.t when built — the snapshot stamp (S6)
  cover:     150,               // metres of sediment above the shallowest body
  surfaceZ:  480,               // cell elevation, m (− = below display sea level)
  water:     0,                 // metres of water column over the seabed, 0 on land
  top:       850, bottom: 1450, // metres below the surface, shallowest top → deepest bottom
  bodies:    [ { top, bottom, footprintKm2, thicknessM, share, aspect } … ],
  unit:      'Mt',              // the ladder's unit: 'Mt' of ore, or 't U3O8'
  size:      50,                // in `unit`
  sizeMt:    50,                // ore tonnage in Mt (= size unless the ladder counts metal)
  sizeClass: 'small',           // <T10 small, <T50 medium, <T90 large, ≥T90 giant
  grade:     { Cu: 0.22, Mo: 0.01, Au: 0.027, Ag: 2.2 },   // principal + byproducts, 2 s.f.
  gradeUnit: { Cu: '%', Mo: '%', Au: 'g/t', Ag: 'g/t' },   // so a panel needs no class lookup
  contained: { Cu: 110000, Mo: 5000, Au: 1.35, Ag: 110 },  // tonnes of metal in the ground
  viable:    false,
  reason:    'grade'            // 'ok' | 'grade' | 'size' | 'depth' when not viable
}
```

`opts = { min: 'viable' }` returns the screened list instead of the catalogue object; the two
catalogue levels of the umbrella §4 are the threshold itself and this filter. A record also
carries `kindIndex`, `owner` and the unit-length `direction` the 0.6.0 ledger re-associates by;
those are internal and `Deposits.json` drops them. A local report calls `Deposits.at(state, kind, cell)` only for
cells/kinds in its selected instrument footprint and enriches only those records. The explicit
regional path calls `Deposits.build`, then `Deposits.viable(state)` returns that store filtered by
the screen; neither regional summary nor world-wide build runs merely because a user clicks a cell.

**Body shape is one aspect ratio, `k = thickness / √area`,** drawn per body from the row's band —
there is deliberately no independent footprint band, because a second band could contradict the
tonnage ladder. The tonnage fixes the volume (`V = share · sizeMt / ρ`), the aspect fixes the
shape, and both dimensions follow: `area = (V/k)^⅔`, `thickness = k·√area`. A 50 Mt porphyry body
at `k = 0.3` is ~400 × 400 × 120 m; an 800 Mt one at `k = 0.5` is ~850 m across and 425 m thick; a
coal measure lands as a low sheet and an iron body as a regional blanket, because that is what
their `k` bands say. The consistency test (§8.4) checks the arithmetic and that a body's interval
fits inside its host crust.

Sources, in the order they appear: USGS OFR 2007-1214 §5 table 5.1-1 (porphyry medians, from Cox
1986 and Singer et al. 2005); USGS OFR 95-0831 model 17 (tonnage percentiles 1,100/140/19 Mt;
Au–tonnage correlation r = −0.49); the 904-deposit VMS compilation (average 17 Mt @ 1.7 % Cu,
3.1 % Zn, 0.7 % Pb; median ≈ 2 Mt) and the Manitoba VMS short-course tables for the subtype
spreads; USGS SIR 2010-5070-i (Ni-Cu-PGE grades); USGS OFR 94-250 (Archean Au-quartz veins
1.0 Mt @ 8.8 g/t; Homestake 3.4 Mt @ 8.0 g/t); USGS OFR 2014-1074 (sediment-hosted Au 5.7 Mt @
2.9 g/t; Carlin 7.1 Mt @ 2.0 g/t); IAEA classification via the uranium-ore literature and the
New Mexico Grants-district figures (0.20 % U₃O₈ primary ores, roll fronts ≈ 9,500 t U₃O₈, up to
50,000 t); USGS 2014 potash overview (basins from 10⁷ to > 10¹¹ t K₂O; typical grades 11–25 %) and
the Russell deposit (392 Mt @ 22.5 % K₂O); USGS Bulletin 1693 model 39b for placer Au-PGE (g/m³, converted at
2.0 t/m³); Hamersley/BIF literature for iron (unenriched 20–40 % Fe, high-grade 56–68 %, deposits
to 10⁹ t). The `coal` row is the only one with no grade–tonnage model behind it and says so.

Four deliberate scalings, stated so nobody mistakes them for the sources' numbers:

1. **A record is a cluster.** The ladder's top end sits above the single-deposit percentile because
   a cell is a district-sized footprint: `bodies` 1–8, and the top-decile body is compared to the
   published median/large deposit, not the cluster. §8.4 checks that a record's tonnage equals the
   volume sum of its bodies, and §8.5 reports the measured per-body tonnage of every class next to
   its published anchor (`anchorMedian` in the row).
2. **Depth is emplacement + burial, and burial depends on the host.** The emplacement top is a
   class band (a porphyry is not born at the surface, a placer is) drawn per record. A
   `basement`-hosted body is then buried by the whole sediment pile, `min(hSed, 4000 m)`; a
   `sediment`-hosted one — placer, coal, potash, roll-front uranium, Carlin-style Au,
   Superior-type BIF — *is* that pile, so nothing is added on top of it. The first draft added the
   pile to every row and measured 0 of 17 viable `sedhost` records and 1 of 38 uranium: every
   sediment-hosted class had been buried below its own mining depth. The sim carries no denudation
   history, so records are *not* removed by erosion — see §7.
3. **The six potentials do not share a scale.** `oPla` is a transported load, not a saturating
   accumulator: on the calibration history its blurred field tops out at 0.144, so on the common
   `depositMin` it produced no record at all. Each kind therefore carries a measured `FIELD_SCALE`
   that maps its own field onto the shared 0..1 deposit scale before quantization, so one threshold
   still means one thing. It is `1` for every kind except `placer` (`7`), and the measured maxima
   are in §10.
4. **Iron has two settings, not one.** Design §8 derives iron both from exposed mafic crust and
   from `oBas` in old basins. Only the second is common on a water-covered planet (the calibration
   history has one exposed-mafic cell and 184 old thick basins), and it is also the Superior-type
   BIF that supplies most of Earth's iron — so the class has an `algoma` row on the exposure rule
   and a `bif` row on the basin rule, and the `bif` row is sediment-hosted because the formation
   *is* the basin fill.

## 3. From potential to record

All of this runs once per build, on demand, never in the frame loop.

1. **Field.** `Extract.blur` (unchanged) writes each class's one-cell-blurred potential into a
   reused `Float64Array(grid.V)`; six of them live in the cache. `Extract.peaks` with
   `depositMin` and the local-maximum rule gives the candidate cells; ties resolve by index, so a
   plateau is stable.
2. **Quantize.** `q = floor(255 · p)`; the record's `potential` is `q/255`. Everything downstream
   reads `q`, never `p`, so S1 holds by construction.
3. **Endowment band.** `q` selects the ladder segment: `q < 77` (0.30) no record; `< 115` (0.45)
   `[min, T10]`; `< 179` (0.70) `[T10, T50]`; `< 230` (0.90) `[T50, T90]`; else `[T90, max]`.
4. **Size.** `w = hash(seed, kind, anchorKey, 'size') / 255`; `T = 10^(log10(lo) + w·(log10(hi) −
   log10(lo)))`, snapped to the nearest 1 / 2 / 5 × 10ⁿ step (the S1 tonnage ladder) and clamped to
   the row's `max`. `sizeClass` follows which percentile the snapped `T` falls into.
5. **Grade.** `v = hash(…, 'grade') / 255`, blended toward the low side for big records:
   `u = 0.75·v + 0.25·(1 − w)`, then log-uniform inside the grade band and snapped to two
   significant figures through a 256-entry log table. The blend reproduces the published negative
   grade–tonnage correlation (r ≈ −0.35…−0.49) without a distribution object.
6. **Bodies.** `n = 1 + floor(hash(…, 'bodies') / 255 · (1 + 7·q/255))`, capped by the row;
   shares are a broken stick from the same hash (sorted descending, `share_i ∝ (n − i + 1)` with a
   hash jitter), so `Σ share = 1` exactly in integer units (share in 1/1024ths) and the volume
   bookkeeping is exact. Each body draws an aspect `k` from its row band and takes the shape that
   volume implies (`area = (V/k)^⅔`, `thickness = k·√area`, §2); the shallowest body defines
   `top`, the deepest `bottom`; body tops stack downward from the emplacement top with gaps from
   the hash.
7. **Burial and water.** `sediment = min(round(hSed/50)·50, 4000)`. A `basement`-hosted row adds
   it (`top += sediment`) and reports it as `cover`; a `sediment`-hosted row is inside the pile, so
   it adds nothing and reports `cover = min(top, sediment)`. The stack is then shifted up if it
   would otherwise hang below `hSed + hFel + hMaf`, so a record always sits inside its own crust.
   On a wet cell `water = round((Params.sea − z)/10)·10` and the depths are measured from the
   seafloor.
8. **Identity.** `anchorKey = [round(bx·32768), round(by·32768), round(bz·32768)]` from the
   owning column's `body`; `id` is the integer mix of `(seed, kindIndex, anchorKey)` printed
   base-16. No frame, no cell, no time in it (S2/S3).
9. **Variants.** Contexts are *exclusive* wherever the geology is exclusive, so one cell always
   names one commodity and the choice is testable: `mafic` diamond needs `hFel > hOro` and
   `age > 300 Myr` (a craton), otherwise `sulfide`; `arc` epithermal needs `hFel < hOceanic` (an
   island arc), otherwise `porphyry`; `orogenic` sedhost needs `hSed ≥ 500 m`, otherwise `vein`;
   `iron` bif needs the old-basin rule, otherwise `algoma`. Only the three `basin` rows genuinely
   overlap and are picked by hash among those the cell qualifies for: potash needs `wet` and
   `|lat| < 40°` (evaporite), coal needs `z > −200 m`, uranium needs continental crust with
   `hSed ≥ 300 m`. A kind with no qualifying variant is not emitted — the same geology then yields
   a different commodity, which is the point. (The arc split was `hFel < hOro` in the first draft;
   at 45 km that makes epithermal the common case on *every* arc and leaves the two variants
   overlapping. `hOceanic` is the island-arc / continental-arc line and is exclusive.)
10. **Derived iron.** `iron` has no potential to peak. Its field is derived per cell from design
    §8's two settings: where the exposure rule holds (`hFel < 2 km`, `z > 0`) it takes
    `max(blur(oMaf), blur(oVms))` and the row is `algoma`; where the old-basin rule holds
    (`hSed ≥ 2 km`, `age > 500 Myr`) it takes `blur(oBas)` and the row is `bif`. The derived field
    is a field like any other, so its local maxima are found by the same `Extract.peaks` pass —
    `Deposits.build` runs over seven fields, the six potentials plus `iron`, and the build reads
    the parent blurs it has already computed rather than re-blurring them.

### 3.1 Worked example

A cell on thick continental crust (`hSed` 120 m) whose blurred `oArc` reads 0.42, and whose owning
column's `body` hashes to the anchor of §1:

| step | arithmetic | result |
|---|---|---|
| quantize | `q = floor(255 · 0.42)` | `q = 107`, `potential = 107/255` |
| band | `77 ≤ 107 < 115` → `[min, T10]` of the porphyry ladder | 20–60 Mt |
| size | `w = 0.47`; `T = 10^(log10 20 + w · (log10 60 − log10 20))` → 1-2-5 snap | **50 Mt**, `sizeClass small` |
| grade | `u = 0.75·v + 0.25·(1 − w)` per metal → Cu 0.22 %, Mo 0.010 %, Au 0.027 g/t, Ag 2.2 g/t | **Cu 0.22 %** |
| bodies | `n = 3`, shares 486/355/183 (‰ of 1024) | bodies 1–3 |
| shape | body 1: `V = 0.475 · 50 Mt / 2.6 = 9.1 Mm³`, `k = 0.291` → `area = (V/k)^⅔ = 0.0995 km²`, `t = 92 m` | ~315 × 315 × 92 m |
| depth | emplacement top 700 m (hash) + 150 m of cover (basement host); bodies hash-spaced downward | **top 850 m**, bottom 1,450 m |
| contained | `50 Mt × 0.22 % = 110,000 t` Cu; `× 0.010 % = 5,000 t` Mo; `× 0.027 g/t = 1.35 t` Au | Cu 0.11 Mt |
| viability | 0.22 % < 0.25 % ✗ | **sub-economic**, `grade` |

A stronger anomaly on the same column (`q = 229`) lands in `[T90, max]` and comes out a 500 Mt
`large` porphyry with five bodies — and with *the same* 0.22 % Cu, because grade rides the anchor
and only the ladder segment rides `q`. The screen still rejects it on grade. That is the intended
reading of §4: a bigger anomaly is a bigger deposit, not a better one.

Every number in the panel's found-deposit line and in `Deposits.json` is one of these cells, and
the map's totals are their sum.

## 4. Viability

`viable` is the industry's first-pass screen, and the reason string says which leg failed:

```
gradeOk = principal grade ≥ row.cutOff        (composite cut-offs are stated in the row)
sizeOk  = T ≥ row.minSize
depthOk = top ≤ row.maxTop
viable  = gradeOk ∧ sizeOk ∧ depthOk          reason = first failing leg, else 'ok'
```

Only the principal commodity is screened; byproducts are reported in `grade`/`contained` and never
valued — the moment a price appears the plan has an economy, and this increment deliberately does
not have one. `sizeClass` is not a viability statement: a giant
low-grade porphyry can be sub-economic on grade and a small high-grade vein can be viable.

## 5. The catalogue object, cache and budget

```
Catalogue {
  epochMyr, threshold, level, classes: Deposits.CLASSES,
  records:      [ record … ]           // sorted by cell, then kindIndex
  cellStart:    Int32Array(V + 1)      // prefix index into records, so a cell is a slice
  byKind:       [ [ recordIndex … ] ]  // 7 rank lists, top 64 by contained principal metal
  viableCount, containedTotals: { Cu: t, Au: t, U3O8: t, K2O: t, … }
  signature:    state.frame
}
```

- **Cache**: two paths with different scopes. The local `at(state, kind, cell)` accessor evaluates
  only that cell/kind's blurred value and peak; any reuse is bounded to the current survey and its
  footprint. A click never builds or traverses the whole catalogue. The full `Float64Array(7·V)`
  blur store, peak lists and catalogue are built and cached only after an explicit regional-map,
  campaign or full-export action, and the cache is keyed on `(state, state.frame, V)` so a paused
  world answers a second request for free. That snapshot shows its `epochMyr` and `Deposits.stale`
  when `state.t − epoch > 5 Myr` (S6); it does not replace the live local click report.
  `Deposits.release()` drops both store and cache when the page rebuilds the world at a new level.
- **Budget**: the explicit full build is `O(V)` — six blurs, one derived iron pass that reads
  them, seven peak scans, then O(records) construction. Target ≤ 25 ms at L5 and ≤ 200 ms at L7;
  **measured 21 / 31 / 74 ms at L5 / L6 / L7** (§10). It runs only on a user-requested
  regional/export action, never inside `frame()` or the local click path. At L7 the blur store is
  7 × 163,842 × 8 B ≈ 9.2 MB, allocated once per level (the same policy the old `extractScratch`
  had). The click path remains footprint-bounded: candidate work scales with the chosen
  instrument's local sample set, not the planet's cell count.
- **Allocation**: local records are created only for the clicked footprint; the catalogue's record
  objects and index arrays are allocated on the explicit regional/export path. No object is
  created per frame — nothing here is reachable from `frame()` at all.

## 6. Exports

`Deposits.json(state)` — `pgt-deposits` **version 2**:

```
{ format, version: 2, level, seed, t, epoch, thresholds: { traceMin, depositMin },
  classes: [ { kind, variant, unit, cutOff, minSize, maxTop, source } … ],
  totals: { records, viable, contained: { Cu, Zn, Pb, Au, Ag, Ni, PGE, U3O8, K2O, Fe } },
  deposits: [ record … ] }
```

`Deposits.summary(state)` returns the map's data: per-kind record and viable counts, the ten
largest viable records per kind by contained metal, the contained totals above, and the `stale`
flag of S6. The UI's
`Build viable map` button (0.6.2) is a thin wrapper over it. `tests/ores.js`'s format assertions
move from v1 to v2 in the same commit that deletes `Extract.json`; `tests/browser-scripts.js`
follows.

## 7. Known simplifications, and the alternatives considered

1. **No denudation.** The sim has no per-column erosion history, so a record never disappears
   because the rock above it was stripped — a porphyry born at 2 km depth sits at 2 km + cover for
   the life of its plate. The honest hook is a future increment: a `denudation` column field
   integrated from the existing erosion flux, which would then also feed placer liberation (the
   sim already moves `p` downhill), and would delete shallow records whose emplacement band is
   below the local erosion level. Recorded here, not faked.
2. **Depth is a band, not a history.** Emplacement depth is hashed from the row; a real system's
   depth depends on the orogen's exhumation. The band is what a first-pass screen needs and it is
   stable (S1); the simplification is visible in the JSON as the `bodies[].top`.
3. **A cluster, not an orebody.** §2's scaling note: the ladder's top end and the body count are
   game quantities calibrated *against* the published percentiles. Any later increment that wants
   body-level fidelity (mine planning, grades by bench) inherits `bodies[]` as the starting point.
4. **Rejected: a per-cell "world-class or nothing" filter.** The map would be empty; the thresholds
   of umbrella §4 already do the noise control, and viability does the rest.
5. **Rejected: prices.** A net-smelter-return model would be more "realistic" and immediately
   become an economy, which the owner scoped out. Cut-off grades are the industry's own
   pre-price screen and they are stable, citable constants.
6. **Rejected: oil and gas.** Basin `oBas` could carry hydrocarbon volumes, but at 223 km cells a
   play-level in-place volume is a basin-model output, not a deposit record; the class row would be
   theatre. Left as a hook with coal and potash carrying the basin economy.

`tests/deposits.js` (short profile; extends the 0.6.0 file with the economics). The long-history
measurement is deliberately *not* in it: `experiments/deposit-calibration.js` owns that, so the
short profile stays a one-second file and the distribution table stays a measurement rather than
an assertion with a hand-picked tolerance.

1. **Quantization and stability (S1/S2)** — perturbing a column's potential by 1e-6, or moving
   `t`/`frame`, leaves the whole record (id, size, grade, bodies, depth) byte-identical except
   `epochMyr`; a step of one 1/255 bucket changes the potential but not the identity or the row.
2. **Identity (S3)** — moving a column's cell and world position without touching its `body`
   leaves `anchorKey`, `id`, `size`, `grade` and `top` unchanged and only `cell/lat/lon` moving.
3. **Determinism** — two builds from the same state are byte-identical JSON, including array
   order; the per-cell buckets agree with the flat array; `Deposits.viable` agrees with the
   catalogue's own count.
4. **The class table itself** — every row's ladder is a monotone percentile ladder, every band is
   positive and ordered, every row names a host and a source, and every row has either a grade
   band or a bulk commodity.
5. **Internal consistency**, over a synthetic world that reaches all thirteen rows in one second:
   `Σ body volumes × ρ == sizeMt` within 5 %; every body's `thickness == k·√area` and `k` inside
   its row's aspect band; shares sum to one; `top ≤ every body top`, `bottom` is the deepest body
   and sits above `hSed + hFel + hMaf`; grades inside the row band; `contained == tonnage × grade`
   to three significant figures; `sizeClass` matches the percentile the size falls in; `reason` is
   the first failing leg of §4 and agrees with `viable`.
6. **Variants** — a cratonic column yields `diamond`, a young mafic host `sulfide`; a thin-crust
   island arc yields `epithermal`, a continental arc `porphyry`; a covered belt yields `sedhost`,
   a bare one `vein`; a drowned low-latitude basin can evaporate to `potash` and never yields a
   coal measure, and a dry basin is never an evaporite.
7. **Iron** — exposed mafic crust yields `algoma`; a submerged one yields nothing; an old thick
   basin yields `bif` and does so *inside* the pile (`top < 500 m`); a young basin and thick
   felsic crust yield nothing; the derived field equals its parent's blurred value.
8. **Viability** — the synthetic world rejects on every leg (`grade`, `size`, `depth`) and
   accepts on none of them wrongly: a `size` rejection really is below `minSize` or `minContained`,
   a `depth` rejection really is below `maxTop` *and* passed grade first, and every viable record
   clears all three.
9. **Local stays local** — with `Extract.peaks` replaced by a counting spy, a `Deposits.at` query
   and a full seven-instrument survey perform **zero** world scans; the explicit `Deposits.build`
   performs exactly one per kind.
10. **The checkpoint is untouched** — `Checkpoint.save` is byte-identical across a full build and
    a survey.
11. **The build budget** — a timed L5 build, asserted under the development ceiling and printed
    in the PASS line.

`tests/ores.js` (history profile) keeps the field primitives (`blur`/`peaks`/`host`) under test
and asserts the catalogue above them: every record is in range and tagged, each kind's rank list
is ordered by contained metal, and the v2 dump is deterministic and carries the class table.
`tests/instruments.js` asserts the found line prints the depth interval, variant, commodity,
tonnage, size class, grade, body count and viability verdict, with no placeholder left.
`tests/browser-scripts.js` loads the catalogue through the classic-script path and checks the v2
tag, the class table and the totals.

## 9. Order and acceptance

Order: `Deposits.CLASSES` + quantization + size/grade (records become numeric) → bodies and depth →
viability → JSON v2 + delete `Extract.deposits`/`Extract.json` → tests. 0.6.2's core and map
build on the finished record and do not change it.

Acceptance:

1. **The records are Earth-plausible.** Every row of the class table is reachable and emits on the
   calibration history, the three grade targets of §10 are met, and the number of viable records
   at 1500 Myr L5 is ≥ 20 and ≤ 1,000 (a planet, not a mine). **Met: 977 records, 584 viable.**
2. **Nothing above the row's own bounds.** No record exceeds the class `max`; no grade outside the
   band; every depth inside the row's emplacement band plus its burial, and inside the crust.
3. **Stability.** The S1/S2/S3 tests pass; `Extract` v1 is gone with no caller left
   (`grep -R -e 'Extract.deposits' -e 'Extract.json' js tests` is empty) and the short profile is green.
4. **Local stays local**: the ordinary click path never calls the O(V) builder; the §8.9 spy
   proves a single-cell survey performs no world scan. Only an explicit regional-map / campaign /
   export action may start the full build.
5. **The build budget holds**: measured L5 and L7 full-build times recorded in §10, both inside
   the targets of §5.
6. **The checkpoint is untouched**: before/after a full build and survey, `Checkpoint.save` is
   byte-identical.

**How to read the anchor columns.** Where the sim's field saturates — `vms`, `arc` — the median
record's per-body tonnage lands on the published median (1.55 vs 2 Mt; 147 vs 220 Mt) and the top
decile lands on the published large deposit. Where the field tops out near 0.7 — `orogenic`,
`basin` — most records fall in the ladder's lowest segment, so the *median* body sits below the
published median and the *p90* body is the one that reaches it (sedhost 5.5 vs 7.1 Mt, potash 200
vs 392 Mt). `basin/uranium` is the one class still 5× short at p90: its field would need a scale
of its own, which is deliberately not applied here because the record count is already where
acceptance 1 wants it. This is a measurement, not a target that was met by moving the target —
the honest reading is that a median anomaly in this sim is a marginal prospect, which is what a
median anomaly should be.
