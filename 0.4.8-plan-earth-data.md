# 0.4.8 — present-day Earth data improvement

Implementation plan for `0.4.8-draft.md`. This is a data-quality increment, not a
claim of globally measured ore concentrations. It can proceed independently of 3D.

## 1. Existing tools and limits

- `data/earth/calibration_points.json`: 35 reference points with relief, crust age,
  sediment and crustal-thickness values. Dataset names in metadata are not per-value
  extraction evidence. Audit provenance before treating these as measurements.
- `tools/earth/bake_earth.py`: calibration-point interpolation, K9 thickness inversion,
  datum adjustment, packing and a separate PaleoDEM path. Merely adding points does
  not necessarily improve the selected modern pack: wire the same sediment correction
  into every intended bake path explicitly, without replacing its relief/plate model.
- `js/earth.js`: pack decode/sample/apply; sediment is packed in 100 m increments.
  `kind` encodes crust/fertility/prior information, not elemental assays.
- `data/earth/SOURCES.md`: source candidates and bake provenance. Verify actual input
  files, versions, licences and checksums; documentation is not an implemented loader.
- `fert` and the six `o*` fields are dimensionless model quantities. Neither is a
  concentration, grade, tonnage or discovery record.

## 2. Scope and data contract

First improve **sediment thickness** in modern Earth starts. Preserve the current
relief source, plate ownership, ocean age and paleogeographic vintage unless a separate
comparison justifies changing them. Do not propagate modern corrections into paleo packs.

Store compact extracted observations in a new `data/earth/observations.json`:
`id`, latitude/longitude in degrees, `field`, value, unit, uncertainty, footprint,
crust/province classification, source ID, dataset version, extraction method and
source coordinate/record. The source registry carries licence, citation, retrieval date,
raw-file SHA-256 and extraction command. Distinguish observed, interpreted and prior.
Unknown is null with a reason, never zero. Reject duplicate IDs, invalid coordinates,
negative thickness, incompatible units and absent provenance.

Keep sediment, total crust thickness, bedrock elevation and ore assays separate.
Record a depth datum for each thickness/assay. Modern model estimates are not direct
borehole measurements. Do not fabricate precise values to fill a map.

## 3. Work packages

### E1 — audit and reproducible baseline

Record commands for the reference bake and the modern PaleoDEM bake; identify which
pack the UI selects. Save compact before reports, including input hashes, sediment
statistics, K9 residuals, wet fraction and existing Earth/reconstruction scores.
Correct source-registry statements that are not enforced by the tooling.

### E2 — observations and validation split

Target thin-cover shields, major sediment basins, passive margins, abyssal plains and
trenches. Candidate regions: Canadian/Baltic/Australian shields, Amazon/Congo basins,
Gulf of Mexico, Bengal fan, North Sea and Atlantic/Pacific abyssal sites. These are
sampling targets, not assumed values. Prefer licensed raster extraction from the
registry's sediment datasets over hand-entered approximate anchors.

Aim for 24–48 additional independently sourced observations across these regimes;
quality and coverage, not a count, decide acceptance. Assign spatially separated
holdout regions before fitting. No holdout point, or nearby duplicate extraction,
may influence interpolation or parameter tuning.

### E3 — bounded, province-aware corrections

Use source raster resampling where available. Else correct the existing sediment
prior locally using spherical-distance weights and an explicit support radius.
Do not blend across continental/oceanic or basin boundaries without a documented
rule. No support means retain the labelled prior, not extrapolate a distant basin.
Handle longitude wrapping and polar distances; raster averages use area weights.

Apply the correction before K9 inversion and datum reconciliation, then report how
much sediment and crust thickness changed and where clamps activated. Preserve raw
observed relief separately from any model-representable adjusted relief.

Keep the first increment in the existing 100 m sediment format; report quantization
error separately (up to 50 m on a point before interpolation). Shallow cover requiring
finer fidelity needs a separately versioned channel, not an undocumented scale change.

### E4 — delivery

Add small source-validation and bake-fixture tests under `tests/`, plus reproducible
commands in the source registry. Commit compact extracts, report and accepted pack
only; raw rasters stay outside Git. Expose provenance/uncertainty in the inspector,
without fetching anything at runtime. Run the same bake twice and compare decoded
arrays; generated timestamps must not obscure data determinism.

## 4. Gates

- Spatial holdout sediment MAE improves relative to the frozen baseline; report median,
  p90 and per-regime error, including failures. Do not approve on training residuals.
- No unexplained per-regime degradation, new invalid values or silent clamp increases.
  If data coverage is insufficient, ship tooling/provenance without claiming better maps.
- Existing Earth/K9 round-trip, coast, shelf, wet-fraction and reconstruction acceptance
  budgets remain satisfied. Run `tests/earth.js`, `tests/paleo.js`, `tests/reconstruct.js`
  and the short profile; changed initialization also requires owner-rig Earth GPU parity.
- No growth in startup-loaded data without reporting bytes and parse cost. A denser
  pack is not justified by a handful of observations.

## 5. Concentrations follow a different path

A later assay/occurrence table may seed the prospector's Earth catalogue. An occurrence
location says a deposit exists, not the grade throughout a geodesic cell. Require
commodity, units, sampled interval, assay/support type, date and source before ingest.
Keep measured evidence distinct from procedurally inferred deposits. The 0.6.x plan
specifies that separation; sediment improvement alone does not calibrate ore grades.
