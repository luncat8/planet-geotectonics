# 0.8.1 — Globe cutter, map interaction and manual export

Deliver the first usable globe-to-section handoff: a user draws a great-circle section on the 2D
map, freezes a coherent globe snapshot, then copies or saves a validated `pgt-slice-pack` v2.
The section repository can load that file without any network service.

This is an implementation plan, not a license to bypass the compatibility gate. It starts only
after `0.8.0-plan-slice-exchange-foundation.md` has supplied the byte-identical v2 codec,
fixture and port checks.

## 1. Scope and non-goals

### In scope

- a two-click, full great-circle cut in the existing 2D equirectangular map;
- a world-space path overlay that follows map panning and wraps correctly at the seam;
- a pure cell-run walker and v2 writer over the current globe state;
- copy-to-clipboard and downloaded JSON transport, including an honest fallback when Clipboard
  API access is unavailable;
- CPU and GPU snapshot discipline, provenance and test fixtures.

The initial UI calls this a **great-circle section**, not a finite arbitrary ruler line: click an
origin and a second point through which the full closed section runs. This uses the existing
section reader's strongest path mode and prevents an underspecified end-cap model from arriving
with the first interchange.

### Out of scope

- freehand/open polyline authoring (the v2 codec reserves it; add it only after the circle
  walker has passed all coverage tests);
- a 3D-map cutter, section reconstruction inside this application, inline iframe or a live
  section animation;
- exporting a display-only reconstruction pose, feeding a section result into `State`, or
  changing a deposit/prospecting record;
- calling `Columns.climb` for arbitrary path lookup. It writes climb diagnostics and is not a
  read-only spatial query.

## 2. Module shape and page order

Add one globe-owned module, loaded after `resolution.js` and the pure shared codec, before
`ui.js`:

```text
port/slice-format.js       shared v2 schema / geometry / validation / identities
js/slice.js                globe-only path, walk, snapshot and writer
index.html                 loads the two files before ui.js and adds controls/canvases
js/ui.js                   owns interaction, source metadata, GPU draining and transport
style.css                  overlay and compact control styling
```

`js/slice.js` exports one global / CommonJS value, `Slice`, with pure entry points such as:

```text
Slice.circleThrough(aWorld, bWorld, radiusKm, cellBudgetKm)
Slice.walk(grid, path, nearestCell)
Slice.pack(snapshot, path, source, options)
Slice.report(pack, walk)
```

Exact public names may differ, but the boundary must not: the module receives plain state/grid/
sea/provenance inputs, returns a fresh pack/report, and does not reach into DOM controls or mutate
the source state. `ui.js` handles browser lifetime and calls `SlicePack.validate` before transport.

Use `Resolution.nearestCell(grid, x, y, z)` for the lookup-seeded hill climb. It normalizes the
direction, seeds from the four lookup texels and walks `grid.ring` without touching statistics.
If its tie behavior must be made canonical for an exact vertex hit, improve that one pure helper
and retain its existing resolution tests; do not fork a second all-grid nearest-cell implementation.

## 3. Path geometry and map overlay

### 3.1 Clicks become a canonical world-space circle

At each map click:

1. call `MapView.direction` to form the displayed unit direction;
2. apply `Quat.rotateInv(..., viewQ, displayedDirection)` to obtain the underlying world
   direction, because `MapView.project` applies `viewQ` world-to-screen;
3. normalize it and retain it in path state, never in screen pixels.

The first click is the circle origin. The second must be separated from it and its antipode by the
shared codec's documented tolerance. Its cross product establishes the signed normal / initial
tangent; `SlicePack.circleThrough` derives canonical `lat0`, `lon0`, `az0`, `arcKm = 2πrKm`, the
supplied current-grid `cellKm` budget and `closes=true`. A bad second click keeps the first point
and shows a small, actionable message rather than exporting a nearly singular plane.

The writer quantises only when encoding through `SlicePack`; the editing representation remains
full precision. Repeated exports of an unchanged path therefore have the same canonical path
checksum and do not accumulate rounded coordinates.

### 3.2 Overlay behavior

Add a transparent `#slice-overlay` canvas to the same positioned map wrapper as the terrain and
marker canvases. It is visual only: it never writes the renderer's texture, `viewLookup`, state or
marker hit table. Sample the circle at a density based on visible pixels, project every point with
`MapView.project`, split a stroke whenever consecutive x values cross half the canvas width, and
redraw after `applyView`, resize, engine swaps and path edits.

The overlay shows:

- a restrained high-contrast line and origin/through-point handles;
- an open first point as `select a second point`;
- a small status line with path checksum prefix, approximate circumference and last export
  checksum / time when available;
- no line while the 3D map is selected.

Keep the path in world coordinates so it remains geographic while the user pans. Allocate a
reusable projection buffer; do not allocate a large point list in every animation frame.

### 3.3 Interaction precedence

Add a clearly labelled `Section` map-tool toggle with `Clear`, `Copy`, and `Save` actions. While
it is active on a 2D map:

- a primary click selects the first or second section point;
- pointer movement and drags continue to pan exactly as today; a moved drag never becomes a
  section click;
- section clicks do not pin/unpin deposits, run a survey or replace the normal probe selection;
- disabling the tool restores the current probe/pan path without deleting a completed cut;
- changing world/level/seed preserves a geographic path but clears its prior export report;
- 3D mode disables the tool with a reason instead of guessing a terrain-ray convention.

Implement this by resolving the tool decision before `mapClick` calls `probeClick`, not by adding
a second competing click listener. The existing 4 px drag dead zone and `pan.suppressClick` remain
the single source of drag-versus-click truth.

## 4. Cell-run walker

The pack represents contiguous source-cell runs along the line, not a dense sequence of duplicate
samples. The walker is responsible for geometry only; field extraction occurs after it has a
verified run list.

### 4.1 Algorithm

1. Parameterize the circle by arc distance `s` in `[0, 2πr)`, with a stable tangent at every
   point.
2. Establish a conservative step bound from the minimum current grid neighbour distance. Measure
   it at L5, L6 and L7 and choose a documented fraction before coding; begin at one third of the
   smallest neighbour distance, not a nominal equal-area cell width.
3. Use `Resolution.nearestCell` at sample positions. Coalesce consecutive identical cells.
4. When adjacent probes differ, bisect the analytic arc until the boundary bracket is below the
   documented metre-scale tolerance. Append the preceding cell's run at the midpoint convention,
   then continue from the new cell. At an exact vertex, use the codec's deterministic tie rule.
5. Assert that every normal transition joins actual `grid.ring` neighbours. If a step discovers a
   non-neighbour, recursively subdivide; if it still cannot establish a legal transition, throw a
   cutter error with location and cell ids instead of inventing an edge.
6. Close the ring by resolving the final-to-first transition in the same way and merge equal
   endpoint runs. Produce strictly increasing `sKm`, a positive span for every run and total span
   equal to `path.arcKm` within the chosen tolerance.

The path's starting cell is allowed to change after a world reraster because it is a geographic
line through a changed/rotated mesh; its geometry and path checksum do not change. No walker
result is cached across a grid rebuild.

### 4.2 Directed boundaries and velocities

For a run ending in neighbour `next`, find the directed ring slot in the preceding cell. Read
`state.edgeType[cell * 6 + slot]` and `state.polarity[...]`, then call the shared v2 boundary
conversion rather than duplicating enum logic in `ui.js`.

For each live source cell, use the analytic unit tangent `t` at a representative point of the run
and the cell-frame velocity `(vx, vy, vz)`:

```text
vt = dot(velocity, t)
vp = sqrt(max(0, dot(velocity, velocity) - vt * vt))
```

`vt` carries direction along the chosen path; `vp` is the non-negative tangent-plane component
out of the section. This matters for a later motion view, but neither number feeds globe physics.
The closing boundary is carried at the final run according to the same directed convention.

### 4.3 Field snapshot

The writer reads the existing authoritative split exactly once for each run:

- cell-frame: `z`, `vel`, edge type/polarity and water comparison;
- owner lookup: `owner[cell]` first, then `hFel`, `hMaf`, `hSed`, `age`, `fert`, `damage`,
  `plate` and the six `Diag.ORE_FIELDS` arrays;
- plate-frame: count and angular velocity in the v2 ordered `plates` table.

Use the v2 gap canonicalisation when `owner < 0`; do not use a neighbouring owner. Use the
current effective sea settings passed by the UI, not a hidden hard-coded `Params.sea` shortcut.
The host code is produced by the shared helper over the exported thicknesses. Potential order is
always the declared `Diag.ORE_FIELDS` order, never object enumeration order.

A pack captures fields from one immutable world snapshot. `Slice.pack` may allocate its own output
arrays, but it must not call a simulation kernel, `Diag.check`, raster operation, prospecting
routine or `Columns.climb`.

## 5. Provenance and coherent GPU capture

### 5.1 Source metadata

`ui.js` constructs a non-physics `source` record at export time:

| v2 field | source |
| --- | --- |
| `repo`, `commit` | explicit release constants in `js/slice.js`; update them in the release change |
| `pack`, `epochMa`, `rotModel` | selected Earth/start metadata held by the UI, not inferred from a dense plate id |
| `tMyr`, `level`, `gridSeed`, `simSeed` | the captured state/grid |
| `built` | ISO capture time, provenance only |
| `license` | exact Earth/source attribution or the synthetic-world attribution string |

If the page is in a display-only reconstruction scrub, disable export with an explanation. The
current pose can be deliberately different from the simulated state; lying with `tMyr` would make
a beautiful but incoherent section. Release the scrub or rebuild/apply a real state first.

### 5.2 CPU path

On CPU, synchronously capture references to the current `state`, `grid`, completed `path` and
water/source metadata, increment an export serial, then write and validate the pack before
enabling transport. A rebuild or path change invalidates an older serial's report.

### 5.3 GPU path

The CPU mirror can be one event cycle old. For GPU export:

1. stop/play-gate further stepping for this export and disable the export controls;
2. use the existing `whenGpuIdle` discipline to await an in-flight batch/campaign readback;
3. call the established device download into the currently captured state;
4. confirm the same `state`, `grid`, path generation and export serial still own the request;
5. synchronously walk/write/validate from that completed mirror, then restore controls and the
   prior play state only if the same world is still active.

A failed readback reports failure and produces no file. A rebuild, engine switch, new export or
path edit cancels the stale callback by serial; it never writes a pack for a newly swapped world.
This mirrors the existing prospecting snapshot discipline rather than introducing a second queue
protocol.

## 6. Transport UX

`Copy` serializes only with `SlicePack.encode(pack)`, which supplies canonical JSON and validates
again. Prefer `navigator.clipboard.writeText`; where it is unavailable (notably some `file://`
contexts), select a read-only text area / show the text with an explicit `copy manually` message.
Never claim it copied if the promise rejects.

`Save` creates a JSON Blob and revokes its object URL after download. Use a readable, collision-
resistant name such as:

```text
pgt-slice-L5-seed7-t200-circle-<pathChecksum8>-<checksum8>.json
```

The status text reports run count, path length, source time, full checksum prefix and whether the
pack came from a drained GPU snapshot. It does not advertise reconstructed beds or a live link.

## 7. Tests and measured gates

Add focused tests to the normal Node runner and retain `tests/browser-scripts.js` coverage for the
new script order.

### 7.1 Pure tests

`tests/slice.js` loads the real grid/state modules plus `Slice` and covers:

- circle construction through known world directions, invalid coincident/antipodal clicks and
  stable canonical path checksum;
- a rotated-view click round trip: `MapView.direction` + `Quat.rotateInv` identifies the same
  world point that `MapView.project` drew;
- L5, L6 and L7 walks, including seam crossing, a pentagon vicinity and a forced gap;
- every transition is same-cell or a legal neighbour; the complete ring tiles the declared arc;
- field values, owner/plate distinction, host/potential order, wet state, gap rows, all boundary
  kinds and signed `vt` / non-negative `vp` against known fixtures;
- repeated writes from an unchanged snapshot/path have identical semantic fields and checksum;
- writer failure does not alter `state`, diagnostic counters, ownership, time, RNG-facing fields
  or prospect ledger data.

Use a fixed small synthetic state for exact hand assertions, then real representative worlds for
coverage. Record actual run count, size and wall time at each offered level in the release report;
no guessed old-grid numbers are acceptance evidence.

### 7.2 UI/GPU tests

Extend the DOM harness with the new elements and prove:

- the tool intercepts a click but not a drag, probe or marker click;
- overlay redraw follows a changed `viewQ` and clears safely;
- an invalid second point does not replace a valid first point;
- Copy/Save are disabled until a completed path and validated pack exist;
- a GPU export waits for download, and an intervening rebuild/path edit suppresses its result;
- Clipboard rejection exposes the manual fallback; no fake success status is printed.

Where hardware WebGPU is unavailable, mock only the promise/order boundary and retain a local
smoke capture on a real adapter before release.

### 7.3 Exit criteria

0.8.1 is complete only when all of these are true:

1. a user can draw, see, clear and re-export a full great-circle line on the 2D map;
2. the saved/copied object is accepted by the v2 validator and the slice-side fixture loader;
3. it accurately reflects a single CPU or drained-GPU snapshot and names its provenance;
4. all boundary, gap, owner/plate and potential semantics are covered by exact tests;
5. the walker proves legal adjacency and full-path coverage at L5–L7;
6. existing tests and short profile are green, with no new simulation/diagnostic side effects.
