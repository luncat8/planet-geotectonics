# 0.8.2 review — deterministic Earth-start section bakes

## Verdict

`0.8.2-plan-slice-bake.md` is implemented: `tools/earth/bake_section.js` writes a valid
`pgt-slice-pack` v2 Earth-start section deterministically, through the same loader, the same
geometry, the same writer and the same codec the map cutter uses. The output is byte-identical
across runs, changes only in `source.built` when only `--built` moves, and names its source
pack, input epoch, preset-derived rotation model and licence. `tests/slice-bake.js` (new, in the
short profile) plus a new GUI provenance assertion hold it; the short profile is green at 43
tests and the Python suite is unchanged and green.

The plan's exit criterion "a counterpart reader accepts it" is not closed here — that is the
slice repository's acceptance, and it is what unblocks its Phase B-b bundle restore. Nothing in
this change starts a live channel, mutates topology or returns an observation to the globe.

## What shipped

- `tools/earth/bake_section.js` — the CLI. `--start --level --seed --preset --circle --out`,
  with `--built`, `--commit`, `--report` and `--force`. Exit 0 on a written pack, 2 on any
  refusal, and a refusal never leaves a file behind. It refuses to write into `js/data/` at all
  (the plan asked for "not by default"; a flat refusal is simpler and cannot be talked past).
- `tests/slice-bake.js` — the writer-path, determinism, provenance, corpus and CLI-refusal
  gates. ~6 s, so it lives in the short profile.
- `data/sections/` — the two reviewed examples the plan's §5 corpus asks for, with
  `data/sections/SOURCES.md` carrying their commands, identities and field semantics.
- `js/ui.js` — Earth-start section provenance is now preset-aware (see §"Decisions").
- `js/slice.js` — the `COMMIT` placeholder `0.8.1-plan-slice-cutter.md` §5.1 left open is
  replaced with the shipping revision, and `tests/slice-bake.js` fails while it is a
  placeholder, so a release cannot ship an anonymous pack.
- `.gitignore` — `out/`, the documented scratch location for generated artifacts.
- `AGENTS.md` — the 0.8.2 entries, the new test count and the `out/` convention.

## The one generation path

`main()` loads, in this order: every `js/data/earth-*.js` (so `EarthPacks` registers exactly as
`index.html`'s script tags do), then `Grid`, `State`, `Params`, `Earth`, `Slice` and the shared
`SlicePack`. `bake()` then does what the page does — `new Grid(level, seed).build()`,
`new State(grid, seed)`, `Earth.pick(level, start)`, `Earth.apply(state, pack, { realistic })`,
the circle from the codec's own geodesic step, `Slice.pack(state, circle, sea, provenance,
license)`, then `SP.validate` / `SP.verify` / `SP.encode`, and only then a write. Nothing
re-decodes a raster, re-inverts K9, re-walks cells or re-checksums: `tests/slice-bake.js`
proves it by building the same fresh state itself and comparing every payload field buffer
against the CLI's output.

`--circle lat lon azimuth` is turned into the canonical circle by stepping one degree along the
codec's own geodesic from `(lat, lon)` on `azimuth` and handing those two points to
`Slice.circleThrough`, so a CLI circle and a browser click are one path object, not two that
happen to agree. The derived `az0` is checked against the request (measured deviation
≤ 1.2e-13 degrees; the guard refuses past 1e-6).

## Decisions that tightened the plan

### `built` is outside the checksum, by design

The v2 `checksum` is `canonical(pack, false, false)`, which drops `source.built` so that
re-stamping a pack cannot change its identity. The first corruption test therefore passed at a
byte inside `built` and was refused by nothing — the test was wrong, not the codec. The suite
now targets payload bytes only (plate table, `sKm`, `license`, the stamp itself) and says why.
A corrupted `built` is undetectable by the stamp; it is provenance metadata and is treated as
such.

### Earth provenance claimed a rotation model the preset had dropped

`sectionProvenance` returned `rotModel: 'PALEOMAP'` for every Earth start. Under the game
preset the pack's poles are not held at all — `Earth.apply` writes zero omega and the
procedural mantle drives the plates — so the exported pack claimed a model it did not use. The
bake had to decide the same question and could not, so the UI now answers it from the preset
(`PALEOMAP` for realistic, `procedural` for game), matching the CLI exactly, and
`tests/gui.js` pins both branches on a real Earth-start capture. This is the one behaviour
change outside the new files.

### `--commit`, beyond the plan's interface

The plan's flag list has no revision. A pack whose `source.commit` is a placeholder is an
anonymous artifact, and the slice side's B-b has to record "globe revision" per restored
bundle. The CLI therefore takes an optional `--commit <sha>`, defaulting to `Slice.COMMIT` —
the release constant — and `tests/slice-bake.js` refuses a placeholder. The corpus files were
generated with the explicit revision that produced them, and the test reads that revision back
out of each file rather than hard-coding it.

### A self-describing corpus

`tests/slice-bake.js` derives each committed example's arguments from the pack itself — start
resolved backwards through `Earth.pick`, level/seed from `source`, preset from `rotModel`,
circle from the stored path — and re-bakes under the provenance the file records, demanding
byte equality. A change in the Earth loader, the walker or the writer turns the example red
instead of leaving a stale fixture that still loads.

### Honest zeros

At `tMyr = 0` all six ore potentials and all damage are zero, and the tool says so rather than
labeling them: `data/sections/SOURCES.md` records that they are the state the start
initializer supplies, not a surveyed absence and not modelled deposits, and the test asserts
the zero sum. The plate table is asserted to account for every run, which is the t=0 truth (no
gap rows, because `Earth.apply` owns every cell).

### Volume mode stays in the browser

The CLI exports level mode at `Params.sea` (the physics datum), the same effective water the
page exports. Volume mode solves a level from the bathymetry on screen, and a bake has no
slider that produced it, so it is deliberately not offered.

## Tests

`tests/slice-bake.js` pins: the writer path (every payload buffer equals a direct `Slice.pack`
on the same fresh state, plate table included); v2 validation, `verify`, and the strict
`decode` round trip; one-byte corruption refusals at payload offsets; byte-identical
determinism; the built-only provenance change; provenance/epoch/preset/licence; zero
potentials and plate-table completeness; the historical epoch and the tilted circle; the
committed corpus; the `COMMIT` release gate; and 14 CLI refusals (missing/unknown start, bad
level/seed/preset/circle, bad `--built`/`--commit`, unknown flag, missing `--out`, latitude
range, a nonempty output without `--force`, a `js/data/` destination and an unwritable one),
each leaving no output and no release line.

`tests/gui.js` adds the Earth-start provenance assertion (pack, epoch, preset-derived rotation
model, licence) on both presets.

Validation on this revision:

```text
node tests/run-all.js
PASS all tests (short profile, 43 tests in 179 s)

python3 -m unittest discover -s tests -p 'test_*.py'
Ran 4 tests — OK
```

The full/release histories were not run in the sandbox, per `AGENTS.md`; nothing in this change
touches a kernel, a history or a GPU path, so the owner-rig gate is a formality rather than a
risk.

## Handoff to `planet-tectonics-2d-slice` (Phase B-b is now unblocked)

The gate the slice side recorded — "B-b executes only when the globe ships a v2 writer" — is
satisfied by `tools/earth/bake_section.js`. The commands, identities and the frozen-bake
boundary are in `archive/0.8.2-report.md` §4; the two committed examples are in `data/sections/`
and reproduce byte-for-byte from the arguments they record. The bundles are theirs to restore
per bundle, through this CLI or an explicitly recorded hand-run cutter export, never through
`tools/earth/bake_section.py`.
