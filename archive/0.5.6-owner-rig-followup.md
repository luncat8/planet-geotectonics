# 0.5.6 owner-rig follow-up — vertex gather timing distribution (2026-10-24)

## Decision

Keep `hex` (Cell samples) as the page default. `vertex` remains available as an explicit
select / `?hmod=vertex` choice, but does not become the default again until its gather passes
the §14.4 limit of 0.5 ms under the distribution gate. This changes only a display-mode
default; it does not change the simulation, the heightfield lookup, or the vertex shader.

## Evidence

Owner-rig log: `experiments/logs/webgpu-smoke-2026-10-24-09-20.log` (Chrome 151, Windows
x86_64, NVIDIA GPU). The smoke passed, with timestamp queries available, no console or
WebGPU errors, and clean D1 parity across 16/16 layers. Its §14.4 gate uses 8 collects per
mode and gates on the maximum:

| mode | gather median / max | draws median / max | gate |
| --- | ---: | ---: | --- |
| hex | 0.064 / 0.066 ms | 1.454 / 1.507 ms | met |
| vertex | 0.786 / 1.049 ms | 0.783 / 0.799 ms | gather missed; draws met |

The separate three-draw sum reported by the same run is 1.507 ms max for `hex` and
2.163 ms max for `vertex`; both are below the 5 ms draw budget. The `vertex` gather maximum
is more than twice the 0.5 ms budget, so the earlier single-collect 0.065 ms reading in
`webgpu-smoke-2026-10-12-20-43.log` is not sufficient to justify making it the default.

The owner full-test log (`experiments/logs/full-test-2026-10-24-09-21.log`) independently
reports 51/51 tests passing, including `section-host` and GUI coverage. The mode-default
change below is also covered by the local GUI test and short-profile suite.

## Implementation

- `index.html` and `js/ui.js`: make `hex` the selected/default mode. Invalid `?hmod=` values
  fall back to `hex`; `?hmod=vertex` still explicitly opts in.
- `js/ui.js`: the copy header treats `hex` as the default and names the non-default `vertex`
  mode.
- `tests/gui.js`: assert the default starts no heightfield lookup, verify the opt-in lookup
  builds and attaches, and pin the revised capture-header behavior.
- `README.md`, `AGENTS.md`, `0.7-proposed.md` and
  `0.5.7-deferred-plan-3d-visual-quality.md`: record the latest gate result and current
  default so future work does not rely on the earlier single-collect decision.

## Verification

```
node tests/gui.js       PASS
node tests/run-all.js   PASS — short profile, 47 tests in 177 s
```

The WebGPU timing was measured on the owner rig and is recorded above; it is not a sandbox
benchmark. The next performance step, if desired, is to profile / optimize the `vertex` gather
and repeat the same owner-rig distribution gate before reconsidering the default.
