### 1. Review of Previous Commit & Improvements

The previous commit (0.5.5) introduced the equirectangular lattice mesh (`Render3D.gridMesh`), per-vertex analytic normals (`NORM_ANALYTIC`), live-swapping `Mesh` and `Normals` selects, and the mode-aware detail list.

A line-by-line review of those changes revealed two bugs/omissions, both of which have been resolved and pinned:

1. **Pole Division-by-Zero in `NORM_ANALYTIC` (`js/render3d.js`)**:
   - *Issue*: In `vertexNormal`, the tangent vector in the local east/north/up frame was constructed as `let east = normalize(vec3<f32>(-dir.z, 0.0, dir.x));`. At the geographic poles ($\vec{d} = (0, \pm 1, 0)$), both $x$ and $z$ are zero, giving `vec3(0, 0, 0)`. In WGSL, `normalize(vec3(0, 0, 0))` divides by zero and produces `NaN`. This corrupted the vertex normal varying, propagating `NaN`s into fragment lighting for all incident pole triangles.
   - *Fix*: Added an early guard at the top of `vertexNormal`:
     ```wgsl
     if (abs(dir.y) > 0.9999) { return dir; }
     ```
     At the exact poles, all longitudes converge and the sphere normal is strictly radial ($\vec{d}$). This eliminates the division by zero, guarantees finite normals, and skips four redundant `textureLoad` taps at pole vertices.
   - *Verification*: Pinned in `tests/wgsl-struct.js`.

2. **WebGPU Timestamp Query Buffer Leak in `Render3D.release()` (`js/render3d.js`)**:
   - *Issue*: When WebGPU timestamp queries are supported by the adapter, `this.tsResolve` (usage `QUERY_RESOLVE`) and `this.tsMap` (usage `MAP_READ`) buffer pairs are allocated in `init`. In `release()`, textures, pipelines, and mesh buffers were destroyed, but `tsResolve` and `tsMap` were left uncollected, leaking GPU buffers on 3D toggles, level rebuilds, and engine switches.
   - *Fix*: `release()` now iterates and destroys all buffers in `this.tsResolve` and `this.tsMap` and sets them to `null`.
   - *Verification*: Pinned in `tests/render3d.js`.

### 2. Diagnosis: Why 3D Elevation Currently Renders Only as Hexes

The reason the 3D globe displays terrain strictly as stepped hexagonal mesas—even when switching between the Icosphere and the Lattice mesh—stems from how elevation data is transferred from the simulation to the 3D render pipeline:

1. **Simulation Voronoi Discretization**:
   The physical sim lives on an icosahedral geodesic grid of $V$ cells (10,242 at L5). Each cell $c$ is a spherical Voronoi polygon (12 pentagons, rest hexagons) centered at unit direction $\vec{p}_c$, holding a single scalar elevation $z_c$.
2. **Nearest-Cell Lookup (`LOOK`)**:
   The equirectangular lookup raster `LOOK` ($1024 \times 512$) stores the nearest cell index $c = \text{argmin}_j \|\vec{d} - \vec{p}_j\|$. For every pixel in the footprint of cell $c$, `LOOK` holds the integer $c$.
3. **The Gather Pass (`Render3D.GATHER`)**:
   The gather compute shader samples `zAt(LOOK[sy * LW + sx])` to populate the $2048 \times 1024$ `HEIGHT` texture. At L5, a single cell covers ~51 pixels in `LOOK` and ~205 texels in `HEIGHT`. Every one of those 205 texels receives the exact same scalar $z_c$.
   **The `HEIGHT` texture is therefore a rasterized mosaic of flat-topped hexagonal Voronoi prisms.**
4. **Bilinear Displacement Artifact**:
   When `heightAt(uv)` samples `HEIGHT` to displace mesh vertices:
   - In cell interiors, all 4 texels are identical ($z00 = z10 = z01 = z11 = z_c$), producing completely flat plateaus ($\nabla z = 0$).
   - Bilinear interpolation only creates a narrow ramp across the single-texel boundary between neighboring cells.
   - Consequently, the displaced mesh forms flat hexagonal plateaus bounded by steep 1-texel cliffs.
5. **The UI Naming Confusion**:
   In 0.5.5, the regular $(u, v)$ quad lattice mesh (`gridMesh`) was labeled **"Heightmap"** in the Mesh select. This conflated mesh *topology* (quad grid vs subdivided triangles) with the *height field* representation. Both meshes sample the exact same stepped hex `HEIGHT` texture, so both appear as stepped hexes.

### 3. Plan & Investigation Added to `0.5.0-plan-3d-render.md` (§14)

A comprehensive investigation and roadmap has been added to `0.5.0-plan-3d-render.md` as **§14: Investigation and plan: 3D height modes (hex plateaus vs vertex-interpolated heightmap)**. Key architectural points:

#### A. The Two Modes
- **`hex` mode (Discrete Hexagonal Cells)**: Visualizes the simulation's native Lagrangian tectonic columns as distinct hexagonal blocks/prisms. Enhanced by nearest-texel sampling or sharp facet normals to eliminate the 1-texel bevel and make cell boundaries crisp and intentional.
- **`vertex` / `heightmap` mode (Continuous Vertex Elevation)**: Naturalistic planetary topography. Mountain ranges, continental margins, rift valleys, and oceanic trenches form continuous, smoothly undulating relief without Voronoi stepping, resembling a standard digital elevation model (DEM).

#### B. Technical Evaluation of Continuous Interpolation Techniques
Four approaches were evaluated:
1. **Candidate A (Spherical Delaunay Barycentric Gather, `LOOK_TRI`)**: Precomputes an 8 MiB equirectangular lookup texture storing $(c_0, c_1, c_2)$ and barycentric weights $(w_0, w_1)$ per texel. Provides exact piecewise-linear ($C^0$) triangular interpolation between cell centers.
2. **Candidate B (Ring Inverse-Distance / Radial-Basis Blend in Gather Shader)** — **Recommended**:
   In the gather compute shader, read nearest cell $c$ from `LOOK` and fetch its $N$ ring neighbors from the existing `GRIDI` adjacency table. Weight each neighbor by a compact smooth spherical distance kernel (e.g. Wendland $C^2$ polynomial).
   - **New GPU Memory**: **0 MiB** (reuses committed `LOOK` and `GRIDI` buffers).
   - **Compute Cost**: 7 buffer reads and distance evaluations per height texel (~0.3 ms in gather pass).
   - **Continuity**: $C^1$ smooth, organic planetary slopes without hex stepping.
3. **Candidate C (Dual Geodesic Vertex Heights)**: Averages cell heights to dual vertices ($z_v = \frac{1}{3} \sum z_c$).
4. **Candidate D (Separable Gaussian Blur on `HEIGHT`)**: Post-processing blur pass; requires an 8.4 MiB ping-pong texture and attenuates peak elevations.

#### C. Decoupled UI & URL Controls
- **Mesh Topology select (`mesh3d`)**: Renamed in UI from "Icosphere / Heightmap" to `Icosphere / Lattice` to clarify that it selects vertex connectivity, not elevation sampling.
- **Height Mode select (`hmod3d`)**: New select beside Mesh: `Height: Hex plateaus | Smooth heightmap`.
- **URL Parameter**: `?hmod=hex` (default) vs `?hmod=vertex`.
- **Live Switching**: Swapping height mode switches the gather compute pipeline/bindings without tearing down the session, mesh buffers, or device.
