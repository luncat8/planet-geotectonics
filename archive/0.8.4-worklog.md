No `fnvText`. Internally `function fnvText(domain, value)` exists (line 402) but is not

its hash with the domain string baked in — which is also what globe §2.1's
"independently testable" asks for and what that section's objection to v1 names
("a private section FNV helper") rules in.

### 2.5 Validation laws correspond — P5 ground

Re-checked item for item against globe §2.1's bullet list and slice `js/core-log.js` §A:

| globe §2.1 list | slice law (core-log.js) |
| --- | --- |
| thicknesses sum to `hTotM` within explicit quantisation tolerance | `TH_TOL = 1.5`, `Math.abs(sum - r.hTotM) > TH_TOL` |
| non-monotone depositional ages except where both named intrusion flags permit | `((fl[at+i]|fl[at+prev]) & FLAG.intr)` exempt, `ag[i] < ag[prev] - AGE_EPS` |
| every bed names real lithology with positive thickness | `li in [0, LITH.n)`, `thM > 0` |
| `sKm` ascending, no duplicates, no non-finite | `sKm > prev`, `finite(sKm)`, `sKm < arcKm` |
| no empty/oversized bed stacks | `records.length > 0`, `beds.length <= layerCap` |
| reject missing checksum, foreign version, unknown schema | `HEX.test(pathChecksum)`, `HEX.test(packChecksum)`, `msg.checksum !== checksum(msg)`, `version !== VERSION`, unknown schema name → refuse |

The two deltas from globe sketch to slice law are exactly P3 (hash ownership) and P4
(named schema + positional beds). The protocol text is a port of a law both sides have
already stated.
