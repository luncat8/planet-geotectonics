# 0.5.6 device report — the rig logs of 2026-10-12, what they exposed, and what to re-run

Scope: the owner-rig captures `experiments/logs/webgpu-smoke-2026-10-12-03-02.log` (FAIL, 4)
and `experiments/logs/gpu-parity-2026-10-12-03-10.log` (ensemble FAIL + parity FAIL), the
fixes their failures led to, and the measured state after them. Validation runs were made on
the container's SwiftShader rig (Chrome 153, `@sparticuz/chromium` + `puppeteer-core` via the
findings recipe) plus `node tests/run-all.js`; the numbers below say which is which.

---

### 1. webgpu-smoke: the vertex gather never actually read back (fixed)

Three `[FAIL]`s (`vertex gather, cellZ` by 5868 m, `cellF` by 6303 m, plateau pairs 100%/100%)
and six uncaptured WebGPU errors all had one root cause: the height texture in
`js/render3d.js` was created with `usage: 0x8 | 0x4` (STORAGE | TEXTURE_BINDING) and no
`COPY_SRC`, while `readHeights` copies it out. Hardware validates that copy ("usage doesn't
include CopySrc" → invalid command buffer ×3), the staging buffer stayed zero, and every
subsequent diff compared zeros against a correct shader. The world texture had already lived
this lesson (`js/gpu/render-gpu.js` carries the comment); the 0.5.6 texture repeated it.

- **Fix**: `usage: 0x8 | 0x4 | 0x1` on the height texture, with the reason in-line.
- **Verification** (SwiftShader smoke, canvas present stubbed per the findings' headless rule):
  `vertex gather, cellZ: worst |device − CPU| 1.08e-3 m`, `cellF: 9.61e-4 m` (gate 0.05 m),
  `0 fallbacks · 0 clamps`, zero console/WebGPU errors. The lookup build reproduced the
  calibration exactly (32.0 MiB, max weight error 1.52e-5).

### 2. The plateau gate was calibrated where the plan says not to look (fixed)

With real readback the plateau check still failed: `94.8% hex · 17.34% vertex` against a
`vp < 0.01` bound. That bound came from `experiments/heightfield-calibration.js`'s synthetic
undulating field measured in f64 (0.00% continuous). Measured on the real L5 world
(node, same records): the CPU oracle itself gives **2.49%** equal pairs in f64 (genuinely flat
abyssal floors and u16-weight quantization — §14.4 "genuinely flat input is allowed to remain
flat") and **19.0%** once rounded to f32, the precision the device texture lives in. The
device's 17.34% is *below* its own f32 oracle — the gather is correct; the gate was not.

- **Fix**: the smoke now prints the CPU-oracle share as the floor and gates the mode property
  the plan actually states — `hp > 0.3 && vp < 0.5 * hp` (vertex must remove most of the same
  session's nearest-cell plateaus).
- **Verification**: smoke PASS end to end (SwiftShader).

### 3. The §14.4 device gate line measured nothing (fixed)

The 2026-10-12 smoke's `3d gather 0.00 · land 0.00 · water 0.00 · rim 0.00 ms` is not a fast
pass: `tsLine()` formats the timestamp buffer immediately while `collect()` maps it
fire-and-forget, so a one-shot read always prints the initial zeros. The 0.5.6 slice-4 gates
(gather ≤ 0.5 ms, 3D passes ≤ 5 ms) had no numbers to be measured from.

- **Fix**: `Render3D.collect()` returns its `mapAsync` promise (the 2 Hz strip still ignores
  it); the smoke awaits it before the gate line.
- **Verification**: the same smoke prints real timings (`3d gather 41.5 · land 27.5 · water
  26.4 · rim 21.8 ms` — SwiftShader, relative only). Hardware numbers are the owner rig's
  next trip; slice 4's default switch waits on them.

### 4. gpu-parity: the frame-0 `low`/`hSed`/`oBas` divergence is closed (elev32)

`[parity] frames=1` failed identically on 2026-09-17 and 2026-10-12 (bit-for-bit: `low` 28
bad at [410], `hSed`/`oBas` 2 bad at [2078] off by the same ~2× — one flipped chain cell
moving a whole sediment packet). That signature was the documented fround residual: f64
elevation vs the device's f32 arithmetic disagree by 1-5 ulp from *identical* inputs
(measured: 6137/10242 cells bit-equal the other way), and every near-tie the drainage pick
sits on can flip.

- **Fix**: `js/surface.js` `elev32` evaluates the elevation formula in the device's own f32
  op order (`elevationZ` verbatim), and `s.z` holds that value; the drainage pick reads it
  directly. Not a full f32 reference sim — one shared formula, exactly.
- **Verification** (SwiftShader rig): the chain is bit-identical to the WGSL output from
  identical inputs over a whole L5 world (10242/10242); `low` flips at the first compare
  drop 83 → 0 (`__run frames=1`: "parity OK for all compared frames", the 2× hSed/oBas split
  gone); the residual at frame 2 is ~2 cells from input drift through kernels still in f64 —
  above all `zDyn`'s vendor-specific `exp` (the `cosx`/`sinx` shared-series pattern is the
  model if an `expx` is ever needed).
- **CPU-side consequence**: z moves by ≤ 5 ulp (sub-millimetre), which is enough to move a
  seed's chaotic rift timing by tens of Myr — `tests/split.js`'s natural run is
  re-baselined on seed 17 / 200 Myr (first merge 28 Myr, first split 48 Myr, both paths with
  more margin than the old seed 23 window; measured, comment updated in place).

### 5. gpu-parity: the ensemble bound violation

The 2026-10-12 ensemble failed at seed 8 / t=91 Myr (columns 2.03% > 2%) — the first bound
violation in the log series (09-16: 1.17% worst, 09-17: 1.02%). The CPU half of that log is
the current code's trajectory (reproduced bit-for-bit in node before any change), so the
violation is the cross-engine drift draw, seeded by the frame-0 flip divergence and amplified
by the 0.6.x deposit/ore thresholds. With the seed gone: local 3-seed 1000-frame ensemble
(SwiftShader, same bounds) passes — worst columns 1.35% (seed 8), mean 13.5%, max 2×,
cont 0.53pp — and `--batch` and `--determinism` pass. A different vendor draws a different
chaotic trajectory, so the owner rig's `python3 run_gpu_parity.py` is the number that counts.

### 6. What the owner rig should re-run

1. `webgpu-smoke.html` — expect `[result] PASS`, the vertex-gather diffs ≤ 0.05 m, the
   plateau line with the CPU-oracle share, and — the new number slice 4 needs — a real
   `3d gather · land · water · rim` timing line for the §14.4 gates (gather ≤ 0.5 ms,
   passes ≤ 5 ms at L5-L7). Until those exist the default height mode stays `hex`.
2. `python3 run_gpu_parity.py` (1000 --ensemble) — expect bounds green with the flip seed
   gone; `python3 run_gpu_parity.py 1` — expect "parity OK" (the old28-flip signature is
   the fixed defect, not a locator to re-read).

Everything above is validated on the container's SwiftShader rig except the §14.4 hardware
timings and the NVIDIA ensemble draw, which only the owner machine can produce.
