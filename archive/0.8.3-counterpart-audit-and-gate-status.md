## 3. The two schema notes the counterpart returned, answered

Both were returned rather than resolved locally (their D6). Neither is a defect and **no port
bump is proposed**: `port/` stays at the bytes in §1.1.

1. **Fixture trailing newline.** Confirmed and intended: `port/fixtures/slice-pack-v2.json` ends
   `… 8 d 8 d 2 " } \n`, while `SP.encode` emits canonical text with no trailing newline and the
   bake CLI writes none (`… f d e 8 7 1 " }`). The fixture is a text file; canonical text is the
   codec's output. Both sides already trim before comparing — `tests/port.js:36`,
   `tests/slice-format.js:8` and the counterpart's equivalent. Equality modulo one newline is
   the designed reading, not a latent ambiguity to legislate.
2. **The path checksum is derived, not stored.** Correct by design: v2 stores one stamp; the
   path identity is `SlicePack.pathChecksum(path)`. A "corrupted stored path checksum" cannot be
   constructed, and path corruption is caught by the stamp together with the path law. No action.

## 4. Phase C gate status — the part the handoff is actually waiting on

**Phase C is not waiting on globe implementation.** `0.8.3-plan-slice-bridge.md` §5 states its
own completion condition: it is planning/architecture work, complete when the backport boundary
is documented, a portable observation protocol is *specified but not prematurely merged*, and the
live bridge's gates are explicit; "implementation may stop after 0.8.2 without being incomplete".
All three hold. One-way, file-safe, validated export remains the intended milestone.

What Phase C is waiting on, in order of hardness:

| item | status | owner |
| --- | --- | --- |
| **C-live gate 4** — the section automatically rebuilds its plate topology after incoming crossings | **open; a block, not a test gap** | slice |
| **C-live gate 1** — repeated manual v2 round trips, CPU *and* GPU globe snapshots | achievable now; the CPU leg is what §1 exercised, the GPU-snapshot leg is untested | shared |
| **C-live gate 2** — both sides reject identity/schema mismatches without partial mutation | largely demonstrated (their corruption suite, this codec's); not yet exercised as a *pair* | shared |
| **C-live gate 3** — staleness correct after either world changes | untested at the pair level | shared |
| **C-live gate 6** — fixed-seed, fixed-cadence runs prove no mass/clock/ownership ambiguity at handoff | untested | shared |
| **C-live gate 7** — a review decides whether C4 stays comparison-only | no review held | review |
| **C-live gate 5** — R4 mechanics | satisfied (slice 0.1.8 brake, 0.1.9 re-measurement); kept on the list so a fork re-derives it | slice |
| **C-return** — a `pgt-core-log` v2 observation protocol | **specified** (`0.8.3` §2.1 gives the canonical body: version, both identities, `arcKm`/`tMyr`/`epochMa`, a named lithology schema, records, checksum, `packChecksum` mandatory) and **deliberately not written** | shared, when scheduled |

Two sentences that should end any ambiguity about the globe's side:

- C-return needs one coordinated `port/core-log-format.js` v2, byte-identical and independently
  testable in both projects. Writing it now would violate `0.8.3` §2.1 ("only when the import is
  actually scheduled") and §5 ("not prematurely merged"). The design is already written down;
  what is missing is a **decision to schedule**, then one port bump.
- C-live needs the slice's gate 4 closed first. No amount of globe-side work substitutes for it,
  and `0.8.3` §3 forbids any acceptance condition that claims mechanically validated two-way
  coupling, topology mutation on the globe, or section-derived mass transfer.

## 6. Disposition

Nothing in this repository is blocked by the counterpart's Phase B-b; it landed and it verifies.
The next move was a **decision**, not an implementation, and it is made:

> **Hold.** Phase C stays closed and one-way, file-safe, validated export remains the milestone

- no `port/core-log-format.js` v2 is written, and no `SectionObservations` side table is added —
  `0.8.3` §2.1 says schedule first, merge later;
- no C0–C4 work of any kind, and in particular no live channel, coupling envelope or
  core-log import;
- `port/PORT.json` keeps its stale pre-cutover note (§5) until something is actually scheduled —
  a manifest touch with no artifact behind it is churn;
- the globe's 0.8 line is therefore **complete as shipped**: `0.8.0` v2 contract, `0.8.1` cutter,
  `0.8.2` deterministic bakes, `0.8.3` planning with its gates explicit.

This document is the globe's standing answer to "Phase C is gated on the globe's 0.8.3 side":
the globe's side is done, and the gate is a counterpart block plus a scheduling decision that has
been taken negatively. Re-open it only on a new decision, recorded here or in a successor.
