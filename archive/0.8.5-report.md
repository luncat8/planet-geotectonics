### 2.2 Decisions inside the milestone

- **The host module itself is lazy.** The answer's §6 sentence "SectionHost is the one new
  page global, created only when the panel first opens" is implemented literally: ui.js
  injects `js/section-host.js` on the first open. `index.html`'s script list is untouched,
  so the slice's namespace audit §D (the page at the pin loads `SlicePack` and
  `CoreLogFormat` exactly once) reads the same after this commit.
- **Two refusal classes, two remedies.** A script `error` with nothing executed keeps the
  host retryable (the tree can appear; the next open retries) and names the failed url, the
  base, the sibling checkout and `?slice=`. Once any script has run, a retry would inject a
  second copy, so a wrong tree (chain completes, contract entries missing) latches
  `loaded`, names the missing entries and asks for a page reload — "never a second copy
  under any name" (contract §8) enforced by the host's own state, not by hope.
- **The skip is presence detection, not a hardcoded omission.** The loader walks the full
  canonical order including the two shared port files and skips exactly those whose global
  the page already holds; `tests/section-host.js` pins both directions (page with the
  codecs: no port url injected; page without: they are injected first).
- **`data-geo` is not set.** The slice's M2 rehearsal pins the geology rate to 1000 for its
  dry run; the globe host leaves the engine's own defaults alone — the mount carries only
  the start bit and the bundle id.
- **The status line is the section's own.** `standalone` leads while `COLSECTION.syncLive`
  is false; mode/stale/paused come from the banner fields, never a host-side guess; the
  baked-bundle limitation (until the slice's `loadPack`, A3) is named in the line and in a
  static panel hint.

   refusal names the url and base, the globe runs unchanged, no partial chrome.
