Root cause
The GUI and bench were still letting canvas presentation race the next heavy segment.

More precisely:
1. GpuSim.play resolves after it has SUBMITTED a segment, not after that segment has FINISHED on the GPU.
2. js/ui.js and bench.html were scheduling the canvas present from queue.onSubmittedWorkDone() while the next play call could already be armed.
3. At heavy settings, that meant the tiny blit was repeatedly queued behind the next heavy segment instead of immediately after the segment whose frame it was meant to show.
4. Result:
   - L6: occasional black flicker / missed visible frames.
   - L7: the canvas could stay black under continuous play until pause/drag forced a standalone redraw path.

This is separate from the earlier fixed bugs:
- not the old frameIn self-copy invalid encoder bug,
- not the old readPixels empty-view bug,
- not the readback texture usage bug.

Fix applied
1. js/ui.js
   - GPU play path now keeps gpu.busy through:
     - GpuSim.play(...)
     - queue drain
     - standalone redraw of the latest buffers
     - second queue drain
     - canvas present
   - The steady-play “presentWhenDrained() every rAF” path was removed.
   - The merged branch now only suppresses duplicate same-frame redraw work.
   - GPU step button path was aligned to the same redraw-after-finish, then present ordering.

2. bench.html
   - smooth measurement now also waits for play work to finish,
   - redraws the final world state,
   - waits for that redraw to drain,
   - then presents,
   - and only then releases its busy flag / schedules the next tick.

3. tests/gui.js
   - updated to pin the new contract:
     - while play is in flight there is no standalone redraw and no canvas present yet,
     - once play settles, the page redraws the latest buffers and then presents them,
     - rebuild still waits for the in-flight GPU work to settle.

Why this should fix the owner symptom
- The visible canvas is no longer refreshed from a callback that can be overtaken by the next heavy segment.
- Instead, the page waits for the heavy segment to finish, redraws the current buffers on a tiny standalone pass, then presents that completed redraw.
- So a heavy config should now freeze or run slowly when necessary, but it should not stay black.
