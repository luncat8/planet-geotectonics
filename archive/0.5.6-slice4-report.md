```
[3d] 3d gather 0.00 · land 0.00 · water 0.00 · rim 0.00 ms
```

Awaiting `collect()` (the 0.5.6-device-report fix) is not enough. `tsMs` starts at 0
and `ms[i] >= 0` is true for those zeros, so `tsLine()` prints `0.00` when collect
returned null or mapped an unwritten slot. The silhouette session is also k6 / 512×256:
on this GPU even a real query would round to 0.00 ms at two decimals, and it is not
the page default (ico k8, 2048×1024 canvas). Slice 4's gather ≤ 0.5 ms / draws ≤ 5 ms
gates cannot be scored from that line.

### 3. What this session changed (so the next trip produces a gate number)

- `Render3D` timestamp ring matches `GpuSim`: 4-deep, collect reads `(tsSlot+1)%4`,
  Uint32 pair decode, map failure self-disables. `tsValid` stays false until a map
  succeeds, so `tsLine()` is silent instead of lying `0.00`.
- `webgpu-smoke.html` fails if the ring is on and did not map; prints the k6 / 512×256
  line to 3 decimals; adds `§14.4 ico k8 2048x1024 hex|vertex` (gather, land, water,
  rim, draws sum, MET/MISS). A missed gate does not fail the smoke — SwiftShader will
  miss; an unmapped ring does.
- Stub + `tests/render3d.js` pin the ring, the slot formula, the decode, silent-until-valid,
  map-failure disable, and a 100-frame timestamped loop that allocates nothing.

Default stays `hex`. The next owner-rig `webgpu-smoke.html` is the number that moves it.
