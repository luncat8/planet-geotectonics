# 0.8.2 — development log: the deterministic Earth-start section bake

Implements `0.8.2-plan-slice-bake.md`. One commit series on top of `0b10d68` (the 0.8.2 tool,
tests and docs). The review is `0.8.2-review.md`; this file is the log: what was done in order,
what was measured, and the handoff package the slice side's Phase B-b consumes.

## 1. Steps, in order

1. **Interface first.** `tools/earth/bake_section.js` takes `--start --level --seed --preset
   --circle --out` with optional `--built --commit --report --force`, exits 0 on a written pack
   and 2 on any refusal, and prints the plan's release line. Argument parsing lifts `--circle`'s
   three values out of the token list before the generic flag loop, supports `--flag=value`, and
   names the offending flag in every refusal.
2. **The load order.** Every `js/data/earth-*.js` is required first so `global.EarthPacks`
   registers exactly as `index.html`'s script tags do, then `Grid`, `State`, `Params`, `Earth`,
   `Slice`, `SlicePack`. `Earth.pick` resolves the start; no filename switch exists anywhere.
3. **The circle.** `--circle lat lon azimuth` steps one degree along the codec's own geodesic
   (`SP.directionAt` on a synthetic circle path) and hands the two points to
   `Slice.circleThrough`, so the CLI's path object is the browser's path object. The derived
   `az0` is checked against the request with a wrapped difference (azimuth 300 legitimately
   comes back as −60).
4. **The write.** `Slice.pack` on the fresh state with level-mode sea at `Params.sea`,
   provenance from the resolved pack and preset, and the pack's own licence string; then
   `SP.validate`, `SP.verify`, `SP.encode`, and only then `fs.writeFileSync`. `bake()` is pure —
   no filesystem, no exit — so the CLI's only remaining failure mode is I/O.
5. **Tests.** `tests/slice-bake.js`, added to the short profile between `heightfield` and `perf`.
6. **Corpus.** Two L5 examples into `data/sections/` with `data/sections/SOURCES.md`, generated
   at revision `0b10d68` with an explicit `--commit`, reproduced byte-for-byte by the test.
7. **Release constant.** `js/slice.js`'s `COMMIT` placeholder replaced with `0b10d68…`, gated by
   a test that fails on the placeholder.
8. **One behaviour fix outside the new files.** Earth-start section provenance in `js/ui.js` is
   preset-aware (§3).

## 3. Findings that changed the work

- **`built` is outside the v2 checksum** (`canonical(pack, false, false)`), so a one-byte edit
  inside `source.built` is refused by nothing. The first corruption test failed there; the
  suite now targets payload bytes and records why. Not a codec defect — a re-stamp must not
  change an identity — but it is a property a reader has to know.
- **Earth provenance overclaimed.** `js/ui.js`'s `sectionProvenance` returned
  `rotModel: 'PALEOMAP'` for every Earth start, including the game preset where `Earth.apply`
  holds zero omega and the procedural mantle drives the plates. Now preset-aware, matching the
  CLI, and pinned on both branches in `tests/gui.js`.
- **`--commit` was missing from the plan's interface.** A pack whose `source.commit` is a
  placeholder is anonymous, and the counterpart's B-b must record a globe revision per restored
  bundle. The flag defaults to `Slice.COMMIT`; the corpus was generated with the explicit
  revision and the test reads that revision back out of each file.
- **A corpus that cannot drift.** Deriving the arguments from the pack itself (start resolved
  backwards through `Earth.pick`, level/seed from `source`, preset from `rotModel`, circle from
  the stored path) makes the example self-describing, so loader/walker/writer drift turns the
  test red instead of leaving a stale fixture that still loads.
- **`js/data/` is refused outright**, not merely avoided by default — the plan's "never writes
  inside `js/data/` by default" is stronger as a flat refusal, and `out/` is now the documented
  ignored scratch location.
- **Zero potentials are asserted, not assumed.** The plate table is also asserted to account for
  every run, which is the t=0 truth and would catch a future change that introduces gap rows at
  initialization.
