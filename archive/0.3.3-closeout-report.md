## 1. Three harness bugs the captures exposed

1. **Every non-ASCII character in both logs was mojibake** (`В·`, `П‰`, `вЂ"`, `вЂ™` for
   `·`, `ω`, `—`, `’`). Node writes UTF-8 to the pipe regardless of the Windows codepage,
   but `run_common.run`'s `Popen(text=True)` decoded it with the locale — cp1251 on the
   owner's Windows — and re-encoded the wrong characters into an otherwise UTF-8 log. One
   `encoding='utf-8'` on that Popen fixes every runner (`run_full_test.py`,
   `run_gpu_parity.py`); verified end-to-end with a node child printing `· ω — ✓` through
   the same plumbing.
2. **`gpuBuild=undefinedms` in every ensemble capture since the driver learned the field.**
   `tests/gpu-parity.js` printed `gpuBuild=${report.gpuBuildMs}ms` unconditionally, but only
   the 1-frame `__run` rig ever set it — the ensemble (and the determinism rig) built a GPU
   world and reported no build time. The page's own label line was already conditional. The
   driver now matches it, and `__ens` records `gpuBuildMs` from the first seed's
   `GpuSim.init` — the cold WGSL build, comparable with `__run`'s number; later seeds
   rebuild on a warm driver cache. The next rig ensemble will log a real `gpuBuild=` and no
   `undefined`.
3. **`[page] Failed to load resource: the server responded with a status of 404` in every
   headless capture.** Chrome requests `/favicon.ico` on any http page; the drivers' static
   `serve()` had no such file and the 404 landed in the captured console as an unrelated
   error line. All four `serve()` copies (`tests/gpu-parity.js`, `experiments/gpu-bench.js`,
   `heavy-overlap.js`, `hud-reflow.js`) now answer the favicon with 204 No Content;
   everything else is unchanged (files 200, missing 404 — checked).

None of the three touches simulation code: the 22:48/22:47 numbers stand as captured.
