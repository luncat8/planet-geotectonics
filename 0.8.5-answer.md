## 2. The scheduling decision

**Accepted now, as globe release 0.8.5 — the globe-side section adapter.** The
globe's 0.9.0 remains climate integration; this adapter is the next increment on the
0.8 slice-exchange ladder, after 0.8.4's C-return (M1/M2 landed at `c1da62f`). It is
scheduled in two parts, because the request's own scope splits along the live gate:

- **Scheduled in 0.8.5 (§3.1–§3.5):** mount and dispose, first-pack startup, the
  geographic cut with display-side snapping, the paused/standalone clock, automated
  observation return for display only, and the staged cut-plane overlay. Delivery of
  a verified pack to the mounted section is a user-initiated, one-shot handoff —
  the hosted form of the manual rung — not a live channel.
- **Not scheduled, still gated:** streaming `COLCOUPLING.apply(msg)` handoffs and
  cadence `COLSECTION.applyClock(clock, rung)` delivery from the globe page
  (request §3.3's live reading), continuous C3/C4 reconciliation, and any feedback
  into a kernel. Those wait for the pair evidence and the gate-7 review that
  0.8.4 §5 M3–M5 already own (§5). A mounted adapter that can start from a pack
  and file observations does not open them by implication, and the adapter's UI
  must say `standalone` whenever no live rung has answered — the section's own
  banner fields (`COLSECTION.syncLive` / `syncStale` / `syncPaused`) are the
  display, unchanged.

Clipboard/file remain the contract transport and the debugging escape hatch at
every milestone. No `postMessage` rung, no server, no vendored copy of either
engine is introduced by this release.

## 3. Answer per requested scope item

Request §3/§4 items, in their order. Each row names the globe-side decision and the
milestone that carries it; "amendment" means a slice-side public-surface addition to
`0.9.0-contract.md`, implemented and pinned by their namespace harness §E after this
answer, per the request's own next step.

### 3.1 Construct and dispose the section — accept, with the layout below

The adapter lives in the globe's existing page (`index.html`), not a new page: the
request's cut-plane overlay and picker are operations on the globe's map, and a
second page would fork the map. The slice engine is **not** loaded at page boot.
Opening the host panel lazy-loads the slice's canonical classic-script set, in
`columns.html` / `library.html` order, from a configured tree (§3.4), then calls
`COLUI.build(mount)` and `COLSIM.start(mount)` with the mount inside an open
ShadowRoot — the rehearsal's own isolation answer, adopted unchanged. The shared
`SlicePack` and `CoreLogFormat` scripts are the page's existing single loads
(`index.html` already loads both); the loader must detect them present and never
inject a second copy under any name (contract §8). One active section, the
singleton the library is; `COLSIM.stop()` plus removing the mount disposes it, and
a later open restarts cleanly, as their harness already proves a restart does.
Host-local CSS for the chrome ids lives in the ShadowRoot; the globe's own
stylesheet is untouched by section rules.

### 3.2 Choose the geographic cut — accept as globe display-side work

The picker, the line, the 3D view and the camera stay globe-side, as they already
are (`js/ui.js` section tool, `Slice.circleThrough`, the `#slice-overlay` canvas).
Equal/antipodal second points are already refused with the origin kept; that
behaviour is the contract the adapter inherits, and its test is already in the
cutter suite. Snapping — perpendicular to the nearest boundary, along local plate
motion — is accepted as a display-side computation over fields the globe already
reads for its own writer (`state.edgeType`, the exported `vt`/`vp` resolution in
`js/slice.js`): it moves the *pending second point* before `circleThrough` runs,
never a kernel, never a state field, and the unsnapped point remains one click
away (snap is a modifier, not a silent rewrite). Snap semantics get their own
overlay/picking tests at A3 (§5); no snap ships as an untested gesture.

### 3.3 Snapshot, clock, and the overlay surface — accept in part, stage the rest

**First-pack startup (amendment requested, A1).** The request is right that
`COLCOUPLING.apply(msg)` cannot mount an arbitrary pack. The globe asks the slice
for one public entry, working name `COLSECTION.loadPack(pack)`, final naming
theirs: it accepts a decoded `pgt-slice-pack` v2 object, proves it through the
shared codec (`SlicePack.validate` + checksum verify + its own path identity),
reconstructs the active section from it, and refuses a corrupt or foreign pack
without mutating the section already mounted — the same parse/validate-then-commit
order the globe importer uses. Accepting the decoded object (not JSON text) is
deliberate: the host page already holds the writer's object from `Slice.pack()`,
and a text round-trip would add a second spelling of the same pack inside one
page. Until this entry exists, the adapter's startup is limited to the baked
`SECTION_PACKS` bundles through `data-pack`, and the UI names that limitation
instead of reaching into `COLCOUPLING` internals. Baked-bundle startup is the
standalone mode, not a substitute claimed as selected-cut support.

The globe delivers the pack from its one existing capture path (CPU synchronous,
GPU drained-then-downloaded, `SlicePack.validate` before transport in `js/ui.js`);
an export that fails validation is never handed to the section, exactly as it is
never copied or saved today.

**Clock (accept, manual rung only).** On each user-initiated handoff and on
pause/resume, the adapter calls `COLSECTION.applyClock(clock, rung)` with the
active pack's `pathChecksum`, the globe's `tMyr`, and the `paused` bit set from
the globe's actual playback state. It does not stream cadence messages, and it
never calls section controls to fake globe state: stopping the *section's* loop
is `COLSIM.stop()` and nothing else, per the contract's own warning.

**Cut-plane geometry and palette (amendment requested, staged to A3).** The
smallest read-only output contract the globe can consume, proposed for the slice
to name and pin: one call, working name `COLSECTION.overlay()`, returning a fresh
plain object per call —

```text
{ pathChecksum, packChecksum,
  palette: { lith: [<6 CSS colours, CoreLogFormat.LITH order>],
             host: [<5 CSS colours, SlicePack.HOSTS order>] },
  segments: [{ sKm, lith, host }, ...] }   // one per exported run, sKm ascending
```

`lith` is the run's dominant section lithology, `host` its `SlicePack.HOSTS`
index; both are indices into vocabularies the shared codecs already own, so no
new vocabulary crosses. Geometry is **not** in the export: the globe owns the
path, and `SlicePack.directionAt(path, sKm)` — already shared, already what the
globe's overlay painter uses — places each segment on the map through
`MapView.project`. The globe draws a quad strip on the existing `#slice-overlay`
canvas between successive segment positions, coloured
`palette.lith[segment.lith]`, and drops the strip the moment the returned
identities stop matching the current export (stale overlay is worse than none).
Colours come from the section's own renderer table, so globe strip and section
view agree by construction; the agreement test (§5) compares them rather than
re-declaring hex values on this side. No private renderer or bed-array read is
used or requested. The overlay ships at A3, after the A2 mounting rehearsal —
the staging the request itself offers — and the contract may instead return the
same shape under a slice-chosen name; the shape, not the name, is what this
answer fixes.

### 3.4 Resource layout on `file://` — decided

Development: the two checkouts are siblings, and the host page loads the slice
tree by relative path — the same convention the globe's climate plan (§5) already
adopted for its own hosting. The adapter's one configuration object (one new page
global, per this repository's rule) is

```text
SectionHost = { sliceBase: '../planet-tectonics-2d-slice/', mount: null, pack: null }
```

with `?slice=<relative-base>` overriding `sliceBase` for rehearsals against a
non-sibling tree. Script URLs are `sliceBase + <path>` built once at open; no
runtime `fetch`, no network, no server, and the page still boots and runs the
whole globe with the slice tree absent — the host panel reports the missing tree
by name and the rest of the page is untouched. Release: a release that ships the
adapter vendors the slice tree **unmodified** under `vendor/slice/` with a
provenance note (source revision + per-file hashes), following this repository's
existing `vendor/` convention and the contract's no-vendoring rule read
correctly: vendoring a *recorded, unedited* tree is distribution, the ban is on
copied-and-diverging code. Selecting the vendored base is the same `sliceBase`
value pointed at `vendor/slice/`; no code path differs. Shared `port/` files are
loaded once from the globe's own `port/` in both layouts (byte-identical, §1).

### 3.5 Return observations for display only — accept, ack surface agreed

The globe importer the request cites already exists and is the adapter's only
return path: `CoreLog.importText` (`js/core-log.js`) parses and validates into a
temporary, compares `pathChecksum` / `packChecksum` / `arcKm` against the current
export through the shared `CoreLogFormat.identity`, commits atomically into the
frozen side table, and never touches `State`, grid, checkpoint, GPU buffers or
clock. What is missing is the section-side active exporter and the
acknowledgement wiring, so the globe agrees this surface (amendment, A1):

- Slice adds one public exporter, working name `COLCORELOG.exportActive()`:
  returns `{ text, pathChecksum, packChecksum }` for the active section's due
  log, or `null` when nothing is due. It is the active-host spelling of the
  existing `COLCORELOG.build(state, opts)` + `COLCORELOG.json(msg)` pair; the
  low-level pair stays engine-internal for hosts.
- The adapter passes `text` to `CoreLog.importText` against the current export
  artifact. Acknowledgement maps one-to-one onto the importer's existing
  statuses, and `COLCORELOG.note()` — the commit-on-acceptance call — is made
  **only** on a commit:
  - `current` (committed): call `note()`, panel shows the filed log as current;
  - `confirmation-required` (same path, different `packChecksum`): show the
    stale reason and ask; on confirmation re-import with `confirmStale`, then
    `note()`; on refusal do not call `note()` — the log stays due on the
    section side, which is its designed reading;
  - `foreign` (different path or arc): refuse with the reason, no `note()`,
    previous filings untouched.
- No path from the adapter calls `note()` speculatively, and no observation —
  filed, stale or refused — is read by any globe kernel, ledger or export. The
  manual core-log panel (paste + `.json` file) stays as the fallback and the
  debugging path, driving the same importer.

### 3.6 Keep the fallback — accept, unchanged

Clipboard/file remain the contract at every 0.8.5 milestone; the hosted rung is
additive UI over the same verified payloads. Nothing in 0.8.5 bumps, edits or
re-interprets `pgt-coupling` v1, `pgt-slice-pack` v2 or `pgt-core-log` v2, and
`port/slice-format.js` / `port/core-log-format.js` bytes do not move.
