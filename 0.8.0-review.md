# 0.8.0 review — local v2 exchange foundation

## Verdict

The globe-side foundation is ready for the coordinated cutover. It is not yet a completed
cross-repository 0.8.0 release: `planet-tectonics-2d-slice` at reviewed revision `fd044e19f` still
ships `pgt-slice-pack` v1. The compatibility gate closes only after that repository copies the
three shared artifacts byte-for-byte, regenerates its fixtures/bundles, and reports a successful
fixture reconstruction.

No cutter UI, Earth section bake or live channel is enabled by this increment. That is deliberate:
`0.8.1` still waits on reader acceptance of the contract.

## Review decisions that tightened the plan

### Fractional sea level versus integer elevation

The draft gap rule said `zM = sea.levelM`, but `zM` is an `i32` and volume mode solves a generally
fractional water level. The portable rule is now `zM = Math.round(sea.levelM)` after the shared
six-significant-digit quantisation. `SlicePack.setGap` and validation own that rule, so the globe
writer and section reader cannot choose different coercions.

### Platform-independent identity bytes

The old codec hashed native typed-array memory. That is compact but makes byte identity depend on
host endianness and gives adjacent metadata strings no explicit structural boundary. V2 hashes the
UTF-8 bytes of a compact, fixed-key-order canonical JSON projection behind a domain line:
`pgt-slice-pack-v2` for the full artifact and `pgt-slice-path-v2` for the geographic line.

The full projection includes all semantics except `source.built`; the path projection excludes
`cellKm` because source resolution is not geographic identity. Both remain non-cryptographic
FNV identities for equality/corruption detection, not signatures.

### Validation before coercion

`decode` proves exact object keys, required strings, scalar types/ranges, raw JSON arrays, integer
integrality/ranges, path geometry, run spans, host law, boundary/polarity consistency, canonical
gaps and plate-table counts/references before constructing typed arrays. This closes v1's
normalize-first holes: a missing array is not zero-filled, and fractional `u8`/`i8` values are not
silently truncated. The public lifecycle is deliberately narrow: readers call `decode`; writers
call `make`, fill fields, then `seal` and `encode`. There is no public normalize-first v1 path.

Every sample plate id must exist in the ordered table, including gap id zero; `plates[].n` counts
only live samples. Unknown semantic fields require a future format version instead of disappearing
from the checksum.

## Tests

`tests/slice-format.js` covers:

- canonical decode/encode stability and the pinned identities;
- every source metadata field, path, sea, plate, license and payload checksum group;
- the intentional `built` and `cellKm` identity exclusions;
- malformed raw arrays, non-integral codes, missing/unknown fields and explicit v1 refusal;
- canonical gaps, exact host thresholds, all boundary conversions and plate cross-validation;
- directed great-circle construction, closure, coincident/antipodal refusal and reserved polyline
  geometry.

## Required counterpart handoff

The slice agent should use `0.8.0-slice-agent-prompt.md` and:

1. copy the three `port/` artifacts without editing them and make its local hash check pass;
2. replace v1 rather than retain a compatibility branch;
3. route paste, file and bundled packs through the one strict v2 decoder;
4. regenerate v1 fixtures and `SECTION_PACKS` through the v2 writer path;
5. decode the pinned fixture, reconstruct it, and return the section state hash plus any schema
   ambiguity.

Only that report can change the verdict from “globe side ready” to complete. If the counterpart
finds a real contract defect, both repositories take one deliberate port bump; neither side forks
the shared file locally.
