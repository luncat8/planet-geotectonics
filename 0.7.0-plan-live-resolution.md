# 0.7.0 — live resolution: conservative state transfer

Continuing a running world on another icosphere level. The page's Resolution select currently
rebuilds the world from scratch (`js/ui.js` `rebuildWorld`): a new `Grid`, a new `State`, the
start pack re-applied and every ledger discarded, because `Earth.apply` seeds fields from a pack
and knows nothing about a live Lagrangian world. This plan replaces that for a *running* world
with an explicit conservative transfer, and keeps the rebuild path for a change of start, seed
or pack.

Scope: L5 ↔ L6 ↔ L7 on both engines. `?level=` stays startup configuration. Out of scope: L8
(0.7.1), any physics change (0.7.2), Earth pack re-bakes, checkpoint-blob compatibility across
levels (a blob carries its level and is refused at another one - `js/checkpoint.js`).

## 1. What a level change means

The crust is not on the grid. It lives in Lagrangian columns that carry their own area, thickness
and plate-frame direction; the grid is the frame for neighbours, boundaries, topography, erosion
and render (design §2, `0.1.5`). A level change therefore moves the *frame*, not the material:

- A coarser level has fewer cells, so several columns end up in one target cell and must
  aggregate. A finer level has more cells, so one column's footprint spans several target cells
  and it must split. Both directions are a re-partition of the same material, and both are
  defined below without interpolating thickness.
- Nothing is advected on the grid, so no step of the transfer may read a grid-indexed
  transport field (erosion inflow, sediment routing) as material. Those are derived.
- Elevation, wet/dry and every boundary classification are functions of the columns, so they are
  recomputed on the new lattice rather than carried. A carried `z` would be a second source of
  truth and the first step would contradict it.

## 2. Inventory

Every field of `State` is in exactly one class. `Resolution.inventory(state)` reports this table
as data (`{ group, fields, class, bytes }`) so a test fails when a new state field is added and
not classified.

| Class | Rule |
| --- | --- |
| **material** | Area-weighted volume is conserved exactly, per family (`hFel`, `hMaf`, `hSed`). |
| **per-column** | Intensive quantity of a column. A shard of a column carries the parent's value unchanged. |
| **plate** | Plate-table entry. Copied verbatim; plate ids, quaternions and ω are the same world's. |
| **world** | One value for the world. Copied verbatim: time, RNG, timers, counters, ledgers, mantle tables. |
| **re-derived** | Function of the columns and the frame. Rebuilt on the target grid, never carried. |
| **scratch** | Per-step working memory. Zeroed; the next step fills it. |
| **view** | Renderer/UI only. Released and rebuilt by the caller (§6). |

## 3. The conservative remap

### 3.1 Definitions

- Source grid `Gs` (level `Ls`), target grid `Gt` (level `Lt`). `A0ref_s = 4πR²/Vs`, likewise
  `A0ref_t`. The sim's mass ledgers count every column with the nominal footprint `A0ref`
  (`js/diag.js`), so conservation is defined on `A0ref × thickness`, not on the varying `A0`.
- A source column `i` has a world direction `w_i` (unit vector) and a plate `p_i`.
- `nearestColumn(Gs, d)`: the source column that owns direction `d`. Seeded from
  `Gs.lookup` (the grid's own nearest-cell raster, best of four texels) and climbed with
  `Column.climb`-style strict improvements; the search covers the owning cell's bin plus its two
  rings, which is the widest neighbourhood a column can own.
- The **shard map**: `srcOf[c]` for every target cell `c` is the nearest source column to the
  target cell's own centre direction `d_c`. This is well defined for every target cell and is
  what makes the target frame complete: no target cell is empty, so no gap is manufactured by
  the transfer itself.
- `share_i = |{ c : srcOf[c] = i }|`, the number of target cells a source column feeds. A source
  column that no target cell picked is appended to its own nearest target cell
  (`dstOf[i]`) with `share_i = 1`, so no material is dropped at either direction of a change.
- The **cell shard map** `scOf[c]` is the nearest source *cell* to `d_c`, used only for
  grid-indexed mobile sediment (§3.4).

### 3.2 Material

For each family `m ∈ {Fel, Maf, Sed}` and every covered target cell `c`, the contributors are the
source columns whose shard includes `c` (`srcOf[c]`, plus any forced column placed there). The
target thickness is the area-weighted mean over contributors, with weight `w_i = A0ref_s / share_i`:

```
h_t[c, m] = Σ_i w_i · h_s[i, m] / Σ_i w_i
```

A cell with one contributor copies its parent's value bit for bit, so an unsplit child is exactly its
parent. The count-share sum `h_t = A0ref_s · h_s / (share_s · A0ref_t)` is not used: for L5→L6 the
footprint ratio is 4 while `share` varies from 2 to 7 per column, so a split child's thickness would
depend on how many cell centres happened to fall in its footprint, a ±50 % stripe across the map.
The mean keeps every child on its parent's thickness.

The mean does not conserve volume exactly, because two tessellations are not nested. The difference
is booked to the ledger's `regrid*` terms and reported (§4.3). Volume is conserved in the ledger; the
field's volume is not, and the size of that gap is the open question in §4.3.

### 3.3 Per-column scalars, plate frame and anchors

- `age`, `fert`, `damage`, `zDyn`, `oVms`…`oPla` are copied from `srcOf[c]` value for value. They
  are intensive; the shard is a piece of the same material, so an area-weighted mix would invent
  a gradient across one column's own footprint.
- Plate identity: `plate_t[c] = plate_s[i]`. No plate is renamed, merged or retired by a level
  change, and `plateCells` is recomputed by the coverage pass.
- Plate-frame placement: `world_t[c] = d_c` and `body_t[c] = q_p⁻¹ · d_c` (conjugation via
  `Quat.rotateInv`). Two consequences are the point of the rule: the crust does not move at the
  switch instant (`|world_t[c] − d_c| = 0`, `rigidError = 0`), and each column rides the same
  plate quaternion it rode before, so subsequent motion is the same rigid motion.
- **Anchors.** Deposit identity is an integer hash of the *quantized plate-frame direction*
  (`Deposits` `anchorKey`, `BODY_SCALE = 32768`), so a shard's anchor key is not
  bit-preserved when the lattice changes: the column now sits at its own new cell's pullback,
  which is within one source-cell radius of the parent's anchor. This is inherent - a level
  change re-lattices the frame, and two levels do not share anchors. The rule that keeps
  identity stable is therefore at the record level (§5.1), not at the column level. The transfer
  measures and reports the drift (§7, `anchorDrift`): bounded by one source cell radius, and zero
  for a column whose own cell survives the change with the same direction.
- A record in a session ledger is never re-derived from a live column: its `anchorKey` and
  `direction` are stored on the entry when it is first found (`setAnchor`), and the transfer
  does not touch them.

### 3.4 Mobile sediment

`mobile`, `mobileFel` and `mobilePla` are grid-indexed because they are being routed one hop at a
time. They are material, so a level change spreads each source *cell*'s load over the target
cells that picked that cell, with the same share rule scaled to the target footprint:

```
mobile_t[c] = A0ref_s · mobile_s[s] / (count_s · A0ref_t)     s = scOf[c], count_s = |{c : scOf[c] = s}|
```

`Diag.mass` adds `Σ mobile` before multiplying by `A0ref`, so this keeps total sediment volume
exact through the change. A source cell with `count_s = 0` keeps its load by the same append rule
as §3.1.

### 3.5 Re-derived fields

On the target state, in this order, with no `Sim.step` and no `Sim.plates` solve:

1. `Mantle.update(dst)` - `uMantle` and `plumeT` are the mantle field sampled on the new cells.
   The mantle's own state (`wave*`, `plume*`, `Tm`, `mantleScale`, `rng`) was copied, so the
   field is the same field.
2. `Columns.bin`, `Columns.raster` - owner, distance, `cellPlate` and `gaps`.
3. `Surface.elevation(dst)` - `z`, `wet`, `gradZ`, `slope`, `low` from the transferred columns.
4. `Edges.velocities`, `Edges.classify` - relative velocities, edge type, polarity, `trenchDist`.
5. `Diag.check` - `mass*`, `oreSum`, `rigidError`, `quatError`, `finite`, history ring.

`belt` (the collision/transform ore belt) is deliberately not carried: it is a one-ring dilation
of the current boundary set, and the classification above recomputes the boundary that defines
it. Carrying it would leave a belt where the new frame says there is no boundary.

`zDyn` is per-column and is carried; `zDynNext`, `collapseDelta`, `collapseDeltaSed`, the erosion
scratch and all routing buffers are per-step scratch and start zeroed.

## 4. Invariants and tolerances

### 4.1 Ledgers

`massFel`, `massMaf`, `massSed` and the `*0` baselines are volumes, so they are carried verbatim
and then recomputed by `Diag.check`. Gate: recomputed equals carried to `1e-12` relative, and
equals the source's value to `1e-12` relative. `producedFel`, `erodedFel`, `subductedMaf`,
`subductedArea` are cumulative totals in the same volume unit and are carried.

The field volume residual is a physics question, not a bookkeeping one: a level change must not
create or destroy crust, and a booked residual does exactly that in the field while leaving the ledger
closed. Whether to remove it (a global conservative scale, or an overlap-weighted remap) is decided
before the page action is treated as final.

### 4.2 What the transfer must not do

- No time advance and no RNG draw: `t`, `frame`, `rng`, `lastEvent`, `ckptDue` are copied. A
  transfer is not a step, and a level change that consumed one event cadence would make two
  otherwise identical runs diverge by a step.
- No new crust: `producedFel/producedMaf` do not move, no column is spawned by the transfer, and
  `alive` is exactly one per target cell.
- No discarded column: every source column's material is placed, and `share_i ≥ 1` by the append
  rule.

### 4.3 Measured tolerances (short profile)

| Quantity | Tolerance | Why |
| --- | --- | --- |
| Ledger identity `massFel0 + produced + regrid − massFel` (and maf) | `≤ 1e-12` relative | The booking closes the books by construction |
| Field volume residual, source vs target | reported, budget `< 5 %` per change | Two tessellations are not nested; measured 0.5 % fresh, 3.9 % on a stepped L5→L6 world |
| Target coverage | `gaps = 0`, one column per cell | Shard map is total |
| Plate frame error after transfer | `rigidError = 0` | `body = q⁻¹world` by construction |
| `t`, `frame`, `rng`, `lastEvent` | exactly equal | Copied, never stepped |
| Anchor drift | `≤` one source cell radius, and 0 for surviving cell directions | §3.3 |
| Round trip L5→L6→L5 thickness RMS | reported, not assumed | Two shard partitions are not inverses; the report states the number |
| Forward equivalence | `z` RMS after 50 steps from the transferred world vs the same 50 steps from the source world, both at L5, reported against the same two worlds after a *no-op* transfer | A transfer is a re-lattice, so equality is not promised; the gate is that the drift is the lattice's, not a lost half of the world |

The two equivalence numbers are reported, not gated at zero: this is a re-lattice, and a test
that demanded bit-equality after a level change would be asking for an interpolation that does
not exist. The gate is that the class-level structure (continent/ocean area, plate count, mean
speed, mass) is inside the short-profile budget the source world itself holds.

## 5. Identity: what survives a level change

### 5.1 Session ledger

`Instruments.Ledger` holds `coverage` (per-cell instrument mask), `cells`/`cellsN` (cells with
coverage), `found` (entries), `byId`, `byRecordCell`, `bySurveyCell`, `sampleSeen`, and per-entry
`cell`, `surveyCell`, `anchorKey`, `direction`, `id`.

- Entries are carried **verbatim**: same ids, same `anchorKey`, same `direction`, same serials,
  same found order, same confidence, drills and grade bands. A level change is not a re-survey.
- `cell` and `surveyCell` are grid indices, so they are re-derived from the entry's stored
  `direction` through the target grid's lookup + climb; `byRecordCell` and `bySurveyCell` are
  rebuilt from the new indices. Gate: every entry still resolves to a cell whose centre is within
  one target cell radius of its stored direction.
- `coverage` is re-laid by the cell shard map: a target cell inherits the source cell's mask when
  the source is coarser (a survey of a coarse cell covers the finer cells inside it) and takes
  the OR of the source cells inside it when the source is finer (a coarse cell counts as surveyed
  where any part was). This can only add coverage, never remove it, which is the conservative
  direction for a record of what has been looked at; the report states the added cells
  (`coverageGain`) so the over-claim is measured rather than hidden.
- `sampleSeen` is per-step scratch and is zeroed.
- The catalogue cache (`Deposits._cache`) and the campaign view are invalidated, not transferred:
  their records were built on the source lattice's cells. The ledger's own records keep their ids.

### 5.2 Pins and selection

A pinned deposit is held by `id`, and ids are carried, so a pin survives. A campaign in flight is
cancelled by the transfer (it samples cells of the old grid); the caller must call it out in the
UI rather than let a stale job write into the new world (§6).

### 5.3 Checkpoint ring

Dropped and restarted: `ckpt = null`, `ckptSlots = 0`, `ckptI = ckptN = 0`, `ckptDue` carried.
The ring is a scrub cache of whole-world blobs, each stamped with the level it was written at;
`Checkpoint.load` refuses a level mismatch by design. Save-to-file is unaffected (it writes the
current world at the current level).

## 6. Transaction

Surface (CPU engine): a Resolution change on a running world is offered, not performed. The
select shows the new level and two actions name it: keep the world (this transaction) or start a
fresh world at that level (the rebuild path, which discards the ledger). A fresh world (no step
taken yet), the GPU engine and a live Reconstruct scrub rebuild as before. The GPU device path is
slice 4.


`Resolution.transfer(src, grid)` never mutates `src`. It allocates its own `State` and its own
work arrays, transfers, re-derives and validates; the caller decides to commit. Nothing in the
transfer writes to a live renderer, a GPU buffer, the ledger or the DOM.

Commit is the page's, and it is a swap, not a mutation of the old world:

1. Stop the frame loop and drain an in-flight GPU transfer (`whenGpuIdle`).
2. Cancel a running campaign and release the deposit cache.
3. Swap `grid` and `state` (the caller's own module-level variables).
4. Rebind the view: `Renderer` (CPU), `GpuSim.init` + `GpuRenderer` (GPU), the 3D height
   lookup (`v3dLookup = null`, rebuilt on the next 3D frame), the marker overlay and the water
   histogram (`waterDirty = true`).
5. Re-lay the ledger (§5.1) and repaint the probe, badge, grid line and ledger rows.

A failure or a cancel before step 3 leaves the old world fully usable, because nothing was
written into it. Peak memory holds both worlds at once, so the action is confirmed and reported
with the two sizes; at L7 a `State` is ~120 MB of column and plate tables plus the device arenas,
and the UI must not offer the action on a world whose target level does not fit the reported
adapter limits (that check belongs to 0.7.1 for L8, but the confirmation shows the numbers now).

## 7. Report

`Resolution.transfer(src, grid)` returns `{ state, report }` with, at least:

`levelFrom`, `levelTo`, `columnsIn`, `columnsOut`, `shards` (share histogram),
`volume: { fel, maf, sed, mobile }` source/target/relative error,
`mass` source/target/max relative error, `gaps`, `rigidError`, `anchorDrift: { max, mean, kept }`,
`coverageGain`, `time`, `rng`, `frames`, `plateCount`, `bytes`.

`experiments/` gets no new script for this: the numbers are cheap, they belong in the test log,
and the report is what the UI prints in the confirmation line.

## 8. Staging

1. **Kernel** - `js/resolution.js`: inventory, shard maps, material/per-column/plate transfer,
   re-derivation, report, `tests/resolution.js` (short profile).
2. **Ledger** - `Resolution.ledger(ledger, grid)`: cell re-derivation, coverage re-lay, index
   rebuild; gates in `tests/resolution.js`.
3. **Page** - the live resolution action on the CPU engine: confirmation, progress, commit swap,
   renderer and water rebind, ledger re-lay; GUI coverage in `tests/gui.js`. Startup rebuilds
   stay for start/seed/pack changes.
4. **GPU** - the device path: re-init arenas at the new level, upload the transferred state, and
   the L6/L7 rig gates (no owner-GPU claim from a sandbox run).

Slices 1-2 are testable in this sandbox and on the owner rig alike. Slice 4 needs the owner rig;
no CPU or stub run establishes a device claim.

## 9. Not this increment

- **No thickness interpolation, no field smoothing, no visual filter on transfer.** A transfer
  is a re-partition, and the earth data tracks (0.4.8) stay the only place a field is fitted.
- **No automatic level change.** Nothing in the sim or the loaders may call the transfer; it is
  an explicit action with a confirmation.
- **No checkpoint migration.** The ring restarts (§5.3).
- **No drift claim for a re-derived catalogue.** `Deposits.build` at the new level produces
  records on the new lattice; the ids of records that live only in a catalogue are not promised
  stable across a level change, and the plan says so rather than pretending otherwise.
- **L8.** The 655,362-cell level stays behind the memory gate in `0.7-proposed.md`.
