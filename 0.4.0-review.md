# 0.4.0 review — defects and hot paths in the 0.3.3 tree

Audit of the release tree (`b940d56`, 0.3.3 closeout) as the base 0.4.0 builds on: what is
wrong, what was fixed, what is left. Written to stand alone — a fork or a reimplementation
should be able to apply this list without the session that produced it. Measurements are from
the Arena sandbox (2 cores, node 22.22.3, no GPU adapter) unless a log is cited; ratios carry
over to a real machine, absolute milliseconds do not.

## 1. Method

Read the whole CPU pipeline (state, sim, columns, column-update, plates, edges, contact,
events, surface, mantle, diag, extract, checkpoint, geodesics, render, ui, gpu/sim-gpu),
then measured the suspects with throwaway probes rather than by inspection:

- per-phase event-cycle timing and a counter for whole-grid passes inside `Events.cycle`;
- the column-compaction window: a probe that mirrors `Events.compact`'s own remap and reports
  every cell whose `owner` (cell -> column) was left pointing at the wrong column;
- heap and ArrayBuffer census per level (state, grid, checkpoint blobs);
- cost per call of `Renderer.ORE.indexOf(layer)` per cell and of byte-wise vs 32-bit paint;
- a digest harness that runs the same world twice — once with the module under test swapped
  for a reference copy — to prove a refactor changed no result.

## 2. Defects

### F1 — column compaction left `owner` a cycle behind (fixed)

`Events.compact` removes consumed columns by shifting every live column down and setting
`s.n = dst`. It rewrote every column array, but `s.owner` — the cell -> column map the rest of
the cycle reads — still held pre-compaction indices until the next `Sim.raster`. Everything
that runs between `compact` and the next raster therefore read *another column's* state.

`Events.split`'s corridor test is the sharp edge: `corridor[c] = damage[s.owner[c]] > splitDamage`
decides which cells are removed from the plate before its components are labelled, so for one
cycle after any column death the corridor was a shifted copy of the damage field.

Measured (L5, seed 7, 1000 Myr, 981 event cycles, every one affected):

| quantity | value |
| --- | --- |
| cell reads that landed on the wrong column | 9,493,680 |
| cells whose corridor classification (> `splitDamage`) flipped | 427,544 |
| cells whose owner pointed at an already-dead column | 0 |
| worst single cycle | 10,170 cells |

Fix (js/events.js): `compact` writes `remap[oldIndex] = newIndex` while it shifts, then remaps
`owner` for every cell once (`owner[c] = alive[o] ? remap[o] : -1`), so the derived map is
consistent from the moment the compaction ends. Cost is one pass over V per cycle.

The GPU path has the same map but not the same defect: the device never receives `owner`
(`EVENT_WRITES` is colF/colI/plateF/plateI/frameOut), and `raster` runs in the dispatch graph
before every kernel that reads it (`integrate, move, bin, raster, mantle, velocities, ...`), so
the device rebuilds the map before use. The fix is mirror-side only.

Consequence to own in 0.4.0 — the fix removes damage noise the split logic was unknowingly
consuming, so early rifting now needs real accumulated damage. First natural split per seed at
L5:

| seed | 4 | 1 | 2 | 7 | 11 | 13 | 5 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| first split (Myr) | 71.9 | 188.5 | 133.5 | 361.6 | none by 600 | none by 600 | none by 250 |

`tests/split.js`'s natural-run block was baselined on seed 11 / 150 Myr, which no longer split;
it is re-baselined on seed 4 / 200 Myr (split at 72, merge at 171, 2 splits + 6 merges total).
The fix delays early rifting rather than suppressing it: `longrun` reaches 1500 Myr with 75
splits and 75 merges (pre-fix log: 66/70) and the same 19.3 % continental area at 1500 Myr, so
the long-run regime is intact and the change is in the timing of the first few hundred Myr. The
prescribed-corridor tests (split opens, fossil corridor stays, suture, absorption, rebase) are
unchanged and all pass.

### F2 — the checkpoint ring was bounded in slots, not bytes (fixed)

`Params.ckptCap` = 16 slots, and a slot is a full-mirror blob:

| level | blob | 16-slot ring |
| --- | --- | --- |
| L5 | 2.66 MB | 42.6 MB |
| L6 | 9.87 MB | 158 MB |
| L7 | 41.13 MB | 627.6 MB |

At L7 the state's own ArrayBuffers are already ~258 MB, so the ring was the largest single
allocation in the app and grew with the level for no reason the parameter expressed.

Fix: `Params.ckptBytes` (96 MB) caps the ring by bytes. `State.ckptCap` stays the slot
request; the ring itself is now allocated lazily by `Checkpoint.push` on the first snapshot,
where the blob size is known, and `s.ckptSlots` records the chosen length (L5 16, L6 9, L7 2).
`ckptCap = 0` still disables the ring, and an explicitly set `ckptCap` is still honoured up to
the byte budget. Blob format is untouched — the ring is runtime state, never serialized.

### F3 — legacy packed grid buffers were retained for nothing (fixed)

`Grid.build` returned `cellA`, `cellB`, `nbrA`, `nbrB` (float32 W×H packs, ~2.5 MB at L5,
~36.7 MB at L7) and `indices` (3.9 MB at L7) from a WebGL draw path that no longer exists.
The flat tables (`pos`, `A0`, `ring`, `ringN`, `nbrDist`, `edgeLen`, `faceN`, `faceT`, `fluxN`,
`collapseWeight`, `gradInv`, `land`, `lookup`) carry the same numbers. The only consumer of the
packed buffers was `experiments/advection-bench.js`, which now reads the flat tables.

`A0` and `nbrDist` gained float64 precision in the process (they were float32 copies of exact
values); `tests/grid.js` is unaffected (its area tolerance is 1e-3 and the flux identity holds
to 1e-18 with the double-precision table).

### F4 — each plate was processed with whole-grid scans (fixed)

`Events.components(s, plate, thr)` cleared `compLabel` for the whole grid and then scanned all
V cells twice per call — and it is called once per plate by `split` and again by `orphans`, plus
once per component by `opening` (`Plates.dragFit` is itself a whole-grid scan filtered by
label). Instrumented: **48.7 full-grid passes per event cycle at L5**, ~24 `components` calls
per cycle, growing linearly with plate count — and the same count at L7 runs over 16x the
cells, which is why the cycle cost scales with V (44.8 ms vs 3.4 ms).

Fix: the event cycle now buckets cells per plate once (`Events.buckets`, two streaming passes
over V, invalidated by `frame` so a direct `Events.split()` call outside a cycle still finds a
list that matches the plate map — this is what `census` now ends with). `components`,
`assignRest`, `opening`, `split`, `orphans` and `dragFit` walk that bucket, in ascending cell
order, so the component numbering is exactly what the ascending whole-grid scan produced. Label
values are cleared per bucket instead of grid-wide; every reader is scoped to the bucket or
guards on `cellPlate`, which is what the old grid-wide clear guaranteed.

`compSize`'s 64-component cap stays per plate, so the orphan tally budget is unchanged.

A/B on the same world, back to back in one session, L5/seed 7/300 Myr (281 cycles): mean
`Events.cycle` 3.19 ms -> 2.42 ms (-24 %), `Sim.step` 15.28 ms -> 15.12 ms. The cycle is ~20 % of
the step at L5 with 13 plates, so the step gain is small there by construction; at L7 the same
passes run over 16x the cells, where the post-fix cycle profile is 36.3 ms of which `orphans`
20.1, `census` 8.2, `compact` 8.0, `buckets` 0.35 — the remaining work is in §4 P1/P2.

Absolute sandbox timings drift by ~1.6x between sessions (identical untouched tests: `quat`
39 -> 60 ms, `mantle` 169 -> 264 ms), so only same-session A/B pairs are quoted.

### F5 — renderer per-cell work (fixed)

`Renderer.draw` resolved `Renderer.ORE.indexOf(layer)` and ran a string-compare chain inside the
per-cell loop (1.68 ms per draw at L7 just for the six-element `indexOf`), and `paint` wrote the
1024×512 raster one byte at a time (2.8 ms vs 1.4 ms for 32-bit stores).

Fix: `Renderer.LAYER` maps the layer name to an integer mode once per draw, the ore potentials
become a mode range over `Renderer.ORE`, and `paint` writes `this.pixels` (a `Uint32Array` view
of the same `ImageData`) leaving the byte view untouched for the tests and the CPU path. A/B at
L7, mean over 12 layers plus one repaint: draw 11.48 -> 8.67 ms, paint 3.20 -> 1.54 ms, so a
draw+paint frame 14.68 -> 10.20 ms.

## 3. Verified

- **Behaviour of the refactors:** a state digest (hFel/hMaf/hSed/age/damage/fert/plate/cell/
  oOro/zDyn + plate tables, plus counts) is identical over 300 Myr at L5 between the current
  tree and a reference copy that carries only the F1 fix — F3/F4 changed nothing observable.
- **Renderer:** `colors` and `image.data` are byte-identical on all 17 layers.
- **Checkpoint:** the ring-wrap and round-trip tests pass with the new lazy allocation; L3 blob
  round trip still bit-identical.
- **Determinism:** `tests/determinism.js` compares a reset state against a fresh one; the new
  scratch buffers are zeroed in `State.reset` so that invariant holds.
- **Profiles:** the 26-test short profile is green, and all four histories pass on the fixed
  tree when run individually — `longrun` (1500 Myr: mid-epoch 9.34 cm/yr, 19.3 % continental,
  plates 6-40, 75 splits / 75 merges; dt pair within bounds), `ores` (arcNearTrenchNow 0.346,
  vmsOceanicNow 0.762, oroContinental 0.999, basinSediment 0.962), `alloc` (heap 55 KB,
  buffers 0), `kinematics` (rigid 0, quat error 2.2e-16, 1-10 cm/yr, mixed boundaries). The
  4.5 Gyr release profile and the strict 60 steps/s proxy remain owner-rig runs.
- **Cost, same-session A/B** (sandbox):

| quantity | before | after |
| --- | --- | --- |
| `Events.cycle`, L5/300 Myr/281 cycles | 3.19 ms | 2.42 ms |
| `Sim.step`, same run | 15.28 ms | 15.12 ms |
| whole-grid passes per event cycle | 48.7 | 2 |
| renderer draw+paint, L7 | 14.68 ms | 10.20 ms |
| checkpoint ring at the default cap | L5 42.6 MB, L6 158 MB, L7 627.6 MB | 42.6 MB, 88.8 MB, 82.3 MB |
| grid buffers retained per level | L5 ~2.5 MB, L7 ~40.6 MB | 0 |

## 4. Open items, in priority order

The event cycle is still the CPU-side hitch the GPU path pays per Myr, and the transfer, not the
kernel, now dominates it (`experiments/logs/0.3-II-roundtrip-cost.txt`: event round trip 3.71 ms
at L5, 18.92 ms at L6, both dominated by the mirror; scaling reaches ~75 ms per cycle at L7).
Ranked by expected gain per unit of risk:

- **P0 — re-prove the histories.** `kinematics`, `ores`, `alloc`, `longrun` are the release gate
  and F1 changes trajectories. All four were re-run on the fixed tree and pass with their
  numbers in place: `longrun` mid-epoch 9.34 cm/yr, continental 19.3 % at 1500 Myr, plates in
  the 6-40 window, 75 splits / 75 merges, invariant residuals exact and the dt pair matching;
  `ores` inside every ratio window; `alloc` 55 KB retained; `kinematics` rigid 0 — so F1 delays
  early rifting without changing the calibrated regime. What is left for the owner rig is the
  release profile (4.5 Gyr, 500 Myr at dt 0.01) and the strict 60 steps/s proxy. If the next
  calibration sweep says the early Myr are too quiet, treat it as a recalibration of
  `kDam`/`splitDamage`/`splitAge`/`kHeal` with `experiments/corridor-scan.js` and the
  `experiments/plate-*.js` rigs, not as a reason to touch F1.
- **P1 — take the census off the JS path.** `census` (8.2 ms per cycle at L7) is a reduction over
  boundary edges that the device already walks in `relatives`. Accumulate `pairLen/pairVel/pairOk`
  on the device (atomic add into a `plateCap²` array, ~196 KB) and download only pairs whose
  length is non-zero. That also removes `edges` from `EVENT_READS`, the largest block of the
  event round trip, and lets the JS `census` disappear.
- **P1 — orphans is the remaining hotspot** (20 ms per cycle at L7, 0.65 ms at L5). It calls
  `components(p, Infinity)` for every plate that passed a size filter, then walks all columns
  once per orphan component. Two cheap reductions: (a) walk the plate's bucket instead of
  `0..n` (the component's cells are known), and (b) when a plate's corridor is empty the
  `splitDamage` and `Infinity` labelings coincide — share them instead of computing both.
- **P2 — compact and buckets.** `compact` (8.0 ms per cycle at L7) rewrites every column even
  when nothing was consumed; a "no deaths since the last raster" fast path skips it. The bucket
  build is two streaming passes and already cheap (0.35 ms at L7).
- **P2 — checkpoint cadence.** The byte budget now caps memory, but at L7 it also means two
  snapshots. Scale `ckptEvery` with the level or store column deltas so a long L7 run keeps a
  usable history.
- **P3 — geometry tables.** `faceN/faceT/fluxN/edgeLen/nbrDist/gradInv` are float64 and read per
  edge per frame by `Edges.classify` (32 ms per CPU step at L7). A float32 mirror to match the
  device's `GRIDF` pack halves the footprint; the identity tests in `tests/grid.js` would need
  their tolerances stated in float32 terms, so do it only with a measured win.
- **P3 — GUI/test hygiene.** `Renderer.LAYER` must stay in step with the layer radios in
  `index.html` (17 names) — a table test over the two lists would pin it. The byte budget
  arithmetic (`ckptSlots = min(ckptCap, floor(ckptBytes / size))`) deserves one cheap assertion
  at L3 in `tests/checkpoint.js`.

## 5. Fix set applied on this branch

| file | change |
| --- | --- |
| `js/events.js` | F1 owner remap in `compact`; F4 `buckets` + bucket-scoped `components`/`assignRest`/`opening`/`split`/`orphans` |
| `js/plates.js` | `dragFit` optional bucket range (F4) |
| `js/state.js` | ring allocated on first push, `ckptBytes`, `ckptSlots`; event-cycle scratch (`colRemap`, bucket lists) zeroed in `reset` |
| `js/checkpoint.js` | lazy ring sized by the byte budget (F2) |
| `js/params.js` | `ckptBytes: 96 MB` (F2) |
| `js/geodesics.js` | packed `cellA/cellB/nbrA/nbrB/indices` removed (F3) |
| `js/render.js` | `LAYER` modes, 32-bit paint (F5) |
| `experiments/advection-bench.js` | reads the flat grid tables (F3) |
| `tests/split.js` | natural run re-baselined to seed 4 / 200 Myr (F1) |

Invariants a later change must not break: `owner` is the cell -> column map and must be valid
whenever any pass reads it between compaction and raster; component ids are numbered per plate,
ascending by first cell, capped at 64 (`compSize.length`), because `orphanTally` and the opening
buckets are indexed that way; the checkpoint ring is a runtime structure — nothing in the blob
format depends on it; `Renderer.LAYER` covers every layer name the UI can send.
