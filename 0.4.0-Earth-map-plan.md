# 0.4.0 — Earth map plan

Start the simulation from real Earth instead of the procedural land mask, and later from
real Earth at past epochs. This is the plan artifact: sources, formats, bake, loader, start
presets, tests, and the 0.4.5 hook. Nothing here is implemented yet; the code changes that
land *before* it are in `0.4.0-review.md`.

Constraints it has to respect (from `0.1.5-final-design.md` and `AGENTS.md`): the page opens
from `file://` with classic `<script>` tags and no build; no network at run time; the crust
lives on Lagrangian columns, so Earth data can only ever be an *initial condition* — never an
advected field; the CPU engine (L5) and the WebGPU engines (L6/L7) must both start from it.

## 1. What the sim needs from a start map

`State.reset` currently seeds one column per cell with `q = identity`, plate ids from nearest
Voronoi seed, and a procedural `land` mask: `hFel = 35 km` on land, `hMaf = 7 km` in the ocean,
`age = 500 Myr` / `U(0..120) Myr`. Elevation is then *derived* by K9:

```
z = -3342 + hFel/6 + (hMaf*350 + hSed*900)/3300 - thermal + zDyn
thermal = (1-ci)*350*sqrt(min(age,80)) + ci*2091,  ci = smoothstep(hFel, 5000, 20000)
```

So an Earth start is six per-column numbers plus a plate map:

| column | source layer | how it is used |
| --- | --- | --- |
| `hFel` | continental crustal thickness | inverted from bedrock elevation where continental |
| `hMaf` | oceanic crustal thickness | inverted from bathymetry + age |
| `hSed` | sediment thickness (GlobSed / CRUST1.0) | direct |
| `age` | ocean crust age grid; cratons for continents | direct (ocean), constant+noise (continental) |
| `fert` | fertility (derived: coast + sediment + type) | direct |
| `plate` | plate-id raster (PB2002) | direct, with `plateCount` |
| `q`, `omega` | — / MORVEL Euler poles | identity / real pole for "realistic" presets |

Everything else (damage, potentials, `zDyn`, histories) starts at zero or at the reset default.
The water surface is `z = 0` — the sim's physics keeps `wet = z < 0` regardless of what is
displayed (0.3.5 §0) — so the bake must invert isostasy such that the map's own sea level
lands on `z = 0` and the wet fraction comes out at Earth's 70.8 %. The draft's "ocean level
for proper colorize" is therefore a bake-time calibration, not a runtime knob: once Earth's
sea level sits on `z = 0`, the 0.3.5 sea controls ride the Earth start unchanged — the level
slider is display eustasy on the real map, and the volume slider's `V0` is the real ocean's
volume, so a `×` there reads as a true eustatic multiple of Earth's water.

## 2. Sources

Recorded with URL, version, licence and SHA-256 in `data/earth/SOURCES.md` at bake time; the
bake script verifies the checksums it is given and refuses to guess. Raw sources are **not**
committed (too large) — the baked pack is, so the app needs nothing.

| layer | first choice | fallback |
| --- | --- | --- |
| bedrock elevation / bathymetry | ETOPO 2022 (NOAA NCEI, 15″–1′, bed-rock and ice-surface variants, public domain) | ETOPO1 1′; GEBCO 2024 15″; SRTM15+ |
| ocean crust age | Müller et al. age grid (EarthByte, ~2′) | Seton et al. 2020 agegrid; synthesize age by inverting the sim's own subsidence (350·√age) from bathymetry |
| sediment thickness | GlobSed (Straume et al. 2019, 5′) | CRUST1.0 sediment layer (1°); synthesize from distance-to-coast + latitude |
| continental crust thickness | CRUST1.0 (Laske et al., 1°) Moho depth | Airy inversion of bedrock elevation |
| plate polygons | Bird 2003 PB2002 (vector, small, publicly redistributable) | hand-drawn boxes for the few plates split across the date line |
| plate motions | NNR-MORVEL56 Euler poles | MORVEL; last resort: zeros (the mantle flow drives the plates) |
| paleo checkpoints (0.4.5) | PALEOMAP PaleoDEMs (Scotese & Wright) | Müller et al. paleo-DEMs; GPlates rotation models (`.rot`) reconstructed forward from a modern base |

A bake that has only ETOPO available still produces a complete pack: age is inverted from
depth, sediment from a documented coastal-distance rule, `hFel` from Airy. The pack records
which fallbacks were used per layer, so a later re-bake with the real grids is comparable.

## 3. Pack format

One JS file per pack, so `file://` needs no fetch:

```js
// js/data/earth-05deg.js  — generated, do not edit
EarthPacks.push({ name: 'earth', epoch: 0, w: 720, h: 360, source: 'ETOPO2022+...',
  datum: -123.4, ocean: 0.7081, scale: { z: 1, age: 1, sed: 0.1 },
  banks: { z: '<base64>', age: '<base64>', sed: '<base64>', kind: '<base64>' },
  plates: { count: 52, ids: '<base64>', seeds: [...], poles: [...] } });
```

- Four banks per pack, raster order, row 0 = south pole, column 0 = 180° W, equirectangular:
  `z` Int16 metres (bedrock, sea level datum included), `age` Uint8 Myr, `sed` Uint8 × 0.1 km,
  `kind` Uint8 (bit 0 continental, bits 1-3 fertility quartile, bit 4 from-fallback).
- `plates.ids` is the same raster quantized to Uint8 plate ids (255 = unassigned → nearest id);
  `seeds` are unit-vector centroids so the renderer and `Raster`'s tie-breaks behave as they do
  for procedural plates; `poles` are `[axisX, axisY, axisZ, radPerMyr]` (MORVEL).
- Size: 4 bytes per sample plus one for the plate id raster, before base64. 1° = 0.43 MB,
  **0.5° = 1.7 MB (default)**, 0.25° = 6.9 MB, 5′ = 62 MB. L7 cell spacing is ~60 km, about 0.5° at the equator, so the default
  pack matches the finest grid the project runs while staying a one-file, no-network download.
  The bake script takes `--deg` and the loader reads `w`/`h` — one path for any resolution, no
  level-specific data.
- Missing data never survives the bake: nodata holes are filled (nearest valid, then a 3×3
  median) and the count is reported. Sea level is the `datum` above; the loader subtracts it,
  because the sim's physics is calibrated on sea level `z = 0` (§1) — the display level is
  the user's afterwards, through the 0.3.5 controls (§6).

## 4. Bake — `tools/earth/bake_earth.py`

Python 3 + numpy, run on the owner's machine (needs internet once, or `--from <dir>`). Steps:

1. read and checksum the sources; report what was found and what will be synthesized;
2. build the common equirectangular raster at `--deg` (default 0.5) by area-weighted averaging
   (never plain subsampling: it aliases coastlines and trenches);
3. invert K9 to thicknesses per cell:
   - ocean (`age` known, `hFel = 0`): `hMaf = ((z + 3342 + 350*sqrt(min(age,80)))*3300 - hSed*900)/350`;
   - continent (`ci = 1`): `hFel = (z + 3342 + 2091 - hSed*900/3300)*6`;
   - shelf/transition: three fixed-point iterations of the same two equations with `ci` from
     `smoothstep(hFel, 5000, 20000)`, which converges in practice because `ci` moves < 0.2 per pass;
   the constants are read from `js/params.js` at bake time, never duplicated in Python;
4. quantize, quantize-check (report the metres/Myr error the quantization adds), write the pack;
5. write `plates.ids` by point-in-polygon over PB2002, with a per-plate cell count so a plate
   under `minPlateCells` is merged into its largest neighbour (the sim would absorb it anyway);
6. calibrate the `datum`: shift the continental `hFel` by a single constant so the wet fraction
   at the bake resolution is 0.708; record the value and the achieved fraction;
7. write `data/earth/report-<stamp>.txt`: per-layer statistics (hypsometric histogram, ocean
   fraction, continental area, mean age by band, sediment volume) and the checksums — this is
   the artifact a re-bake is compared against.

**Validation is part of the bake, not a later hope.** `experiments/earth-roundtrip.js` loads the
pack, runs `Sim.raster` + `Surface.elevation`, and compares the sim's `z` against the source
raster sample by sample. Acceptance: RMS error < 150 m, 99th percentile < 600 m (the residual
is bilinear resampling plus the `ci` transition band, not a physics mismatch). The bake prints
the same statistics, so a bad inversion is visible before anything is committed.

## 5. Loader — `js/earth.js`

A single module, no per-call allocation, loaded after `geodesics/params` and before `ui`:

```
Earth.decode(pack)                 // base64 -> typed arrays, cached on the pack object
Earth.apply(state, pack, opts)     // resample onto the state's grid and seed plates
Earth.score(state, pack)           // ocean fraction, continental area, hypso RMS vs the pack
```

`apply` walks cells once (bilinear in lat/lon, wrap in longitude, clamp in latitude), writes
`hFel/hMaf/hSed/age/fert`, then the plate map, then `q = identity`, `omega` from `plates.poles`
(realistic preset) or zeros, `plateBirth = 0`, `plateDead = 0`, and ends with `Sim.raster`,
`Surface.elevation`, `state.rebase()` so the mass ledgers start clean. Column position stays
`body = world = grid.pos` (every column starts at its cell, exactly as reset does). Cost at L7:
~4 layers × 164k cells bilinear ≈ 5 ms plus ~20 ms to decode 1.4 MB of base64 — synchronous is
fine, no worker, no async.

Options: `{ epoch }` selects a pack for §0.4.5; `{ realistic: false }` keeps the real crust but
draws procedural plates/motions from `state.seed` (the game preset); `{ jitter: n }` adds
seeded `fert`/`age` noise so two runs from the same pack still diverge after the first Myr.

## 6. UI and render

- `Start` selector in the existing Startup fieldset: `procedural` (default, unchanged) and every
  pack found in `EarthPacks` ("Earth now", "Earth 250 Ma" in 0.4.5).
- No renderer change is needed: since 0.3.5 the elevation layer colours `z < Params.sea` with
  a sea-relative ramp on both engines, and the Earth start is calibrated so its own sea level
  IS `Params.sea = 0` (the `datum` subtraction at load, §3/§4). The default Earth render is
  therefore the real coastline with no sea setting at all — the 0.3.5 bit-identity, now on a
  real map.
- The 0.3.5 sea controls carry their meaning onto the Earth start: the Sea level slider is
  display eustasy over real bathymetry, and the Water × slider conserves the REAL ocean —
  its `V0` is the pack's ocean volume, so `1.20×` is a genuine 20 % sea-level rise against
  Earth's hypsometry. The sea setting is a page global, so it carries across the start
  switch exactly as it carries across a rebuild or a Load, and the switch re-arms the volume
  tick, which re-solves `V0` against the new bathymetry — no Earth-specific water code.
- `zRange` stays the adjustable relief ramp; it and the sea level are independent by
  construction (the ramp is sea-relative, 0.3.5 §2).
- The HUD reports the start map's name, resolution, epoch, achieved ocean fraction and hypso RMS
  (from `Earth.score`), which is how a user sees whether a pack loaded as intended.
- `screenshot.avif`/README get an Earth-start screenshot once the pack lands.

## 7. Tests and acceptance

- `tests/earth.js` (short profile, a tiny synthetic 8×4 pack checked in under `tests/`):
  decode bounds and dtype, bilinear resample identity on a constant pack, latitude/longitude
  wrap at the date line and the poles, plate ids in range with `plateCount <= plateCap`,
  `Earth.score` on a synthetic pack, determinism (same pack + seed → identical state digest),
  and `rebase()` leaving every ledger at zero.
- Numeric acceptance on the real pack (an assertion in `tests/earth.js`, run once the pack is
  committed): ocean fraction 0.708 ± 0.02, continental area 0.29 ± 0.02, no cell with
  `hFel > 80000` or `hMaf > 20000`, and a 100 Myr run from the L5 Earth start stays finite with
  plate speeds inside the acceptance window. The datum calibration gets its own sharp check
  through the 0.3.5 solver: on the applied Earth world,
  `Water.fromElevations(state.z, 1).level` lands within one 60 m bucket of `0` — that is
  exactly the 0.3.5 default-identity (1.00× ≡ level 0), so the two sea sliders agree on the
  Earth start by construction and any drift names a datum error in the pack.
- `experiments/earth-compare.js` prints the pack's statistics against a reference report, so a
  re-bake or a resolution change is diffable. `experiments/earth-roundtrip.js` is the RMS check
  from §4.
- GPU: one `tests/gpu-parity.js` ensemble entry that starts from the pack and runs 20 frames on
  both engines — the Earth start must not break parity (it is just a different initialization,
  but it exercises different numeric ranges than the procedural mask).
- Load budget: < 100 ms at L7 from a cold page, measured by `tests/perf.js`'s stopwatch.

## 8. 0.4.5 — historical checkpoints and parameter presets

The draft's goal, "form more or less the same continents starting from Pangaea", is a loop
around the same machinery:

- bake one pack per epoch (250, 200, 150, 100, 66, 40, 20 Ma) from paleo-DEMs + GPlates rotation
  reconstructions; `plates.poles` at each epoch come from the rotation model rather than MORVEL,
  and `plate.ids` from reconstructing modern plate polygons through the same rotations;
- the Start selector lists the epochs; `Earth.apply(state, pack)` is already epoch-agnostic;
- **realistic preset**: real crust map + real poles, `cooling = 0` and `Tm` pinned to modern
  (the sim's 4.5 Gyr cooling curve is Earth's whole history, not a 250 Myr step, so a realistic
  preset must pin `Tm`, `mantleScale`, `kPlume` and `kDam` to the present-day budget — the
  "adjust parameters" half of §0.4.5);
- **game preset**: the same crust map, procedural plates/motions, jittered fertility, so
  repeated games do not replay the same world;
- **scoring**, an experiment not a gate: run 250 Ma → 0 Ma and report continental-mask IoU and
  mean plate-boundary distance against the 0 Ma pack; the numbers feed a parameter sweep
  (`experiments/plate-sweep.js` is the existing rig). Expect the first honest result to be a
  tuning loop, not a pass.

### 9a. Resolution: one baked pack, resampled at load — live sim-level change is out of scope

The pack is baked at one resolution (`--deg`, 0.5° default) and the loader resamples it onto
whatever sim level the world is built at: `Earth.apply` bilinearly interpolates in lat/lon
(wrap in longitude, clamp in latitude), so a 0.5° pack is a valid L5, L6 or L7 start without
any level-specific data — this *is* the draft's "at load possible downscale to other level".
The 0.3.5 review added a change-resolution request for the simulation world itself; it is
recorded here as out of scope for 0.4.0 and nothing in this plan depends on it:

- **changing the sim's resolution is a world rebuild, not a parameter.** `level` is the
  column grid's geometry — the Lagrangian state lives on its columns, and the mass ledgers are
  per-column moveables. There is no `setLevel()` that scales a world in place: the Resolution
  select today rebuilds the world from scratch (`rebuildWorld`, ui.js), and a mid-simulation
  resolution change would have to re-bucket every column onto the new grid and re-raster — a
  genuinely new mechanism with its own determinism and calibration proof, which is why it is
  backlog, not 0.4.x.
- **what 0.4.0 can re-use when that lands:** the pack is already grid-independent (a raster,
  not a column field), so scaling real data to a target resolution is a property of `Earth.apply`,
  and the loader's resample is the exact code a future in-place resolution change would call to
  re-seed the finer/coarser grid. 0.6.0 can add a "change resolution in simulation" control;
  since data layers are captured from sources, only the sim's `z` field is resolution-locked,
  so re-seeding at a new resolution is a per-column matrix operation no source needs to be
  re-downloaded for.

## 10. Risks

- **Provenance drift**: the sources are big and versioned; SOURCES.md + checksums + the report
  file are the defence, and a re-bake must be diffable against the last report.
- **Licences**: ETOPO/GEBCO/GlobSed are public-domain or openly licensed, PB2002 is
  redistributable, CRUST1.0 and the paleo-DEMs need their citation; the pack records what it
  used and the repo carries no raw source data.
- **The 0.5° default loses trenches and ridges** — 55 km pixels against ~60 km L7 cells cannot
  hold a 10 km trench.
  That is acceptable for a start map (the sim builds trenches), but it means score comparisons
  must be done at the pack's resolution, and a 0.25° pack is the answer if the coastline looks
  too raw at L7. A re-bake at another resolution leaves the loader and every test below it
  untouched (the loader reads `w`/`h`) — the one resolution knob is bake-side, not runtime.
- **Isostasy inversion is exact only where the sim's K9 is exact**: the `ci` transition band and
  `zDyn` start at zero, so shelf depths are the noisiest part of the round trip. The RMS
  acceptance in §4 accepts that; if it fails, the fix is the `ci` iteration count, not the
  physics.
- **Historical fidelity is not guaranteed by construction**: 250 Ma → today in this sim is a
  tuning problem (cooling budget, plate coupling). §0.4.5 is written as a loop with a scoring
  experiment so the first result can be a miss without stalling the release.
